# Совместимый автономный XLSX-контракт

Этот формат доступен в форме «Файл» при выборе «История из XLSX, без Jira» и через локальный API с `X-History-Source: file`. Старые книги и кэш сохраняют совместимость. Другой выбор формы читает ключи CSV/XLSX и получает историю из Jira; правила описаны в [README](../README.md).

## Обычная выгрузка дашборда

Обязательные колонки полного листа:

| Колонка | Допустимые названия |
| --- | --- |
| Ключ эпика | Ключ эпика, Ключ, Issue key, Key |
| Тип эпика | Тип эпика, Epic type |
| Название | Summary, Название, Название эпика, Тема |
| Резолюция | Резолюция, Resolution |

Пробелы, переносы строк и неразрывные пробелы нормализуются. Подходящий лист определяется по колонкам, а не по активной вкладке. Если полных листов несколько, импорт просит оставить один, не угадывая выборку по размеру. Заголовки могут находиться в первых 30 строках.

Остаются `HF` / `Гипотеза (HF)`, исключаются DF и `Отклонено`. Повторный ключ сохраняется один раз с предупреждением. Некорректные ключи, типы и числовые агрегаты отмечаются. Пустая резолюция допустима для открытых эпиков.

Если истории нет, автоматически выбран режим **«Состав из Excel»**: показываются исходный TTM и `Cycle Time [HF] …`. Числа не пересчитываются под другое определение TTM. В колонке «Возврат в открыто» стоит прочерк: `Cycle Time [HF] Открыто` не позволяет отделить первоначальное ожидание от возвратов.

Справа длительности этапов складываются в полосу на общей абсолютной шкале дней. Порядок блоков соответствует колонкам Excel и **не означает последовательность переходов**. Открыто исключено из состава; исходный TTM остаётся целиком и отмечается отдельным пунктиром. Сумма не подгоняется под TTM: при расхождении обе величины остаются видимыми. Пропуски отмечаются отдельно, нули сохраняются. Названия колонок сохраняются даже при пустых значениях; повторяющиеся названия агрегатов требуют исправления файла перед импортом.

Фильтр по исполнителю сочетается с поиском и сортировкой. Медиана и максимум TTM пересчитываются для видимой выборки и выбранного источника; карточка показывает число известных значений. Масштаб состава остаётся общим для полного набора даже при фильтрации. Панель эпика содержит длительности каждого этапа, исходный TTM, сумму этапов и разницу, метаданные и замечания к истории.

Колонки с датами отдельных этапов и агрегатами не доказывают отсутствие повторных входов. По ним календарная шкала не достраивается. Прочерк означает неизвестное значение, а не ноль.

Ограничения импорта: XLSX до 20 МБ, до 20 000 строк и 500 столбцов на листе, до 1000 HF-эпиков.

## Недельный отчёт TTM

Также поддерживается формат `Weekly_report_TTM`: **Ключ эпика, Название эпика, Статус, Значение ТТМ**. Заголовки нормализуются тем же способом. Наличие этих колонок позволяет импортировать отчёт без «Тип эпика» и «Резолюция».

- Если «Тип эпика» отсутствует, HF/DF определяется по явной метке `[HF]` или `[DF]` в начале статуса. Строки без однозначной метки пропускаются с предупреждением. Если колонка типа присутствует, используются её значения; пустые или некорректные значения не подменяются статусом.
- «Вид эпика», например «Бизнес (мастер-фича)», сохраняется как отдельное свойство. Это не эквивалент HF/DF. В деталях также сохраняется группа отчёта.
- Без колонки резолюции отбор отклонённых эпиков возможен только по статусу «Отклонено». Приложение сообщает об ограничении; резолюция не выдумывается из статуса «Закрыт». Если резолюция предоставлена, она тоже участвует в отборе.
- Текущий TTM берётся из «Значение ТТМ». «ТТМ на начало недели» сохраняется отдельно в исходных агрегатах; пропущенное текущее значение не заменяется предыдущим.
- Если в отчёте нет длительностей этапов и полной истории, доступны TTM, поиск, сортировка и метаданные. Состав этапов и календарные интервалы из дат создания и входа в поток не достраиваются.

В предоставленном `Weekly_report_TTM_2026-09-14.xlsx` — 19 строк с явной меткой `[HF]`: 9 в статусе «Закрыт» и 10 в активных статусах. Текущий TTM присутствует у всех 19 эпиков. Папка `temp_imports/` исключена из Git.

## Таблица точной истории

Импортёр уже поддерживает описанный ниже формат. Следующий пользовательский пример служит основой для адаптации, если его структура отличается.

Для календаря поддерживается лист **«История»** в той же книге. Одна строка — один непрерывный интервал, включая повторные входы.

| Ключ эпика | Статус | Начало | Окончание |
| --- | --- | --- | --- |
| EXAMPLE-1 | [HF] Открыт | 01.09.2026 12:00:00 | 02.09.2026 12:00:00 |
| EXAMPLE-1 | [HF] Подготовка | 02.09.2026 12:00:00 | 05.09.2026 12:00:00 |
| EXAMPLE-1 | [HF] Реализация | 05.09.2026 12:00:00 | 17.09.2026 12:00:00 |
| EXAMPLE-1 | [HF] Закрыт | 17.09.2026 12:00:00 | |

Пример вымышленный. Ключи корневой истории присутствуют в основном листе; при дополнении версии 1 также допускаются дочерние ключи из листа «Элементы».

- Допустимы дата-время Excel, `ДД.ММ.ГГГГ ЧЧ:ММ:СС`, `ГГГГ-ММ-ДД ЧЧ:ММ:СС` и ISO со смещением, например `2026-09-02T12:00:00.123+03:00`.
- Время без явно указанного пояса трактуется как Europe/Moscow. Текстовая дата без времени не считается точным переходом.
- Окончание интервала должно совпадать с началом следующего. Пробелы и пересечения делают расчёт эпика недоступным. Суммы Excel при этом сохраняются отдельно.
- Пустое окончание разрешено у последнего интервала. Для незакрытого эпика оно равно `asOf`. Явное окончание последнего незакрытого интервала тоже должно равняться `asOf`.
- Закрытие нужно передать отдельной строкой `[HF] Закрыт` с точной датой начала. Окончание последнего активного интервала само по себе не доказывает закрытие.
- Нулевые интервалы допустимы. При совпадающем времени сохраняется порядок строк.
- История должна начинаться не позже первого активного HF-статуса. Приложение проверяет внутреннюю непрерывность, но не может обнаружить пропущенное начало истории, если его нет в предоставленных данных.

Добавьте лист **«Параметры»**:

| Параметр | Значение |
| --- | --- |
| asOf | 18.09.2026 12:00:00 |

`asOf` — единый момент среза предоставленной истории. Без него календарь не рассчитывается. При повторном открытии приложения этот момент не сдвигается к текущему времени.

## Impediment

Лист **«Impediment»** содержит колонки `Ключ эпика`, `Начало`, `Окончание`. Пустое окончание означает, что флаг ещё действовал на `asOf`.

Наличие листа утверждает, что передана полная история флагов для выборки: отсутствие строк эпика означает отсутствие impediment. Лист только с заголовками означает, что флагов не было у всей выборки. Отсутствие листа означает **неизвестные данные**, а не ноль.

Пересекающиеся или некорректные интервалы не суммируются. История статусов при этом может оставаться доступной. Флаги обрезаются по границам TTM и рисуются отдельной строкой. Короткий флаг имеет выносной маркер, даже когда его длительность округляется до `0,00` дня. TTM от наличия флага не меняется.

## Расчёт и отображение

- TTM по истории: от первого активного HF-статуса до последнего входа в окончательный `Закрыт` либо до `asOf`.
- Первоначальное Открыто исключается. Последующее Открыто учитывается как `↩О`, включая незавершённый возврат.
- Промежуточное закрытие при переоткрытии включается в сквозной TTM и отмечается предупреждением. Последовательные входы в Закрыт завершают TTM последним таким входом.
- Неизвестные и смешанные HF/DF-статусы внутри TTM сохраняют длительность и серую штриховку.
- Интервалы полуоткрытые: `[начало, окончание)`. Арифметика использует миллисекунды без округления по дням. Сумма сегментов должна точно равняться TTM.
- Календарь показывает кварталы, месяцы и дни; масштаб меняет только ширину, не длительности. Короткие сегменты получают выносные подписи. Наконечник стрелки — декоративное обозначение незакрытого эпика; точное окончание указано в подсказке.
- Поиск и сортировка меняют порядок/видимость строк, сохраняя временной диапазон выборки. Неполные значения сортируются после известных.
- «Календарь по истории» и «Состав из Excel» — разные источники числовой таблицы и правой диаграммы. Они не подменяют друг друга. Календарь всегда основан только на истории; состав всегда использует агрегаты.
- Полный набор — непрерывные предоставленные интервалы и доступные данные impediment. Частичный набор сохраняет пригодные эпики и сообщает причины пропусков. При новом импорте прежняя история не подмешивается.

Пороги heatmap перенесены из `Процедура проведения анализа ТТМ по дашборду, по MVS в Туту.md`, проверенной 18.09.2026. Нижняя граница включается, верхняя не включается. Исключение: скоринг без цвета до 30 дней включительно, оранжевый при значении больше 30. Реализация менее одного дня — бордовая по процедуре. Полная шкала доступна в «Правилах расчёта».

Структура интерфейса следует предоставленному `Jira Upgrade НТ.pdf`; оформление незакрытого сегмента — `image.png`. В отличие от прежнего прототипа, новый TTM по истории не включает первоначальное Открыто.


## Связанные эпики и задачи: дополнение версии 1

Основной лист и его HF-отбор сохраняются. Для связанных DF и обычных задач добавьте:

| Лист | Обязательные данные |
| --- | --- |
| Параметры | `asOf` и `hierarchyVersion` со значением `1` |
| Элементы | `Ключ`, `Название`, `Вид элемента`, `Резолюция`, `Создан`, `Статус на срезе` |
| Связи | `Откуда`, `Связь`, `Куда`; значения `contains` либо `is contained in` |
| История | Непрерывные интервалы всех существовавших на срезе допустимых элементов, включая исходные эпики |

«Вид элемента»: «Эпик», «Задача», «Подзадача». Пустая резолюция допустима; колонка обязательна. Метаданные нужны также для исходных родителей. Лист «Элементы» не становится вторым основным списком. Для задачи, включённой в эпик через Epic Link, добавьте строку `эпик contains задача`; заголовок раздела Jira не является значением колонки «Связь». Связь `A contains B` равна `B is contained in A`; другие отношения в граф не включаются.

Необязательная колонка «Категория статуса на срезе» использует `done`/`completed` для закрытия и `new`/`indeterminate`/`in-flight` для незакрытого состояния. При отсутствии пригодной категории эпики закрывают `[HF] Закрыт` и `[DF] Закрыт`. Для задач применяются полные нормализованные названия из [согласованного словаря](sdd/changes/LOCAL-20260924-02-linked-issue-status-bars/design.md), например «Готово» или `Done`. Подстроки «Не закрыто» и «Готово к тестированию» не означают закрытие. Неизвестная граница даёт диагностическую строку без точной полосы.

Дочерняя история начинается ровно в «Создан», сохраняет непрерывность и соответствует «Статусу на срезе». Закрывающий статус передаётся конечной строкой с датой входа; длительность после окончательного закрытия не растягивается до среза. Переоткрытие сохраняет промежуточный закрытый интервал. Для создания после `asOf` история и статус на срезе могут отсутствовать: показывается «Создан после среза», без отрицательной полосы.

Без листа «Связи» состав неизвестен; лист с одними заголовками означает подтверждённое отсутствие связей. Повтор одного отношения объединяется, конфликт метаданных или неизвестная версия дополнения отклоняет новый импорт. Разрыв одной истории сохраняет остальные пригодные строки. Отсутствующие метаданные дают предупреждение и не превращаются в вымышленную задачу.

Отклонённые элементы и подзадачи не показываются; допустимые потомки скрытого отклонённого эпика остаются доступны. Все ветки изначально свёрнуты. Дочерние строки не содержат числовых длительностей, а исходные метрики сохраняются. В автономном режиме Jira и Keychain не читаются.

[Протокол](sdd/changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md) фиксирует успешные автоматические проверки и невыполненную фактическую визуальную приёмку.
