# Выбор источника и отбор эпиков

## Назначение и ответственность

Возможность определяет кандидатов из файла, прямого списка ключей, постоянной выборки Jira-доски либо ссылки на один эпик и фиксирует причину включения или исключения. Владелец поведения — локальный сервис. Для Jira-режима истинность типа, потока и резолюции определяет текущий ответ Jira; для автономного режима — предоставленная книга.

## Требования

### FR-001: Источники выборки

КОГДА пользователь передаёт CSV/XLSX с ключами, вводит список ключей, даёт ссылку на доску или ссылку на эпик, система ДОЛЖНА создать задание для соответствующего источника. Файл и прямой список для Jira-режима требуют только ключей; название, тип и история берутся из Jira. В форме файла пользователь также может явно выбрать автономный XLSX: его признаки, связи и история берутся из книги, без Jira и Keychain, по [FR-033](legacy-compatibility.md). Смена этого выбора сама по себе не запускает импорт; CSV в автономном режиме отклоняется с пояснением.

#### AC-001: Импорт файла по ключам

- **ДАНО** CSV или XLSX с одним однозначным списком ключей.
- **КОГДА** пользователь выбирает файл.
- **ТОГДА** приложение собирает кандидатов и читает актуальные данные и историю из Jira.

#### AC-022: Прямой ввод — новый сценарий

- **ДАНО** введено несколько ключей.
- **КОГДА** пользователь запускает анализ.
- **ТОГДА** создаётся одно задание и одна выборка с общим моментом среза.

### FR-026: Прямой ввод списка ключей

Система ДОЛЖНА принимать в одном многострочном поле ключи разных Jira-проектов через запятые, построчно либо в одноколоночной таблице Markdown. Эти разделители можно сочетать; пустые элементы между запятыми и пустые строки пропускаются. Подпись `New grid` и строка выравнивания таблицы пропускаются; первая строка с ключом остаётся данными. Пробелы по краям удаляются, регистр ключа нормализуется, повтор одного ключа объединяется с сохранением номеров всех исходных строк. Один запуск создаёт одно задание с общим моментом среза.

#### AC-018: Два вида одной выборки

- **ДАНО** 24 ключа из [контрольных примеров](../changes/archive/2026/LOCAL-20260924-01-multi-epic-keys/examples.md) представлены построчно и в таблице.
- **КОГДА** список разбирается.
- **ТОГДА** оба вида дают те же 24 кандидата в исходном порядке, включая первый ключ таблицы.

#### AC-019: Повтор ключа

- **ДАНО** ключ повторён в разных строках или регистрах.
- **КОГДА** список разбирается.
- **ТОГДА** он создаёт одного кандидата и одну строку результата; повтор отражён в аудите.

### FR-027: Ошибочные строки

Каждый непустой элемент после разделения по запятым, который не содержит один распознаваемый ключ, ДОЛЖЕН оставаться в аудите с исходным текстом, физическим номером и причиной. Он не направляется в Jira. Поддерживаемое оформление таблицы из FR-026 пропускается. Если корректных ключей нет, отчёт только об ошибках создаётся локально без Jira и Keychain; пустой ввод или одно оформление отклоняются до задания. HTTP-контракт задан в [архитектуре](../architecture.md), пределы — в [эксплуатации](../operations.md).

#### AC-020: Смешанный ввод

- **ДАНО** список содержит корректные ключи, неверные строки и пустые строки.
- **КОГДА** пользователь запускает анализ.
- **ТОГДА** корректные ключи проверяются в Jira, неверные строки попадают в аудит, пустые строки пропускаются.

#### AC-021: Только ошибки

- **ДАНО** после пропуска пустых и служебных строк остались только ошибки формата либо не осталось данных.
- **КОГДА** пользователь запускает анализ.
- **ТОГДА** ошибочные строки образуют локальный отчёт без чисел и шкал, который не выдаётся за подтверждённое отсутствие HF; при отсутствии строк данных ввод отклоняется как пустой.

#### AC-094: Ключи через запятую

- **ДАНО** строка из 17 ключей RAILDIS, разделённых запятыми и пробелами, как в примере пользователя от 12.10.2026.
- **КОГДА** пользователь загружает её через «Список ключей».
- **ТОГДА** формируются 17 отдельных кандидатов в исходном порядке, от RAILDIS-376 до RAILDIS-83, с физическим номером строки 1. Принадлежность к HF проверяется прежним отбором Jira.
- **ДАНО** смешаны запятые и переносы, повторы в разных регистрах, пустые элементы и неверный ключ.
- **ТОГДА** повторы объединяются с сохранением всех вхождений, неверный элемент получает собственную запись аудита, пустые элементы пропускаются. Счётчик ввода учитывает непустые элементы, не только физические строки. Многостолбцовая Markdown-строка остаётся одной ошибкой и не разбивается; предел 1000 уникальных ключей действует на весь ввод без усечения.

### FR-002: Однозначность и пределы файла

Система ДОЛЖНА отвергать неоднозначные листы или колонки ключей, некорректный формат и превышение пределов; дубликаты и некорректные строки ДОЛЖНЫ оставаться видимыми в аудите. Необязательные контрольные поля и агрегаты файла МОГУТ использоваться для сравнения, но не для решения о HF.

### FR-003: Постоянная выборка доски

КОГДА передана допустимая ссылка на проверенную Kanban-доску, система ДОЛЖНА читать постоянный фильтр, подфильтр и статусы колонок. Конфигурация и фильтр ДОЛЖНЫ совпадать с проверенным профилем; изменение профиля останавливает чтение. Для проверки состава выполняются два полных чтения; при несовпадении допускается ещё одна пара. Быстрые фильтры, `projectKey` и иные дополнительные параметры ссылки не применяются. Доска определяется по `rapidView`; подтверждение видимости завершённых задач хранится в профиле.

#### AC-002: Изменение доски

- **ДАНО** первая пара полных чтений доски дала разный состав.
- **КОГДА** приложение выполняет вторую пару.
- **ТОГДА** совпавшая полная выборка допускается к обработке; при повторном расхождении задание завершается ошибкой и прежний набор сохраняется. Несовпадение настроек с проверенным профилем блокирует чтение независимо от этих повторов.

### FR-004: Один эпик

КОГДА передана ссылка вида `https://hq.tutu.ru/browse/KEY-123`, система ДОЛЖНА проверять ровно эту задачу без зависимости от доски или файла.

### FR-005: Решение о включении

Система ДОЛЖНА включать подтверждённый HF-эпик, у которого ни резолюция, ни текущий статус не означают отклонение (`Отклонено`, `Отклонён`, `Rejected`, `Не будет выполняться` после нормализации). Другие непустые резолюции сами по себе не исключают эпик. Тип эпика определяется по `epicTypeIds` профиля; поток — по единственному префиксу `[HF]` или `[DF]` текущего статуса. Поле «Вид эпика» не заменяет этот признак. Неэпики и DF исключаются с причиной, неизвестный поток остаётся неразрешённым. Для доски неразрешённые кандидаты блокируют загрузку историй всей выборки.

#### AC-003: Неразрешённый HF

- **ДАНО** среди кандидатов доски есть задача без подтверждённой принадлежности HF или DF.
- **КОГДА** завершается проверка метаданных.
- **ТОГДА** история доски не загружается и аудит показывает причину.

## Поведение при сбоях и на границах

Файл ограничен 20 МиБ, 20 000 строками листа (включая заголовки) и 500 колонками. CSV ДОЛЖЕН быть в UTF-8. Заголовок ключа ищется в первых 30 строках; допускается одноколоночный список ключей без заголовка. Листы интервалов с ключом и колонками начала/окончания не считаются основным списком. Ключи нормализуются в верхний регистр; старый и новый ключ одной задачи объединяются по стабильному `issueId` до чтения истории.

Доска ограничена 10 000 кандидатами и 500 страницами. Предел 1000 подходящих HF-эпиков применяется ко всем четырём Jira-источникам. Превышение ДОЛЖНО приводить к ошибке без усечения.

| Результат отбора | Публикация |
| --- | --- |
| Все кандидаты однозначно исключены либо проверенная доска пуста | Допустим пустой набор с аудитом |
| Файл содержит разрешённые и неразрешённые кандидаты | Допустим частичный набор; прежние эпики не подмешиваются |
| Все кандидаты файла неразрешённые | Ошибка, прежний набор остаётся |
| Прямой список содержит только неверные строки или отдельно недоступные задачи | Допустим набор с ошибками, без утверждения об отсутствии HF |
| У доски или одного эпика не удалось подтвердить отбор | Ошибка, прежний набор остаётся |

Публикация также зависит от доступности историй включённых эпиков: см. [чтение Jira](jira-ingestion.md). Некорректные строки файла остаются в аудите; они не означают, что прочитан неполный файл, но понижают общее качество набора.
