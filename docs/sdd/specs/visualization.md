# Визуализация и анализ набора

## Назначение и ответственность

Локальный интерфейс показывает отобранные эпики, качество данных, длительности и календарную последовательность; предоставляет поиск и детализацию без изменения Jira.

## Требования

### FR-015: Таблица и фильтры

Система ДОЛЖНА показывать ключ, название, качество и метрики эпика; предоставлять поиск по ключу или названию, фильтр исполнителя и сортировку. Отсутствующее значение ДОЛЖНО оставаться неизвестным, а не нулём.

Поиск выполняется без учёта регистра, исполнитель выбирается по точному отображаемому значению. По умолчанию применяется сортировка по убыванию TTM; неизвестные числа идут последними в обоих направлениях, равные значения упорядочиваются по ключу. Медиана и максимум TTM считаются по известным значениям отфильтрованных строк в выбранном источнике метрик. Календарный диапазон и шкала состава рассчитываются по всему набору и не сдвигаются при фильтрации.

#### AC-010: Пропущенная метрика

- **ДАНО** у эпика нет подтверждённой длительности.
- **КОГДА** пользователь открывает таблицу.
- **ТОГДА** ячейка показывает прочерк, а подробности содержат предупреждение.

### FR-029: Ошибки прямого списка в таблице

Для источника `keys` таблица ДОЛЖНА показывать рядом с включёнными HF-эпиками ошибочные строки ввода и отдельно недоступные Jira-задачи. Строка ошибки содержит исходный текст, номер строки, метку «Ошибка» и известную причину; числовые ячейки в ней показывают прочерки, календарной полосы и деталей эпика нет. Ошибки остаются также в аудите и не входят в число HF, медиану или максимум. Несколько введённых алиасов одной недоступной задачи дают одну строку ошибки с номерами строк в аудите; исключённые DF, отклонённые задачи и неэпики остаются только в аудите. Неполная история подтверждённого HF сохраняется как строка эпика, а не превращается в ошибку ключа.

Поиск по введённому тексту, текущему ключу или причине оставляет ошибочные строки доступными. Ошибки идут отдельным блоком после эпиков при любой сортировке; внутри блока сохраняется порядок первого физического номера строки. Выбор конкретного исполнителя скрывает ошибки, у которых исполнитель неизвестен; при фильтре «Все» они видны. При отчёте только из ошибок таблица остаётся видимой без календарных делений. Только локальный отчёт, состоящий из ошибок формата `invalid`, скрывает исторические подписи, режим календаря, масштаб и легенду и сообщает «Jira не запрашивалась». Для недоступных корректных ключей `unresolved` запросы Jira уже выполнялись; общий режим и подписи Jira сохраняются ([интерфейс](../../../src/App.tsx), [сводка](../../../src/DatasetSummary.tsx)).

#### AC-025: Смешанный результат

- **ДАНО** в списке есть HF, неверная строка, отдельно недоступная задача и исключённый DF.
- **КОГДА** загрузка завершилась.
- **ТОГДА** HF показан с историей, две ошибки — с причинами и без чисел или полос, DF — только в аудите.

#### AC-026: Поиск ошибки

- **ДАНО** таблица содержит ошибочную строку.
- **КОГДА** пользователь ищет введённый текст либо меняет сортировку.
- **ТОГДА** ошибочная строка остаётся доступной по своему тексту; неизвестные числовые значения не превращаются в нули.

#### AC-027: Все задачи недоступны

- **ДАНО** все синтаксически корректные ключи по отдельности недоступны без глобального отказа Jira.
- **КОГДА** чтение завершено.
- **ТОГДА** виден отчёт с ошибками без числовых показателей и без заявления об отсутствии HF.

#### AC-028: Неполнота данных не равна ошибке ключа

- **ДАНО** для одного HF доказан TTM, но неизвестен impediment; другой подтверждённый HF ещё не начал работу.
- **КОГДА** строится таблица.
- **ТОГДА** известный TTM первого остаётся видимым, неизвестный impediment отмечен отдельно, второй показывает «TTM ещё не начат» и исходное ожидание по действующим правилам.

### FR-016: Календарь истории

Система ДОЛЖНА показывать последовательные интервалы по общей временной оси в масштабах день, неделя и месяц. Начальное Открыто и предрабочие состояния ДОЛЖНЫ быть визуально отделены от TTM; узкие интервалы ДОЛЖНЫ получать выносную подпись без изменения их ширины.

Начальный масштаб — неделя; день/неделя/месяц соответствуют 26/8/3 пикселям на сутки, а не округлению длительностей. Для Jira-набора начальный источник метрик всегда «История», даже при неизвестном TTM. Автономный набор без числового TTM, начального Открыто и пригодной истории связанных элементов по умолчанию открывает «Состав из Excel» ([выбор источника](../../../shared/contracts.ts)).

### FR-017: Состав агрегатов

При доступных агрегатах Excel система МОЖЕТ показывать отдельный состав длительностей этапов на общей абсолютной шкале с отметкой исходного TTM. Порядок блоков соответствует колонкам файла и не ДОЛЖЕН выдаваться за хронологию. «Открыто» ДОЛЖНО быть исключено из состава, поскольку агрегат не разделяет ожидание и возвраты; TTM остаётся без пересчёта.

Название «Состав из Excel» используется также для контрольных агрегатов CSV. Неизвестные дополнительные агрегатные этапы показываются нейтрально; отсутствующие значения не равны нулю. Файловые агрегаты не пересчитываются при refresh Jira. Разница TTM и суммы известных этапов не доказывает ни порядок переходов, ни причину расхождения.

#### AC-011: Сравнение агрегатов

- **ДАНО** сумма известных этапов отличается от TTM.
- **КОГДА** пользователь открывает детали.
- **ТОГДА** показаны оба исходных числа и разница без подгонки.

### FR-018: Цветовая оценка длительностей

Цветовая оценка ДОЛЖНА использовать сохранённые пороги этапов и TTM. Для возврата в Открыто порог не применяется; неизвестный этап показывается нейтрально.

Точная таблица порогов — [HEAT_BANDS](../../../shared/heatmap.ts), она также показана в «Правилах расчёта». Нижняя граница включается. TTM: жёлтый до 60 дней, оранжевый от 60, красный от 100, бордовый от 200. Скоринг не окрашивается до 30 дней включительно, выше — оранжевый. Реализация меньше одного дня бордовая: это фактическое правило, а не ошибка описания. Цвет статуса на календаре и heatmap длительности — разные обозначения.

### FR-019: Детали и правила

Система ДОЛЖНА показывать исходные переходы, интервалы, impediment, момент среза, качество и предупреждения, а также доступные пользователю правила расчёта и аудит отбора.

Модальные окна закрываются Escape и кликом по фону, удерживают клавиатурный фокус и возвращают его после закрытия. При успешном новом наборе сбрасываются поиск, исполнитель, выбор источника метрик, выбранный эпик и сортировка; масштаб календаря сохраняется.

#### AC-012: Частичная история

- **ДАНО** история эпика помечена частичной.
- **КОГДА** пользователь открывает его детали.
- **ТОГДА** интерфейс явно показывает качество и причину, не создавая впечатления точного TTM.

## Поведение при сбоях и на границах

При загрузке новый результат не заменяет текущий до успешного сохранения. На ошибке пользователь видит сообщение, прежний набор остаётся.

UI опрашивает задание с интервалом 700 мс; после транспортного сбоя повторяет через 3 секунды. `JOB_NOT_FOUND` приводит к загрузке последнего сохранённого набора с пояснением. Иная HTTP-ошибка прекращает polling и снимает локальное состояние задания; это не команда отмены серверу. Закрытие страницы тоже не отменяет уже запущенный импорт ([клиент](../../../src/api.ts), [UI](../../../src/App.tsx)).

## Связанные элементы: реализованное дополнение

### FR-030: Раскрытие связанных элементов

В календарном режиме система ДОЛЖНА показывать у исходных и вложенных эпиков отдельную стрелку раскрытия. Изначально ветки свёрнуты; нажатие показывает непосредственных видимых детей, повторное нажатие скрывает всё поддерево. Название исходного эпика продолжает открывать его детали. Задачи не раскрываются в подзадачи.

Дочерняя строка ДОЛЖНА показывать ключ, название и собственную историю по FR-032 на общей временной оси, с отступом уровня. Числовые ячейки TTM, длительности этапов и impediment для дочерней строки отсутствуют; названия и даты статусов доступны на полоске и в подсказке. Исходные строки, их расчёты и статистика сохраняются.

Связанные элементы показываются независимо от HF/DF, но с отклоняющей резолюцией («Отклонено», нормализованные варианты либо «Не будет выполняться») исключаются. Один элемент ДОЛЖЕН быть видим под каждым родителем, а если он сам выбран исходным эпиком — также в исходной строке. Повтор одного элемента в текущей цепочке ДОЛЖЕН останавливать цикл с предупреждением. Подзадачи не показываются отдельными строками и не раскрываются в интерфейсе; их состав и истории читаются для анализа работы по FR-036. Это аналитическое чтение не включает подзадачи в видимый граф, исходную выборку, статистику или границы календаря как самостоятельные элементы.

Если отклонённый промежуточный эпик скрыт, неотклонённые потомки ДОЛЖНЫ оставаться достижимыми через ближайшего видимого предка с пояснением о пропущенном промежуточном элементе. Пользователь подтвердил это правило при разборе повторной проверки пакета.

Подтверждённое отсутствие детей ДОЛЖНО отличаться от неизвестного состава ветки и от старого набора без сведений о связях. Недоступная или недоказанная статусная история оставляет строку и предупреждение, не выдуманную точную полосу статусов. Это ограничение не скрывает независимо подтверждённые сегменты спринтов по FR-035/FR-039: их даты и работа могут быть известны по дочерним задачам даже при неизвестных этапах самого эпика. Календарный диапазон ДОЛЖЕН учитывать исходные строки и доказанные интервалы допустимых дочерних элементов набора, включая скрытые сворачиванием или фильтром корней, и оставаться стабильным при раскрытии, фильтрации и сортировке. Отклонённые элементы, подзадачи, недостижимые элементы и диагностические строки без доказанных интервалов не расширяют ось; допустимые потомки скрытого отклонённого эпика учитываются. Поиск, исполнитель и сортировка применяются к исходным эпикам; дочерние строки следуют за видимым родителем.

При недостаточном бюджете или локальном отказе аналитических подзадач прежние видимые узлы, связи, полосы и полнота основного графа ДОЛЖНЫ сохраняться. Причина ограничения анализа спринтов показывается отдельно. Сегменты спринтов ДОЛЖНЫ отображаться в полосках исходного эпика, раскрытых Delivery-эпиков и задач по FR-035. История статусов каждой строки остаётся читаемой; сегменты эпика отражают только его допустимые нижние задачи и не зависят от раскрытия. Критерий бреши определяется FR-038/039: отметка непосредственно под цветной полосой выбранного этапа, вплотную к её нижнему краю, означает только доказанное отсутствие включённых задач. Недостаточность данных и предварительное отсутствие работы на этой полосе не отображаются; состояния отдельных сегментов спринтов сохраняются.

#### AC-029: Раскрытие по уровням

- **ДАНО** эпик A содержит эпик B, B содержит задачу C, у C есть подзадача D.
- **КОГДА** пользователь открывает набор, затем раскрывает A, затем B.
- **ТОГДА** сначала виден A; после первого нажатия — A и B; после второго — также C; D отсутствует, у B и C нет числовых длительностей.

#### AC-030: Сворачивание

- **ДАНО** раскрыты A и B.
- **КОГДА** пользователь сворачивает A.
- **ТОГДА** B и C скрыты; исходные полосы, метрики и календарная ось сохранены.

#### AC-031: Недоступная история

- **ДАНО** история C недоступна, а история соседней задачи доступна.
- **КОГДА** пользователь раскрывает их родителя.
- **ТОГДА** C видна с предупреждением без точной полосы; соседняя полоса остаётся видна.

#### AC-032: Общая календарная ось

- **ДАНО** история C начинается раньше родителя и заканчивается позже него.
- **КОГДА** пользователь раскрывает ветку, меняет масштаб и сворачивает её.
- **ТОГДА** вся история помещается на общей оси; даты и длительности не меняются, сворачивание не сдвигает диапазон.

Дополнительный вариант AC-032: у отклонённого эпика, подзадачи и недостижимого элемента даты далеко за пределами допустимых строк; эти даты не расширяют ось. Допустимый потомок отклонённого эпика с более ранним началом расширяет её независимо от сворачивания.

#### AC-035: Общий элемент

- **ДАНО** A и B содержат C, а B также выбран исходным эпиком.
- **КОГДА** обе ветки раскрыты.
- **ТОГДА** C видна под A и B, B сохраняет исходную строку; раскрытие одной ветки не меняет другую, статистика считает только исходные эпики.

#### AC-036: DF и отклонённые

- **ДАНО** у A есть связанный DF-эпик, обычная задача и отклонённый эпик с неотклонённым потомком.
- **КОГДА** A раскрыт.
- **ТОГДА** DF и обычная задача видны, отклонённой строки нет; потомок виден с пояснением о промежуточном исключении.

#### AC-037: Пустая ветка и цикл

- **ДАНО** A не имеет детей, состав B неизвестен, а C содержит D и D содержит C.
- **КОГДА** пользователь исследует эти ветки.
- **ТОГДА** у A показано подтверждённое отсутствие детей, у B предупреждение о неизвестном составе; ветка C конечна и отмечает цикл.

## Текущие ограничения

Тесты DOM и сборка проходят, но ручная визуальная приёмка смешанной и полностью ошибочной таблиц ещё не завершена ([протокол изменения](../changes/archive/2026/LOCAL-20260924-01-multi-epic-keys/verification.md)).

Реализация связанных элементов проверена автоматическими сценариями на обоих источниках и живыми образцами Jira. Пользователь подтвердил проверку по ключу и признал её пока достаточной. Полная приёмка XLSX и остальных живых/ручных случаев не заявлена; границы результата и непроверенные остатки T012/T013 — в [протоколе](../changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md).

Аналитика спринтов добавлена по [FR-035–041](sprint-continuity.md). Автоматическая проверка выполнена; живая и визуальная приёмка новой раскладки остаются открытыми в [протоколе](../changes/archive/2026/LOCAL-20260929-01-sprint-continuity/verification.md).

На строках обычных задач видимые спринты ограничиваются правилом FR-042: участие сохраняет целый спринт, остальные спринты с доказанным отсутствием участия показываются только целиком внутри открытого периода задачи. Это не ограничивает сегменты эпиков.

Уточнение 12.10.2026: доказанные длительности известных этапов Jira показываются независимо от неизвестного начала TTM по [AC-092](sprint-continuity.md). Полнота истории по-прежнему обязательна; прочерк TTM не скрывает известные числа этапов.
