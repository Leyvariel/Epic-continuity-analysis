# Чтение Jira и контроль полноты

## Назначение и ответственность

Сервис читает текущие признаки задач и историю переходов через проверенный адаптер Jira Server. Он не изменяет Jira и не превращает частичный ответ в полную историю.

## Требования

### FR-006: Проверенный профиль и доступ

ПЕРЕД новым чтением Jira система ДОЛЖНА прочитать локальный профиль, PAT из Keychain и проверить версию Jira. Запись `Code Jira Relations PAT` ДОЛЖНА выбираться по точному аккаунту `leyva@tutu.tech`. Резервная `tutu-jira` для того же аккаунта применяется только при отсутствии основной записи, а не после отказа в доступе или HTTP 401. Записи других аккаунтов не используются. При каждой новой загрузке или обновлении PAT читается заново, без сохранения в кэше, файлах, логах, ответах API или браузере. Файл и прямой список кандидатов проверяются до обращения к credentials. Прямой список только из ошибок формата не обращается к Jira и не требует профиля/PAT ([FR-027](source-selection.md)). Автономный XLSX-контракт также не требует Jira и рассматривается [отдельно](legacy-compatibility.md).

#### AC-004: Нет подтверждённого профиля

- **ДАНО** файла профиля Jira нет либо его схема не проходит проверку.
- **КОГДА** пользователь запускает импорт, требующий чтения Jira.
- **ТОГДА** задание завершается ошибкой до чтения истории, а прежний набор остаётся.

#### AC-093: Точный аккаунт и обновление PAT

- **ДАНО** запись Keychain с согласованным названием и аккаунтом; в хранилище могут существовать записи других аккаунтов.
- **КОГДА** приложение начинает загрузку или обновление.
- **ТОГДА** оно читает точную пару названия и аккаунта; после замены PAT следующее чтение получает новое значение. Другие аккаунты не подставляются. Резерв допускается только при отсутствии основной записи для того же аккаунта.
- **КОГДА** Keychain отказывает или возвращает некорректный секрет.
- **ТОГДА** клиент получает безопасное сообщение без токена, stdout и stderr.


### FR-007: Ограниченное чтение

Система ДОЛЖНА выполнять только GET к разрешённым путям фиксированного адреса `https://hq.tutu.ru` и не передавать PAT при перенаправлении. Ответы ДОЛЖНЫ проходить проверку схемы, ограничение размера и времени запроса.

### FR-008: Доказательство истории

История статусов ДОЛЖНА считаться полной только при доказанных начальном состоянии, количестве, уникальности и непрерывности переходов и согласованности с текущим статусом. Полнота Flagged ДОЛЖНА оцениваться отдельно. При обрезанном `expand=changelog` длительность не ДОЛЖНА выдаваться за точную.

#### AC-005: Частичный журнал

- **ДАНО** Jira сообщает больше записей истории, чем вернула.
- **КОГДА** приложение нормализует эпик.
- **ТОГДА** статусная история помечается неполной, а точный TTM остаётся неизвестным.

### FR-009: Неатомарное чтение

Система ДОЛЖНА повторно проверять метаданные задачи после чтения истории, включая случай ошибки истории. При изменении `updated` допускается ещё одна попытка чтения истории и метаданных. Если повтор стабилен, результат МОЖЕТ быть полным; продолжающееся изменение на последней попытке ДОЛЖНО помечать полученную статусную историю как `partial` с `ISSUE_CHANGED`. История предыдущей попытки не используется вместо неудавшейся повторной. При смене резолюции или потока решение о включении пересматривается.

`JIRA_UNAUTHORIZED`, `ABORTED`, `PROFILE_UNVERIFIED`, `RATE_LIMITED` ДОЛЖНЫ прекращать запуск новых чтений; уже запущенные операции завершаются перед освобождением задания. Отказ отдельной задачи, например 403/404, не тождественен глобальному отказу авторизации: результат зависит от источника и полноты отбора.

#### AC-006: Отказ отдельной истории

- **ДАНО** метаданные HF-эпика получены, но его история недоступна.
- **КОГДА** остальные истории доступны.
- **ТОГДА** эпик остаётся в наборе с неизвестной шкалой и предупреждением, не с выдуманной длительностью.

## Поведение при сбоях и на границах

Таймаут 20 секунд применяется к каждой попытке, а не ко всему импорту. Для временных сетевых ошибок, таймаутов и 5xx допускается до трёх попыток. При 429 ожидание `Retry-After` до 60 секунд допускает повтор; большее значение завершает чтение с `RATE_LIMITED`. Размер ответа ограничен 20 МиБ. Чтение задач ограничено четырьмя параллельными операциями.

Если есть включённые эпики, но ни одна возвращённая история не имеет `statusCoverage`, отличного от `unavailable`, новый набор не публикуется. Доступные **частичные** истории проходят этот барьер: набор может сохраниться с неизвестным TTM у всех эпиков. Полнота и вычислимость не тождественны; см. [модель качества](../domain.md).

## Связанные элементы: реализованное дополнение

### FR-031: Получение направленных связей и дочерних историй

Для каждого исходного Jira-эпика система ДОЛЖНА получить связи и пройти рекурсивно по нижним эпикам до обычных задач включительно. `A contains B` и `B is contained in A` ДОЛЖНЫ нормализоваться в одно отношение «A содержит B». Для каждого эпика система также ДОЛЖНА получать стандартный состав по Epic Link (раздел Jira «Задачи, составляющие бизнес задачу») и объединять его с явными связями без повторной строки одного ребёнка у того же родителя. Стандартный состав не ограничивается статусом, исполнителем или доской; исключение отклонённых и подзадач из видимой иерархии сохраняется. Обход идёт только вниз; вышестоящие элементы и посторонние типы связей не становятся детьми. Посторонние связи обычных задач не продолжают обход видимой иерархии. Для допустимых дочерних задач система дополнительно ДОЛЖНА читать состав подзадач и их истории, необходимые для FR-036. Подзадачи определяются по явному признаку типа; аналитическое чтение не делает их видимыми дочерними строками и не продолжает обход их произвольных связей.

Система ДОЛЖНА читать DF и обычные задачи независимо от фильтра исходной HF-выборки, учитывать резолюцию при отображении по FR-030 и получать историю для FR-032. Связь не добавляет элемент в исходную выборку. Истории используют общий момент среза набора; состав связей отражает наблюдение при загрузке и не выдаётся за исторический снимок связей на этот момент.

Качество состава ветки и истории ДОЛЖНО определяться отдельно. Отказ одного элемента сохраняет доступные ветки и предупреждение. Недоступность промежуточного эпика означает неизвестность его потомков. Глобальные ошибки подключения, авторизации, отмены и ограничения частоты сохраняют действующую остановку новых запросов; ошибка до публикации сохраняет предыдущий набор.

Основной граф ДОЛЖЕН быть получен до дополнительного аналитического чтения и иметь приоритет в бюджете объектов. Аналитические отношения подзадач не ДОЛЖНЫ менять видимые связи или полноту основного графа. Ограничение дополнительного бюджета и локальный отказ аналитического объекта, включая HTTP 5xx после допустимых повторов, обозначают неполноту нового анализа, сохраняя доступные основные ветки. Публикация следует FR-040; прежние обязательные условия успешного основного набора сохраняются. Для исторической оценки используется текущий состав подзадач с явным ограничением по FR-036; этот список не выдаётся за восстановленный состав в прошлом.

#### AC-033: Прямое и обратное представление

- **ДАНО** A contains B и B is contained in A описывают одно отношение; P contains A, а A blocks X — другие отношения.
- **КОГДА** загружается исходный A.
- **ТОГДА** B доступен как ребёнок A один раз; P и X не показаны его детьми.

#### AC-034: Отказ отдельной истории

- **ДАНО** одна дочерняя история возвращает 403, остальные доступны.
- **КОГДА** загрузка завершилась.
- **ТОГДА** доступные истории опубликованы, отказ указан у соответствующей строки; это не сообщение об отсутствии связей.

#### AC-038: Недоступный промежуточный эпик и глобальный отказ

- **ДАНО** имеется прежний набор.
- **КОГДА** один промежуточный эпик недоступен.
- **ТОГДА** его ветка отмечена неполной, соседние ветки доступны.
- **КОГДА** вместо этого возникает глобальный отказ авторизации.
- **ТОГДА** новые чтения прекращаются и прежний набор остаётся текущим.

#### AC-048: Стандартный состав дочернего эпика

- **ДАНО** RAILDIS-58 содержит RAIL-11361; у дочернего эпика есть аналитическая задача через contains и обычные задачи через Epic Link, в том числе повтор той же связи, отклонённая задача и подзадача.
- **КОГДА** пользователь загружает родительский эпик и последовательно раскрывает оба уровня.
- **ТОГДА** под дочерним эпиком видны все допустимые задачи обоих источников, с ключами и полосками доказанной истории; повторная связь не дублирует строку, отклонённые и подзадачи не показаны, числовые дни дочерних строк отсутствуют.
- **КОГДА** состав Epic Link разбит на страницы или его чтение недоступно/неполно.
- **ТОГДА** система получает все страницы либо явно обозначает неполноту; доступные contains-ветки сохраняются. Глобальный отказ останавливает загрузку и сохраняет прежний набор.

#### AC-063: Подзадачи читаются для анализа

- **ДАНО** допустимая дочерняя задача включена в спринт и имеет подзадачи.
- **КОГДА** загружается новый Jira-набор.
- **ТОГДА** состав подзадач и необходимые истории доступны анализу работы, но самостоятельные строки подзадач не появляются; полнота состава отличается от подтверждённо пустого списка.

### NFR-001: Ограниченный обход без молчаливой потери данных

Система ДОЛЖНА предотвращать бесконечные циклы и дублирование процесса получения одного объекта из-за нескольких родителей или присутствия объекта среди корней. В рамках одной загрузки/обновления все ссылки на устойчивую идентичность используют один общий процесс получения данных. Этот процесс включает чтение истории, контроль метаданных после неё и не более одного повторного чтения снимка при обнаруженной нестабильности; контрольные запросы не считаются дублированием обхода. Пределы количества объектов, связей и отображаемых путей ДОЛЖНЫ быть явными. При достижении предела нельзя заявлять полноту дерева; доступные данные сопровождаются предупреждением. Полное выполнение пользовательского сценария не ДОЛЖНО считаться подтверждённым только проверкой такого предупреждения.

#### AC-039: Цикл и предел объёма

- **ДАНО** граф с циклом, общими детьми и объёмом выше защитного предела.
- **КОГДА** выполняется загрузка и раскрытие.
- **ТОГДА** чтение завершается, нет бесконечного повторения; общий объект имеет один процесс получения данных независимо от числа родителей, контроль стабильности и ограниченный повтор разрешены, а ограничение явно видно.

## Текущие ограничения

Адаптер поддерживает доказательство полноты ответа Server через `expand=changelog`: нулевой начальный offset, совпадение количества и уникальности записей с `total`, корректная цепочка переходов. Порядок задаётся временем, id записи и порядком элементов записи. Это не догрузка обрезанного changelog по страницам. Живая длинная история сверх обычного объёма ответа ещё не проверена; Cloud-пагинация не предполагается.

Реализация связанных элементов проверена автоматическими сценариями на обоих источниках и живыми образцами Jira. Пользователь подтвердил проверку по ключу и признал её пока достаточной. Полная приёмка XLSX и остальных живых/ручных случаев не заявлена; границы результата и непроверенные остатки T012/T013 — в [протоколе](../changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md).

Аналитика спринтов добавлена по [FR-035–041](sprint-continuity.md). Автоматическая проверка выполнена; живая и визуальная приёмка новой раскладки остаются открытыми в [протоколе](../changes/archive/2026/LOCAL-20260929-01-sprint-continuity/verification.md).
