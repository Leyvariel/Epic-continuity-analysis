# Сохранение и обновление набора

## Назначение и ответственность

Сервис управляет жизненным циклом одного сохранённого набора и одного активного задания; при сбоях защищает последний пригодный результат.

## Требования

### FR-020: Атомарная публикация

Новый набор ДОЛЖЕН становиться текущим только после успешного расчёта и записи кэша через временный файл и атомарное переименование. Ошибка до публикации и отмена, замеченная до фазы `committing`, ДОЛЖНЫ оставлять прежний набор. Уже начатая запись не отменяется сигналом остановки; гарантия отката после входа в `committing` не предоставляется.

#### AC-013: Неуспешное обновление

- **ДАНО** ранее сохранён пригодный набор.
- **КОГДА** новое задание завершается ошибкой до записи.
- **ТОГДА** `GET /api/dataset` возвращает прежний набор.

### FR-021: Ручное обновление

По команде пользователя система ДОЛЖНА заново проверять в Jira сохранённых кандидатов файла, перечитывать актуальный состав доски или один эпик по сохранённому стабильному `issueId`. Для файла исключённые ранее кандидаты остаются во входном списке и проверяются заново. Сам файл с диска повторно не открывается: используются сохранённые ключи, контрольные поля и агрегаты, а `source.importedAt` остаётся датой исходного импорта. Для изменения списка или агрегатов нужен новый импорт файла.

Для прямого списка обновление ДОЛЖНО заново проверять всех сохранённых корректных кандидатов, включая ранее исключённых и недоступных: по стабильному `issueId`, если он уже известен, иначе по запрошенному ключу. Ошибочные строки формата сохраняются. Исходный текст поля повторно не читается; для исправления строки нужен новый ввод. Список только из ошибок формата обновляется локально без обращения к Jira; недоступность синтаксически корректной задачи проверяется заново в Jira. Время `source.importedAt` остаётся временем исходного ввода.

Запрос с устаревшим `datasetId` ДОЛЖЕН получать `STALE_DATASET` (409); для автономного набора возвращается `OFFLINE_SOURCE` (409).

### FR-022: Восстановление

При запуске система ДОЛЖНА восстанавливать последний набор из кэша без сети и пересчитывать производные шкалы из сохранённых входов. Job после перезапуска не восстанавливается. Если открытый интерфейс продолжает опрашивать исчезнувший job и получает `JOB_NOT_FOUND`, он ДОЛЖЕН открыть последний набор и объяснить исчезновение задания. При новом открытии страницы загружается набор, без восстановления прежнего задания.

#### AC-014: Перезапуск сервера

- **ДАНО** набор сохранён, а активное задание существовало только в памяти.
- **КОГДА** сервер запускается заново.
- **ТОГДА** набор доступен без Jira, а старый идентификатор задания не выдаётся за продолжающийся импорт.

### FR-023: Совместимость кэша

Кэш v2 ДОЛЖЕН мигрировать в v3 с профилем `legacy-v2`, сохраняя исходные входы, `id`, `savedAt` и переданный срез. Перед записью создаётся `dataset.v2.backup.json` с запретом перезаписи. Если файл backup уже существует, реализация продолжает миграцию без проверки соответствия его содержимого текущему v2. Производные числа пересчитываются текущим кодом; тесты подтверждают сохранение чисел проверенных фикстур, а не неизменность при любых будущих изменениях расчёта. Повреждённый кэш или неизвестный профиль ДОЛЖЕН сохраняться для разбора.

#### AC-015: Повреждённый кэш

- **ДАНО** локальный файл не проходит проверку схемы.
- **КОГДА** сервер читает его при запуске.
- **ТОГДА** исходный файл остаётся на диске, а API сообщает ошибку.

### FR-028: Сохранение прямого списка

Нормализованные кандидаты и аудит прямого списка ДОЛЖНЫ сохраняться вместе с набором в кэше v3. После перезапуска этот набор открывается без сети с включёнными эпиками и ошибками. При сбое нового задания до публикации прежний набор остаётся текущим. Прежняя версия приложения не читает новый вариант источника `kind: keys`; для отката требуется восстановить прежний совместимый `dataset.json` либо начать с пустым каталогом данных.

#### AC-023: Обновление списка

- **ДАНО** сохранены включённый, исключённый и недоступный ключи.
- **КОГДА** пользователь выбирает «Обновить».
- **ТОГДА** все три корректных ключа проверяются по текущей Jira, ошибки формата остаются в аудите, старые вычисленные эпики не подмешиваются.

Если ранее недоступная задача стала доступной и включена в HF-выборку, её прежняя строка ошибки ДОЛЖНА смениться обычной строкой результата без дублирования. Ошибка формата устраняется новым исправленным вводом, а не повторным запросом Jira.

#### AC-024: Восстановление списка

- **ДАНО** сохранён набор прямого списка.
- **КОГДА** сервер перезапущен без Jira.
- **ТОГДА** приложение показывает сохранённые эпики и ошибочные строки без нового запроса.

## Поведение при сбоях и на границах

Допускается одно активное задание в экземпляре сервиса; второе получает `BUSY` (409). В памяти удерживается не более 20 последних заданий. `completed` означает успешное сохранение, а не полные данные: в таком задании могут быть ошибки отдельных эпиков. Кэш содержит нормализованные входы и результат, но не PAT. После успешного нового импорта прежняя ошибка чтения кэша снимается.

## Связанные элементы: реализованное дополнение

### FR-034: Сохранение и обновление иерархии

Структура связей, сведения об исключениях, качество веток, входные истории и основания определения закрытия ДОЛЖНЫ сохраняться вместе с набором. При перезапуске система ДОЛЖНА восстановить их без сети с тем же моментом среза и заново получить производные полоски.

Обновление Jira ДОЛЖНО заново получать доступные связи и истории, учитывать добавление и удаление связей, изменение резолюции и ключа по устойчивой идентичности. Старая и новая иерархии не смешиваются. Публикация набора остаётся атомарной. Автономная книга обновляется повторным импортом, а не чтением Jira. Старый кэш без иерархии открывается с состоянием «не загружена», без автоматического сетевого обогащения.

#### AC-046: Перезапуск и старый кэш

- **ДАНО** сохранён набор с иерархией и фиксированным срезом.
- **КОГДА** сервер перезапускается без сети.
- **ТОГДА** дерево и полосы восстановлены с теми же датами; если вместо него открыт старый кэш без иерархии, это явно обозначено.

#### AC-047: Обновление и отказ сохранения

- **ДАНО** в Jira одна связь добавлена, другая удалена, общий ребёнок сменил ключ.
- **КОГДА** обновление успешно сохранено.
- **ТОГДА** виден новый состав без устаревшей связи и дубликата по прежнему ключу.
- **КОГДА** запись нового набора завершается ошибкой.
- **ТОГДА** полностью сохраняются прежний набор и прежняя иерархия.

## Текущие ограничения

Хранится только последний набор. Автоматического расписания обновлений, endpoint отмены, межпроцессной блокировки и сервиса резервного копирования нет. Запись через rename не сопровождается `fsync`; устойчивость к потере питания не доказана.

Реализация связанных элементов проверена автоматическими сценариями на обоих источниках и живыми образцами Jira. Пользователь подтвердил проверку по ключу и признал её пока достаточной. Полная приёмка XLSX и остальных живых/ручных случаев не заявлена; границы результата и непроверенные остатки T012/T013 — в [протоколе](../changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md).
