# Сохранение и обновление набора

## Назначение и ответственность

Сервис управляет жизненным циклом одного сохранённого набора и одного активного задания; при сбоях защищает последний пригодный результат.

## Требования

### FR-020: Атомарная публикация

Новый набор ДОЛЖЕН становиться текущим только после успешного расчёта и записи кэша через временный файл и атомарное переименование. Ошибка до публикации и отмена, замеченная до фазы `committing`, ДОЛЖНЫ оставлять прежний набор. Уже начатая запись не отменяется сигналом остановки; гарантия отката после входа в `committing` не предоставляется.

#### AC-013: Неуспешное обновление

- **ДАНО** ранее сохранён пригодный набор.
- **КОГДА** новое задание завершается ошибкой до записи.
- **ТОГДА** `GET /api/dataset` возвращает прежний набор.

### FR-021: Ручное обновление

По команде пользователя система ДОЛЖНА заново проверять в Jira сохранённых кандидатов файла, перечитывать актуальный состав доски или один эпик по сохранённому стабильному `issueId`. Для файла исключённые ранее кандидаты остаются во входном списке и проверяются заново. Сам файл с диска повторно не открывается: используются сохранённые ключи, контрольные поля и агрегаты, а `source.importedAt` остаётся датой исходного импорта. Для изменения списка или агрегатов нужен новый импорт файла.

Для прямого списка обновление ДОЛЖНО заново проверять всех сохранённых корректных кандидатов, включая ранее исключённых и недоступных: по стабильному `issueId`, если он уже известен, иначе по запрошенному ключу. Ошибочные строки формата сохраняются. Исходный текст поля повторно не читается; для исправления строки нужен новый ввод. Список только из ошибок формата обновляется локально без обращения к Jira; недоступность синтаксически корректной задачи проверяется заново в Jira. Время `source.importedAt` остаётся временем исходного ввода.

Запрос с устаревшим `datasetId` ДОЛЖЕН получать `STALE_DATASET` (409); для автономного набора возвращается `OFFLINE_SOURCE` (409).

### FR-022: Восстановление

При запуске система ДОЛЖНА восстанавливать последний набор из кэша без сети и пересчитывать производные шкалы из сохранённых входов. Производные TTM, TTM без флага, длительности и состав колонок пересчитываются по расширенной модели с сохранённым asOf, без продвижения среза к текущему времени. Сырые входы и аудит исходного отбора не переписываются ради нового числа. Ранее исключённые кандидаты без загруженной истории не включаются автоматически: их повторный отбор выполняется при обычном обновлении Jira. Job после перезапуска не восстанавливается. Если открытый интерфейс продолжает опрашивать исчезнувший job и получает `JOB_NOT_FOUND`, он ДОЛЖЕН открыть последний набор и объяснить исчезновение задания. При новом открытии страницы загружается набор, без восстановления прежнего задания.

#### AC-014: Перезапуск сервера

- **ДАНО** набор сохранён, а активное задание существовало только в памяти.
- **КОГДА** сервер запускается заново.
- **ТОГДА** набор доступен без Jira, а старый идентификатор задания не выдаётся за продолжающийся импорт.

#### AC-118: Пересчёт сохранённого среза

- **ДАНО** прежний кэш с полной историей 5 суток работы → 60 Отложено → 10 работы и сохранённым срезом.
- **КОГДА** приложение новой версии запускается без сети спустя неделю.
- **ТОГДА** TTM равен 15, календарный размах и исходные входы прежние; новый показатель использует только сохранённые доказанные флаги. Повторное чтение не увеличивает длительности.

#### AC-119: Кандидат без истории

- **ДАНО** отельный кандидат был исключён прежним отбором и его история не загружена.
- **КОГДА** набор открывается без сети.
- **ТОГДА** кандидат остаётся в сохранённом аудите без придуманного результата; обычное обновление может включить его по FR-005 после получения истории.

### FR-023: Совместимость кэша

Кэш v2 ДОЛЖЕН мигрировать в v3 с профилем `legacy-v2`, сохраняя исходные входы, `id`, `savedAt` и переданный срез. Перед записью создаётся `dataset.v2.backup.json` с запретом перезаписи. Если файл backup уже существует, реализация продолжает миграцию без проверки соответствия его содержимого текущему v2. Производные числа пересчитываются текущим кодом; тесты подтверждают сохранение чисел проверенных фикстур, а не неизменность при любых будущих изменениях расчёта. Повреждённый кэш или неизвестный профиль ДОЛЖЕН сохраняться для разбора при чтении. Исключение — явно подтверждённый пользователем сброс по FR-055, удаляющий данные анализа, включая повреждённый кэш и его локальную копию.

#### AC-015: Повреждённый кэш

- **ДАНО** локальный файл не проходит проверку схемы.
- **КОГДА** сервер читает его при запуске.
- **ТОГДА** исходный файл остаётся на диске, а API сообщает ошибку.

Сброс такого состояния проверяется отдельно по AC-150; обычное чтение ничего не удаляет.

### FR-028: Сохранение прямого списка

Нормализованные кандидаты и аудит прямого списка ДОЛЖНЫ сохраняться вместе с набором в кэше v3. После перезапуска этот набор открывается без сети с включёнными эпиками и ошибками. При сбое нового задания до публикации прежний набор остаётся текущим. Прежняя версия приложения не читает новый вариант источника `kind: keys`; для отката требуется восстановить прежний совместимый `dataset.json` либо начать с пустым каталогом данных.

#### AC-023: Обновление списка

- **ДАНО** сохранены включённый, исключённый и недоступный ключи.
- **КОГДА** пользователь выбирает «Обновить».
- **ТОГДА** все три корректных ключа проверяются по текущей Jira, ошибки формата остаются в аудите, старые вычисленные эпики не подмешиваются.

Если ранее недоступная задача стала доступной и включена в HF-выборку, её прежняя строка ошибки ДОЛЖНА смениться обычной строкой результата без дублирования. Ошибка формата устраняется новым исправленным вводом, а не повторным запросом Jira.

#### AC-024: Восстановление списка

- **ДАНО** сохранён набор прямого списка.
- **КОГДА** сервер перезапущен без Jira.
- **ТОГДА** приложение показывает сохранённые эпики и ошибочные строки без нового запроса.

## Поведение при сбоях и на границах

Допускается одно активное задание в экземпляре сервиса; второе получает `BUSY` (409). В памяти удерживается не более 20 последних заданий. `completed` означает успешное сохранение, а не полные данные: в таком задании могут быть ошибки отдельных эпиков. Кэш содержит нормализованные входы и результат, но не PAT. После успешного нового импорта прежняя ошибка чтения кэша снимается.

## Связанные элементы: реализованное дополнение

### FR-034: Сохранение и обновление иерархии

Структура связей, сведения об исключениях, качество веток, входные истории и основания определения закрытия ДОЛЖНЫ сохраняться вместе с набором. При перезапуске система ДОЛЖНА восстановить их без сети с тем же моментом среза и заново получить производные полоски и собственные длительности статусов, не прибавляя их к родителям. Состав колонок учитывает допустимые узлы независимо от раскрытия.

Обновление Jira ДОЛЖНО заново получать доступные связи и истории, учитывать добавление и удаление связей, изменение резолюции и ключа по устойчивой идентичности. Старая и новая иерархии не смешиваются. Публикация набора остаётся атомарной. Автономная книга обновляется повторным импортом, а не чтением Jira. Старый кэш без иерархии открывается с состоянием «не загружена», без автоматического сетевого обогащения.

#### AC-046: Перезапуск и старый кэш

- **ДАНО** сохранён набор с иерархией и фиксированным срезом.
- **КОГДА** сервер перезапускается без сети.
- **ТОГДА** дерево, полосы и собственные длительности восстановлены с теми же датами и общим составом колонок; если вместо него открыт старый кэш без иерархии, это явно обозначено.

#### AC-047: Обновление и отказ сохранения

- **ДАНО** в Jira одна связь добавлена, другая удалена, общий ребёнок сменил ключ.
- **КОГДА** обновление успешно сохранено.
- **ТОГДА** виден новый состав без устаревшей связи и дубликата по прежнему ключу.
- **КОГДА** запись нового набора завершается ошибкой.
- **ТОГДА** полностью сохраняются прежний набор и прежняя иерархия.

### FR-055: Сброс данных и начало нового анализа

В основном приложении система ДОЛЖНА предоставлять кнопку «Сбросить все данные». Перед выполнением система ДОЛЖНА показывать подтверждение с действиями «Отмена» и «Сбросить данные» и объяснять, что сохранённый анализ будет удалён и для его восстановления потребуется новая загрузка. Отмена и закрытие подтверждения ничего не меняют.

После подтверждения система ДОЛЖНА удалить текущий локальный набор: исходные входы анализа, аудит отбора, загруженные истории, иерархию, спринты и производные результаты, а также локальные копии и временные файлы этого набора, принадлежащие механизму кэша. Завершённые и ошибочные задания с данными прежнего набора удаляются из памяти. Сбрасываются поля ввода источника, поиск, фильтры, сортировка, масштаб, выбор источника метрик, раскрытые строки, выбранная карточка, прежние ошибки и сообщения. Пользователь видит стартовый экран выбора источника. Перезагрузка страницы и перезапуск сервера не восстанавливают удалённый анализ; новый импорт начинается без данных прежнего набора.

Сброс относится к данным анализа внутри приложения. Исходные CSV/XLSX пользователя, данные Jira, настройки и учётные данные подключения, согласованные правила расчёта и список проектов без спринтов сохраняются. Сброс не требует обращения к Jira. Режимы просмотра сохранённого снимка и демонстрации не предоставляют действие сброса.

Во время импорта, обновления или другого сброса действие ДОЛЖНО быть недоступно; сервер также отклоняет конфликтующее действие. Сброс из устаревшей вкладки не ДОЛЖЕН удалять новый набор, появившийся после открытия подтверждения: требуется открыть актуальный набор и заново подтвердить действие. Поздний ответ прежнего запроса не ДОЛЖЕН возвращать удалённые данные на экран.

Успех ДОЛЖЕН отображаться только после подтверждённого удаления сохранённых данных. При ошибке серверной очистки система ДОЛЖНА показать причину и сохранить текущий пригодный набор; удаление части вспомогательных копий не объявляется полным успехом. При потере ответа интерфейс ДОЛЖЕН сверить фактическое состояние с сервером, не предполагая ни успех, ни сохранность прежнего набора. Повторный сброс пустого состояния безопасен. Повреждённый кэш также можно удалить по явному подтверждению.

#### AC-145: Подтверждение и отмена

- **ДАНО** загружен набор и пользователь нажал «Сбросить все данные».
- **КОГДА** открывается подтверждение.
- **ТОГДА** видны последствия и два действия; до подтверждения запрос удаления не отправляется.
- **КОГДА** пользователь отменяет или закрывает подтверждение.
- **ТОГДА** набор, поля ввода и настройки отображения сохраняются.

#### AC-146: Сброс сохраняется после перезапуска

- **ДАНО** сохранён набор с историями, иерархией и спринтами, изменены фильтры и раскрыты строки.
- **КОГДА** сброс подтверждён и сервер завершил очистку.
- **ТОГДА** отображается стартовый экран с исходными значениями полей и настроек; API возвращает отсутствие набора, прежние задания недоступны.
- **КОГДА** страница и затем сервер перезапускаются без Jira.
- **ТОГДА** набор остаётся пустым; копии кэша не восстанавливают старый анализ.

#### AC-147: Новый импорт и границы очистки

- **ДАНО** сохранён анализ A, настроено подключение к Jira и имеется исходный файл пользователя.
- **КОГДА** выполнен сброс, затем импортирован набор B.
- **ТОГДА** B не содержит данных A; исходный файл, настройки подключения и согласованные правила расчёта сохранены. Для самого сброса сетевых запросов к Jira нет.

#### AC-148: Занятость и устаревшее подтверждение

- **ДАНО** выполняется импорт или обновление.
- **КОГДА** пользователь пытается сбросить данные, в том числе прямым запросом API.
- **ТОГДА** действие отклонено как занятое; задание и прежний набор сохраняются.
- **ДАНО** подтверждение открыто для A, но другая вкладка уже загрузила B.
- **КОГДА** отправляется подтверждение сброса A.
- **ТОГДА** B сохраняется, интерфейс сообщает об изменении набора и требует нового подтверждения.

#### AC-149: Ошибка очистки и потерянный ответ

- **ДАНО** существует пригодный сохранённый набор.
- **КОГДА** удаление кэша завершается ошибкой.
- **ТОГДА** пригодный набор остаётся текущим и восстанавливаемым; показана ошибка, успех не заявлен.
- **КОГДА** сервер выполнил сброс, но ответ потерян.
- **ТОГДА** повторное чтение подтверждает пустое состояние; интерфейс не возвращает прежний набор из памяти и не запускает импорт автоматически.

#### AC-150: Пустой или повреждённый кэш

- **ДАНО** набора нет либо его кэш повреждён и анализ не открывается.
- **КОГДА** пользователь подтверждает сброс; в пустом состоянии действие затем повторяется.
- **ТОГДА** результат — стартовый экран без ошибки чтения кэша; повтор не создаёт данных и не требует Jira.

#### AC-151: Просмотр и защита локального действия

- **ДАНО** открыт режим демонстрации или просмотра снимка.
- **КОГДА** отображается интерфейс либо отправлен прямой запрос сброса.
- **ТОГДА** кнопки нет, сервер отклоняет запрос; снимок сохраняется.
- **ДАНО** запрос приходит с чужого источника или без заголовка локального действия.
- **КОГДА** сервер принимает запрос.
- **ТОГДА** он отклоняет его с существующей защитой локального API без удаления данных.

#### AC-152: Поздний ответ прежнего запроса

- **ДАНО** ответ чтения или опроса старого задания задержался, а сброс уже завершён.
- **КОГДА** старый ответ приходит в интерфейс.
- **ТОГДА** пустое состояние сохраняется; история, карточки и результаты прежнего анализа не появляются вновь.

## Текущие ограничения

Хранится только последний набор. Автоматического расписания обновлений, endpoint отмены, межпроцессной блокировки и сервиса резервного копирования нет. Запись через rename не сопровождается `fsync`; устойчивость к потере питания не доказана.

Связанные элементы проверены автоматическими сценариями, живыми образцами Jira и полным браузерным путём XLSX 11.11.2026. Естественный отказ словаря категорий не наблюдался; резерв по названию проверен управляемым повтором живых историй. [Свидетельства и границы приёмки](../changes/archive/2026/LOCAL-20260924-02-linked-issue-status-bars/acceptance-20261111.md).
