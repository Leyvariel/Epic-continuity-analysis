## Путь данных и ответственность

Существующий сбор Jira → `hierarchy` и `sprintInputs` → полная проверка статусов/членства/календаря в `analyzeSprints` → новый чистый расчёт для исходных корней → `SprintAnalysis` → таблица, сортировка и детали. Видимость сегментов — отдельная проекция полного аналитического результата.

`server/jira/dataset.ts` остаётся владельцем сборки набора, `server/cache.ts` — атомарной публикации. Новые сырые входы, таблицы, сервисы, внешние зависимости и отдельная миграция не нужны. Поле нового результата предлагается хранить производно в `SprintRow.focus` только для исходных корней; это часть существующего `SprintAnalysis`, а не копия исходной истории в `EpicTimeline`.

Новый `server/sprint-focus.ts` — чистая функция расчёта циклов и интервалов. `server/sprint-analysis.ts` передаёт ей уже доказанные полные интервалы и структурированные признаки полноты; наличие неизвестности нельзя выводить из текста предупреждений или видимых кнопок. Общие проверки истории и интервальные операции переиспользуются. При необходимости выделить их из текущей функции в именованные вспомогательные функции, сохранив старые результаты побайтно по смыслу.

## Циклы реализации

По полной цепочке статусов на срезе последовательно открыть цикл первым входом в распознанную Реализацию; закрыть его первым следующим входом в Эксперимент. Повторная Реализация при открытом цикле его не дублирует. После эксперимента следующий вход начинает новый цикл. Доказанное создание сразу в реализации разрешено. По решению D9 незавершённый экспериментом цикл ограничивается окончательным закрытием, иначе срезом.

Объединить непересекающиеся циклы и вычесть все их пересечения с Отложено. Не подставлять общие границы TTM: у истории с неизвестным ранним Discovery циклы реализации могут быть доказаны независимо. Проверять всю предоставленную цепочку, включая события после среза; будущие события не добавляют время на срезе. Сохранять порядок одновременных переходов и наблюдение нулевого цикла; список только положительных фаз `sprintStatusHistory` не должен ошибочно превращать такой цикл в «реализация не начата».

Обозначим полученное множество интервалов W. В него могут входить тестирование, релиз и возвраты до эксперимента. Промежутки вне W не оцениваются.

## Формула покрытия и времени без работы

Использовать полуоткрытые интервалы `[start,end)` в миллисекундах и прежние точные операции объединения, пересечения и вычитания. Округлять только отображаемые дни.

- C — объединение всех пригодных закрытых и наблюдаемых активных спринтов из календарей допустимых нижних задач; будущие исключены.
- P — объединение целых наблюдаемых спринтов, в которых подтверждена работа хотя бы одной допустимой задачи по FR-036.
- A — объединение наблюдаемых активных спринтов.
- U — область возможного покрытия неизвестной работой, членством, составом или календарём. Неограниченная неизвестность даёт W; ограниченная рабочая неизвестность распространяется на весь затронутый спринт.
- D = W ∩ C — оцениваемое время; доказанное время вне всех спринтов исключено.
- N = D без P и U — доказанное либо предварительное время без работы.
- Nпредв = N ∩ A; Nзакр = N без A.
- Uост = (W ∩ U) без P — неизвестность, которая ещё может изменить итог.

Если Uост непусто, точный итог неизвестен: нельзя выдавать сумму известных фрагментов за полное число. Если Uост пусто и D имеет положительную длительность, показатель равен длине N = длине Nзакр + длине Nпредв. Ненулевое Nпредв помечает итог предварительным. Известная работа имеет приоритет над неизвестностью; перекрытия не удваиваются.

Неполный календарь может скрывать как дополнительную работу, так и дополнительную область оценки, поэтому его нельзя молча заменить прочитанной частью C. Отсутствие задач не доказывает ритм: при текущем источнике без пригодного календаря выводить причину отсутствия расчёта. Если W пусто, различать отсутствие реализации, нулевой период и отсутствие учитываемого времени после Отложено. Если D пусто при полном календаре, показывать «В периоде нет спринтов», а не успешный нулевой простой.

Инварианты при вычислимом результате: `0 ≤ N ≤ D ≤ W`; покрытое время, Nзакр и Nпредв разбивают D без пересечений; Отложено и дни вне спринтов не входят в D. Количество задач, путей, досок и одинаковых названий не меняет эти равенства.

Подтверждённая работа в любой части наблюдаемого спринта покрывает его целиком; метрика обрезает покрытие границами W, а не ищет отдельные рабочие часы внутри W. Например, работа в конце того же спринта может покрыть раннюю часть цикла. Это следствие согласованного приближения, которое нужно объяснить в правилах.

## Контракт результата и UI

Предлагаемый `SprintFocusResult` хранит состояние (`not-started`, `not-applicable`, `known`, `preliminary`, `unknown`), циклы и оцениваемые интервалы, итог/закрытую/предварительную длительности, неизвестные интервалы, причины и ссылки на исходные ID спринтов/задач. Поля и детальные причины уточняются при реализации без изменения FR-049–053; контракт не копируется целиком в SDD.

`shared/metrics.ts` получает явный контекст новой аналитики по ключу исходного эпика. Один и тот же доступ к метрике используется таблицей и сортировкой; значения не извлекаются из `excelAggregates`. Изменения: тип Metric и доступ к значению/причине, `src/App.tsx` (колонка, сортировка, панель), `src/HierarchyRows.tsx` (прочерк), `shared/composition.ts` и легенда (новая служебная метрика не становится этапом). Источники без аналитики показывают причину; в режиме Excel колонка скрыта и сортировка сброшена. Сводные медиана и максимум остаются по TTM.

`visibleSprints` фильтрует по `state === work` для всех уровней, независимо от прежних `hiddenSprintIds`. Полные сегменты остаются для расчёта и диагностики. `sprintBounds` получает аналитические границы отдельно от видимости: новая фильтрация не меняет существующий диапазон, даже если видимый слой пуст. Не вводить циклическую зависимость: видимость не участвует ни в расчёте новой метрики, ни в старых gaps.

На полосках нет ?, ○ и ◌; пустые полосы не резервируют дорожки, кроме компактного текстового состояния без работы. Предупреждения о неполноте остаются доступными без кнопки скрытого спринта. Детали эпика объясняют числовые части и расхождение с прежней тёмной отметкой; действующие классы, положение и подпись самой отметки FR-038 сохраняются.

## Кэш, ошибки и эксплуатация

Производный результат строится заново из прежних входов v3 на прежнем asOf; сохраняемые входы, ID набора, savedAt и аудит не меняются при чтении. Старый кэш без спринтов остаётся открываемым с недоступной новой метрикой. Автономный XLSX не обогащается Jira; исходные агрегаты сохраняются. Чистая функция детерминирована; повторная загрузка тех же входов даёт тот же результат.

Не меняются пределы чтения, повторы, один активный импорт, атомарная публикация и обработка 403/404/глобальных ошибок. Не менять рабочий набор ради проверки. PAT и Keychain остаются в прежнем серверном контуре. Перезапуск с новой версией пересчитает сохранённый набор без нового запроса Jira.

Расчёт повторно использует уже собранный граф и интервалы, а не загружает задачи при раскрытии. Не расширять лимиты 10 000 узлов, 50 000 рёбер и существующие пределы спринтов. Для больших наборов объединять интервалы перед пересечениями; не добавлять запросы, зависящие от числа видимых строк.

## Ввод и откат

После согласования пакета и отдельного разрешения выполнить TDD-пары, общую регрессию и реальную проверку браузера на синтетическом/сохранённом наборе. Временная копия кэша проверяется без сети; рабочие данные не заменяются. После проверки перенести дельты в текущие спецификации, обновить эксплуатационное описание и архивировать по правилам проекта. Откат возвращает прежний код: входы остаются совместимыми. Реализация разрешена; commit и push не поручены.
