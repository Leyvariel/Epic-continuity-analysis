# Дельта: видимость спринтов с работой

## Добавленные требования

Нет. Новая метрика описана отдельно в sprint-focus.md.

## Изменённые требования

### FR-035: Сегменты спринтов на задачах и эпиках

Система ДОЛЖНА показывать сегменты спринтов в полосках обычных дочерних задач, Delivery-эпиков и главного эпика на общей календарной оси. На задаче сегмент отражает её работу по FR-036; на эпике — работу допустимых обычных задач всех его нижних веток, а не собственный статус эпика или назначенный ему Sprint. Сегменты главного эпика видны сразу, Delivery-эпика — при появлении его строки, задачи — при раскрытии до её уровня. Раскрытие не является условием расчёта.

Каждый сегмент ДОЛЖЕН сохранять название, собственные даты и различимый источник ритма. Спринты разных ритмов не ДОЛЖНЫ принудительно получать одинаковые границы. На эпиках сегменты разных спринтов не ДОЛЖНЫ превращаться в один безымянный сплошной интервал: общий результат покрытия может объединяться, но идентичности спринтов остаются различимыми. Один и тот же спринт учитывается в каждой полоске один раз независимо от числа задач и путей к ним.

В выборку ДОЛЖНЫ входить закрытые спринты для анализа прошлого и начавшиеся активные, ещё не закрытые спринты; будущие исключаются по FR-039. Система ДОЛЖНА различать спринты с подтверждённой работой задачи или потомков эпика, спринты без такой работы и недостаточность данных. Для выявления пропущенных спринтов рассматриваемый календарь не ДОЛЖЕН ограничиваться только спринтами, найденными у задач эпика. На всех трёх уровнях ДОЛЖНЫ отображаться только спринты с подтверждённой работой по FR-036. Пустые, неизвестные и активные без подтверждённой работы сегменты скрываются по FR-042; их даты, состояния и причины сохраняются для аналитики и текстовых пояснений. Статусная история и течение этапа на той же полоске сохраняются, поэтому отсутствие работы можно сопоставить с продолжающимся этапом. Отметка бреши на главном эпике ограничивается этапами FR-038; само отображение сегментов на других уровнях не меняет это ограничение. Показ самостоятельных строк Jira Sub-task этим требованием не вводится.

### FR-037: Покрытие целыми спринтами и объединение задач

ЕСЛИ работа задачи по FR-036 подтверждена хотя бы в части спринта, система ДОЛЖНА считать этот спринт спринтом с работой целиком. Внутренние паузы между рабочими интервалами этой задачи или её подзадач не ДОЛЖНЫ становиться отдельными брешами внутри такого спринта.

Для главного эпика система ДОЛЖНА отдельно объединять временное покрытие спринтов с подтверждённым включением хотя бы одной допустимой дочерней задачи. Такое включение устраняет общую брешь в покрытом периоде независимо от рабочего статуса, команды, проекта и ритма. Состояние работы каждого сегмента по FR-036 при этом не меняется. Это покрытие членством используется только прежними брешами FR-038. Для новой метрики FR-050 объединяются спринты с работой; включение без работы её не покрывает. Сворачивание, порядок строк и порционная отрисовка не ДОЛЖНЫ менять расчёт. Общая задача не увеличивает длительность покрытия при повторной встрече в разных ветках.

### FR-039: Неизвестность отличается от бреши

Система ДОЛЖНА различать два вывода: работу в сегменте спринта по FR-036 и отсутствие включённых задач для бреши по FR-038. Недоступная статусная история, неизвестная категория или неполный состав Sub-task делают работу неизвестной, но сами по себе не мешают доказать отсутствие членства родительской задачи. При известном включении брешь отсутствует независимо от полноты рабочих статусов и Sub-task.

Полнота состава дочерних задач ДОЛЖНА оцениваться отдельно для каждого главного эпика, включая вложенные ветки и допустимых потомков скрытого отклонённого эпика. Непрочитанный элемент с неизвестным типом/допустимостью или неполученная часть ветки учитываются как возможные включённые задачи. Если неизвестные состав, членство, даты или календарь не позволяют ограничить возможное включение, отрицательный вывод во всём оцениваемом периоде затронутого эпика запрещён. Неполнота одной ветки не отменяет достоверную оценку независимого главного эпика.

Под цветной полосой эпика ДОЛЖНЫ отображаться только подтверждённые бреши по FR-038. Известное включение задачи исключает брешь на всём спринте; неизвестность возможного включения также запрещает брешь. На перекрытии с активным спринтом окончательная брешь не показывается. Доказанный промежуток без спринта не является брешью. Недостаточность данных на этой полосе не рисуется.

В аналитическом результате сегментов сохраняется приоритет работы: подтверждённая работа, неизвестность, предварительное отсутствие работы активного спринта, отсутствие работы закрытого спринта. Пустой и неизвестный сегменты скрыты по FR-042, но сохраняют собственные границы в аналитике и текстовых пояснениях; отсутствие работы не равнозначно отсутствию включённых задач. Состояния сегментов задач и эпиков не ограничиваются маской FR-038. Отсутствие подходящего HF-этапа у Delivery-эпика не скрывает его сегменты с доказанной работой. Новый числовой показатель имеет собственные границы и правила неизвестности FR-049–051; членство без работы не заменяет рабочее покрытие.

Будущие, ещё не начавшиеся спринты не ДОЛЖНЫ входить в аналитическую выборку, создавать покрытие, неизвестность или расширять ось, в том числе при отсутствии дат. Начавшийся активный спринт ДОЛЖЕН попадать в выборку без completeDate; он ограничивается срезом. Состояние оценивается на срезе; закрытие после него не переносится в прошлое. Отказ чтения спринта или подзадачи сохраняет доступные статусные полосы. Причины неполноты ДОЛЖНЫ оставаться в текстовых пояснениях анализа, доступных и без видимого сегмента; неизвестность отличается от предварительного результата ещё не завершённого периода.

### FR-042: Только спринты с подтверждённой работой

На строках обычной задачи, вложенного эпика и исходной гипотезы система ДОЛЖНА показывать только спринты с подтверждённой работой по FR-036/037. Пустые, неизвестные и активные без подтверждённой работы сегменты скрываются независимо от положения внутри открытого периода задачи. Одного участия, нахождения в Backlog либо неизвестной истории недостаточно для видимости.

Спринт с доказанной работой показывается целиком в наблюдаемых границах, включая части до или после закрытия задачи, если подтверждённая работа и членство пересекались внутри этого спринта. Активный спринт ограничивается срезом. Пустая или неизвестная ветка не скрывает подтверждённую работу другой ветки у общего родителя; сама неизвестность остаётся доступной в текстовых пояснениях соответствующей строки.

Это фильтр отображения: исходные аналитические состояния не удаляются. Новый показатель FR-050 не рассчитывается по списку видимых кнопок; прежние бреши FR-038, доказательство работы, числовые TTM/CT/impediment и кэш входов не меняются из-за скрытия. Фильтр восстанавливается без Jira. Из скрытых сегментов не создаются дорожки, кнопки, табуляция и отдельные всплывающие карточки. Для полностью скрытого слоя используется текст «Нет спринтов с подтверждённой работой»; причины неполноты показываются отдельно.

Календарная ось сохраняет исходный аналитический диапазон и прежние отметки; скрытие не сжимает календарь, не меняет даты и не убирает причины неизвестного числа.
