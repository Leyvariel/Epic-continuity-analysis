# Проверка реализуемости

Уточнение после независимого ревью: Q7 решён, R7 учтён в AC-082/B31; сегменты на трёх уровнях описаны в FR-035 и AC-081/B30. [Текущие проверки](evidence/sprint-levels-checks.json) подтверждают документы, а не реализацию.

Последующая [проверка актуальной редакции](review-5.md) уточнила состояния Delivery без HF-маски, независимый от статусной истории слой сегментов и различие конкретного спринта с общим покрытием. R8–R10 исправлены в документах с AC-083–085; производственная реализация не проверена.

## Итог стадии

Последняя [проверка после доработки](review-3.md) выявила R6. По поручению пользователя оно учтено: дизайн связывает неполноту достижимого состава с областью неизвестности отдельно для каждого корня; AC-078–080 / B27–B29 проверяют результат и восстановление. [Матрица исправлений](review-resolution.md) отражает закрытие R1–R6 в документах; D1 позднее подтверждено [живой проверкой](live-discovery.md); native Sub-task подтверждены [примером](d2-decision.md); подготовленная редакция A по текущему составу ожидает итогового согласования E1.

Проверка кода и исходной регрессии выполнена. Два прохода выявили R1–R5, после чего пакет доработан по поручению пользователя. Решения внесены в проект документов и сценарии; их состояние и ограничения — в [матрице доработки](review-resolution.md). Источники истории спринтов и текущих Sub-task проверены на целевой Jira. Редакция A не зависит от доказательства полного прошлого состава; её ограничение E1 включено в итоговое согласование этапа 5. Готовность к реализации ещё не подтверждена согласованием.

## Сопоставление с текущим кодом

[Повторная проверка](review-2.md) сохранила контрпримеры R4/R5. Теперь дизайн требует проверки полной цепочки до отсечения и сохраняет действующее различие локального HTTP-отказа и глобальной ошибки; реализация новой аналитики ещё не проверена.

| Область | Найденный факт | Решение или риск |
| --- | --- | --- |
| Владелец входов | `JiraInputs`, `collectJiraInputs`, `buildJiraDataset` и `CacheStore` уже задают полный путь | Новые сведения включаются в тот же результат и запись |
| История | `getHistory` сохраняет только статус и флаг | Историю Sprint нужно получить из той же доказанной цепочки либо отдельного проверенного источника; текущий контракт её теряет |
| Граф | Узел `subtask` и история допустимы схемой; общий предел — 10 000 | Основной обход завершается первым; подзадачи занимают только оставшиеся места, аналитические отношения отделены от основных рёбер |
| Дочерний календарь | `relatedTimeline` определяет закрытие для эпика или задачи, не аналитической подзадачи | Расчёт рабочих интервалов должен брать исходную доказанную историю, не полагаться на текущую производную полосу подзадачи |
| Категории | Справочник категорий статусов уже собирается | Работа требует проверенного соответствия категории, без словаря закрытия и без `isActive` HF |
| Пагинация | `collectPages` требует стабильный `total` и последовательный `startAt` | D1 подтвердило isLast без total и фактический предел страницы 50; нужен соответствующий разбор завершения |
| Новый этап | «Проверка идей» не входит в `STAGES`; неизвестный статус до первого активного делает TTM неоднозначным | FR-041 обеспечивает календарный показ из полной истории; числовые правила не меняются |
| Отображение | `HierarchyRows` использует путь и порционную отрисовку; `childrenOf` исключает подзадачи | Сводный расчёт выполняется до UI, новые строки подзадач не требуются |
| Кэш | Схема графа строгая, входы Jira нормализуются, производные данные перестраиваются | Новое дополнение должно пройти явную схему, ссылки и срез; нельзя надеяться на сохранение неизвестных полей |
| Откат | Текущие исходники не входят в HEAD | Нужна локальная копия рабочего дерева и кэша, `git checkout` не является достаточным планом восстановления |

Проверенные пути и первичные наблюдения — в [исследовании](research.md). Фактическая база исходников сохранена в [контрольных суммах](evidence/baseline-sha256.json).

## Что проверено автоматически

`npm run check` завершился с кодом 0: 42 файла, 309 тестов; `tsc --noEmit` и Vite успешны. [Лог](evidence/baseline-check.txt). Новая возможность отсутствует: этот результат не доказывает чтение спринтов, работу по подзадачам или новые бреши.

Для фиксированного примера BDD вручную заданы четыре ожидаемых интервала; арифметика их длительностей дополнительно проверена независимо от будущей реализации. Ожидаемые интервалы не вычислялись тестируемым кодом.

## Живая проверка и доступ

Подготовлена ограниченная диагностика: существующий механизм чтения PAT, сведения о версии/статусах/поле Sprint и три уже имеющиеся в локальном наборе задачи HOTELS-14091, HOTELS-14245, ANL-20734. Запросы — только GET; рабочий кэш и Jira не изменяются, PAT не выводится. Исходный локальный набор содержит 164 обычные задачи; диагностика не запрашивает их все.

Первый запуск внутри sandbox завершился `KEYCHAIN_NOT_FOUND` до сетевого запроса; код 1. [Факт попытки](evidence/jira-access-attempt.json). Это не доказывает отсутствие PAT вне sandbox. В протоколе предыдущего изменения описан аналогичный доступ через отдельно разрешённый запуск вне sandbox. Позднее пользователь предоставил постоянный доступ приложению. Узкие командные правила сохранены и зеркалированы в gvault, GET-диагностика выполнена; [новый протокол](live-discovery.md). Первоначальный отказ sandbox остаётся историческим фактом, а не текущим блокером.
