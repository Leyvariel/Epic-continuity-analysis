## Данные

Времена и ожидаемые четыре бреши заданы вручную в [контрольном наборе BDD](bdd-scenarios.md). Фикстуры нормализованных интервалов не вызывают вычислитель для получения ожидаемого результата. Категории статусов включают рабочую, начальную, завершённую, отсутствующую и неизвестную. Название статуса без категории не считается доказательством работы.

Фактические образцы D1 сохранены в [живой проверке](live-discovery.md): Sprint версии 2, from/to с ID, две полные последовательности страниц isLast. Они служат основой минимальных адаптерных фикстур; образцы D2 для native Sub-task, текущего состава и статусных историй сохранены в [проверке примера](d2-decision.md). Редакция A использует текущий состав; доказательство прошлого состава не требуется, предел результата отражён в AC-070/071. Нельзя выдавать выдуманный ответ Jira за проверенный контракт. Для алгоритма допустимы полностью вымышленные нормализованные входы, явно отделённые от адаптерных образцов.

Из реального примера следует подготовить адаптерные проверки: непустые `subtasks` при пустом `issuelinks`; связь по ID и `issuetype.subtask`; категория по ID при различающихся именах; RAIL-13346 не покрывает 13433, поскольку работа закончилась до добавления родителя в спринт. Проверка записанных данных реализована в `tests/sprint-rail-replay.test.ts`: RAIL-13346 покрывает только 13311; 13433 покрывается RAIL-13347. Это воспроизведение записи D2, не новая живая сверка.

Фикстуры состава содержат полные текущие списки и обратные parent, пустой/неполный текущий состав, противоречие и обнаруженное изменение parent. Отдельно проверить дату создания внутри спринта: наличие текущей подзадачи не разрешает ранний переход к статусу родителя. Событие переноса синтетическое, его живой формат не заявляется проверенным. Для R2 нужны 8 000/3 000 и 10 000/1 узлов, разные порядки завершения запросов, общий ID и перезапуск. Для R5 подставной клиент возвращает 500/500/500, 500/200, 403 и глобальные ошибки; проверяются число попыток, итог задания, ID набора и записи кэша. Контрпримеры старого кода из review-2 остаются свидетельством проверки дизайна, не красными/зелёными тестами нового поведения.

Для R6 нужны отдельные структурные варианты: неизвестный дочерний узел после локального отказа; неполученное ребро и `branchCoverage: partial` без ID ребёнка; неполная вложенная ветка под скрытым отклонённым эпиком; общий потомок и цикл; независимый полный корень. Полнота известной T и её календаря задана отдельно, чтобы неизвестность возникала именно из состава графа. Проверить результаты B27–B29 до и после перезапуска без сети; ожидаемые интервалы заданы вручную, а не вычислителем спринтов.

## Негативные и граничные случаи

- Положительное пересечение рабочего статуса, членства и спринта; нулевое касание границ; событие точно на срезе и после него.
- Добавление в середине спринта, удаление до его начала, перенос между спринтами, отсутствие доказанного начального набора Sprint.
- Подзадача создана внутри спринта; обнаружен перенос или другой parent; текущий состав полный пустой, непустой либо неизвестный. Родитель не подменяет текущие подзадачи даже до их создания. Пометка текущего состава остаётся при сворачивании и после перезапуска.
- Два одновременно идущих спринта одного источника, разные источники, одинаковые имена, общий спринт на нескольких досках.
- Фактическое закрытие раньше/позже планового конца; неизвестная дата; начавшийся активный спринт без completeDate обязательно включён. Подтверждённый future без дат исключён до проверки дат: не создаёт неизвестности или покрытия даже при назначении работающей задачи; результат сохраняется после перезапуска. Противоречивый future не принимается за доказанное исключение. Период без определимого календаря.
- Повтор выбранного этапа, смешанные статусы, неизвестный TTM при полной истории и действительно неполная история.
- 403/404 отдельного источника, глобальные ошибки, нестабильность снимка, пропуски/повторы страниц и все пределы из дизайна.
- Работа соседней задачи при неизвестности другой: положительное покрытие сохраняется; неизвестность распространяется на целый возможный спринт. Активный спринт имеет приоритет над отрицательной оценкой закрытого; подтверждённый период без спринта не является брешью.
- Единственный переход после среза восстанавливает предыдущее состояние; разрыв после среза остаётся разрывом; текущее закрытие с completeDate после среза не меняет прошлое состояние спринта.
- Бюджет аналитики не меняет основной граф, его полноту или полосы до/после перезапуска. Состав дополнительных ID устойчив к порядку ответов.
- При локальном 5xx после повторов основной набор публикуется с неизвестной аналитикой, если все остальные условия выполнены; при глобальных ошибках публикаций нет. Действующий код не меняется в сторону глобального отказа на любой JIRA_HTTP.
- Неполнота достижимых веток проверяется до потери неизвестных элементов при отборе. Общая `graph.coverage` не запрещает оценку независимого полного корня. Неизвестность состава не ограничивается календарями уже прочитанных задач; положительное покрытие сохраняется.
- Неполученное ребро объясняется на существующем предке; после восстановления нет ссылок на отсутствующие узлы. Общие ветки распространяют неполноту на все достигающие их корни, цикл не вызывает бесконечный обход.
