# Предложение: расширение статусной модели и расчёта TTM

Пакет согласован к реализации 02.11.2026. Основание — прямое поручение пользователя «Приступай к реализации» после предъявления полного пакета. Оно разрешает согласованный объём требований, дизайна и задач; повторное разрешение на него не требуется. Ход реализации и фактические проверки ведутся в протоколе.

## Проблема

Нынешние восемь этапов правильные, но недостаточны для анализа старой и новой моделей и Отелей. Дополнительные статусы могут сохраняться в календаре, не получая числовых колонок; некоторые не позволяют прежнему расчёту доказать начало TTM. Отельные эпики в текущих статусах без префикса также не проходят нынешний отбор. Проверенные факты — в [исследовании](research.md).

## Ожидаемый результат

Пользователь видит все фактически встречающиеся статусы исходных и вложенных объектов, сравнивает собственные длительности и два показателя исходных эпиков: TTM и TTM без флага. Старые названия не заменяются новыми. Колонки упорядочены для сопоставления исторических моделей; календарь сохраняет реальную последовательность.

Гипотеза полезности: новые колонки помогут заметить этапы работы и ожидания, которые сейчас нельзя сравнить отдельно. Это ожидаемый, ещё не измеренный эффект.

## Подтверждённые решения

Основание — запрос 15.10.2026 и ответы пользователя 02.11.2026. Jira подтверждает названия и наблюдаемую историю, но не заменяет решения пользователя о TTM.

| Область | Решение |
| --- | --- |
| Каталог | Сохранить восемь прежних этапов; добавить Проверка идей, Решили делать, Отложено, Запланировано, Тестирование эпика и Релиз |
| Точные названия | Каталог HOTELS содержит «[HF] Проверка идей», «[HF] Отложено», «[HF] Запланировано», «Тестирование эпика», «Релиз». «Решили делать» подтверждено историей HOTELS-12351 |
| Порядок колонок | ↩О → Подготовка → Проверка идей → Валидация → Решили делать → Отложено → Скоринг → Запланировано → Проработка решения → Готово к реализации → Реализация → Тестирование эпика → Релиз → Эксперимент → Оценка результата |
| Открыто | Первоначальное ожидание не требуется отдельным числом; важны возвраты. Сохраняется ↩О, новая колонка полного Открыто не создаётся. История первоначального ожидания остаётся вне TTM |
| Проверка идей | Учитываемая работа: в подтверждённом примере первые 5 суток проверки входят в TTM. Может начать отсчёт |
| Отложено | Есть ценность, реализация отложена на 1–2 квартала. Не запускает TTM; всё время в нём исключается, в том числе после начала работы. Пример 5 + 60 отложено + 10 даёт TTM 15 суток |
| Запланировано | План на текущий или начало следующего квартала. Входит в TTM и может начать его. По договорённости флаг ставится при планировании и снимается при переходе в проработку решения; приложение только читает факты |
| TTM без флага | Для 10 суток Запланировано с флагом и 5 суток проработки TTM = 15, TTM без флага = 5. Это отдельный показатель, основной TTM остаётся доступным |
| Решили делать в Отелях | Исторически шёл после Открыто до Discovery, но уже входил в TTM, несмотря на категорию «К выполнению», указанную пользователем |
| Состав колонок | Показывать только встречающиеся в наборе статусы, включая прежние. Это правило не скрывает служебные колонки и оба показателя TTM |
| Представления | Таблица, календарь, детали, «Состав из Excel» и автономный XLSX |
| Вложенные объекты | Собственные числовые статусные длительности вложенных эпиков и задач; они не прибавляются к родительскому времени и статистике корней. Отдельный дочерний TTM не запрошен |
| Отбор HOTELS | Включать исходные эпики в текущих «Решили делать», «Тестирование эпика», «Релиз», несмотря на отсутствие [HF]. Остальные проекты проверять по прежним правилам |
| Нормы и бреши | Новые нормативные сроки и новые этапы поиска брешей не добавлять; прежние правила сохранить |

Примеры определяют изменения расчёта; полные требования и границы ошибок находятся в дельтах. «Открыто» в согласованном порядке представлено именно возвратами ↩О. Порядок колонок не является предписанным маршрутом рабочего процесса.

## Область изменения

### Входит

- Дополненный каталог, сохранение исходных названий, динамические колонки в согласованном порядке.
- Собственные статусные длительности корней и видимых по правилам иерархии эпиков и задач.
- Пересчёт TTM с исключением Отложено; отдельный показатель без фактического флага.
- Ограниченное правило отбора HOTELS без префикса; прежние проверки типа, отклонения и профиля доски.
- Отображение и объяснение расчётов; одинаковые правила для доказанных точных историй Jira и XLSX.
- Восстановление производных чисел из прежних сохранённых входов без фоновой сети.

### Не входит

- Изменение Jira, её рабочих процессов, полей, флагов или исторических переходов.
- Восстановление отсутствующей истории по договорённости о флаге или по агрегатам файла.
- Новые пороги длительности; новые этапы брешей; изменение календарей, связей, спринтов или состава подзадач.
- Числовые TTM, TTM без флага и impediment дочерних объектов; включение дочерних строк в статистику исходных эпиков.
- Автоматическое исправление исходного TTM Excel; новый формат экспорта; выгрузка Jira в XLSX.
- Удаление старых статусов, отдельная числовая колонка первоначального Открыто.
- Изменения harness, skills, MCP или разрешений; commit и push.

## Участники и авторизация

Канонический владелец — этот Git-репозиторий. Пользователь утверждает поведение, пакет и начало реализации; агент готовит и проверяет документы. Jira и файлы остаются источниками фактов. Одобрение отдельных правил расчёта не отменяет запрет реализации из первоначального запроса.

## Закрытие вопросов и границы предложений

Q1 закрыт чтением одного предоставленного эпика и текущего каталога; обе ссылки одинаковы. Q2a закрыт ответом «15»: Отложено вычитается и после старта. Q2b закрыт ответом «TTM 15, без флага 5» и примером учёта проверки идей. Q3a закрыт ответом «Да»: Подготовка после Открыто. Q4–Q6 закрыты: встречающиеся колонки, все обсуждённые представления и дочерние длительности, без новых норм и брешей. Q7 отдельно подтверждён: три отельных статуса допускаются к отбору. Q8 закрыт: нужны возвраты, не числовое первоначальное ожидание.

Содержательных блокирующих вопросов пользователя не осталось. Технические риски разобраны в предложенном [дизайне](design.md): независимые признаки каталога и TTM, пересечение временных интервалов, совместимость входов и стабильная раскладка. Это технические предложения на согласование, не уже принятые решения владельца.

Риски: ошибка двойного вычитания флага и Отложено; изменение прежних предположений о равенстве TTM календарному расстоянию; широкая таблица из статусов дочерних задач; несовпадение исходного TTM Excel с новой формулой; ранее не загруженные истории отельных кандидатов. Для каждого предусмотрены сценарии и проверки; старые непроверенные остатки других пакетов не объявляются закрытыми.

## Критерии успеха

- **SC-001**: прежние и новые фактические статусы показаны без переименования и пустых лишних колонок.
- **SC-002**: повторные входы дают сумму доказанных интервалов; Отложено видно как статус с числом, хотя исключено из TTM.
- **SC-003**: порядок колонок соответствует решению; календарные интервалы и возвращения сохраняют реальные даты.
- **SC-004**: примеры пользователя дают TTM 15 при 60 сутках Отложено и пару 15/5 при 10 сутках флага; пересечение флага и Отложено не вычитается дважды.
- **SC-005**: неполнота статусов и флага независимо ограничивает только зависимые показатели; кэш открывается без сети с прежним срезом.
- **SC-006**: согласованные отельные состояния допускают HF-анализ, одноимённые статусы другого проекта не расширяют отбор.
- **SC-007**: Excel не получает вымышленных новых метрик из одних агрегатов; доступные исходные значения сохранены и названы как источник Excel.
