# Изменение визуализации: расширенная статусная модель

## Добавленные требования

### FR-043: Совместное отображение старых и новых статусов

Система ДОЛЖНА сохранять прежние восемь этапов и дополнять их статусами «Проверка идей», «Отложено», «Запланировано» и статусами Отелей «Решили делать», «Тестирование эпика», «Релиз». В одной истории новые статусы не ДОЛЖНЫ заменяться названиями прежней модели или объединяться с ними без отдельного решения пользователя.

Точные имена Jira, префиксы и идентификаторы подтверждены в [исследовании](../research.md). Отображение в заголовке без служебного префикса не переименовывает исходный статус в истории. Словоформа «Проверка идеи» из запроса означает проверенный статус «[HF] Проверка идей», а не отдельный дополнительный статус. Модель применяется к таблице, календарю, деталям, «Составу из Excel» и автономному XLSX. «Решили делать» получает собственную колонку при наличии в наборе.

#### AC-095: Смешанная модель

- **ДАНО** доказанная история содержит прежние этапы и добавленные статусы из согласованного каталога.
- **КОГДА** пользователь открывает согласованное представление.
- **ТОГДА** старые и новые статусы доступны под собственными названиями без переключения эпика на единственную версию процесса.

#### AC-096: Прежняя история

- **ДАНО** контрольный эпик проходил только прежние этапы.
- **КОГДА** его история отображается после расширения модели.
- **ТОГДА** прежние названия и длительности сохранены; отсутствующие в наборе статусные колонки скрыты по FR-046.

### FR-044: Длительность каждого добавленного статуса

Для исходного анализируемого эпика система ДОЛЖНА показывать отдельную числовую длительность каждого добавленного статуса при доказанных исходных данных. Повторные входы ДОЛЖНЫ суммироваться в колонке; неизвестность не ДОЛЖНА подменяться нулём; точные даты не ДОЛЖНЫ восстанавливаться по одним агрегатам. Учёт длительности статуса и включение времени в TTM — разные правила: исключение времени из TTM не разрешает скрыть сам статус и его доказанную длительность.

Длительности определяются по всей доказанной истории до окончательного закрытия или среза, включая Отложено до начала TTM. Первоначальное Открыто не получает отдельной числовой колонки; возвраты показываются по FR-011. Длительности вложенных объектов предусмотрены FR-030, расчёты TTM — FR-010 и FR-047.

#### AC-097: Повторный вход

- **ДАНО** полная история эпика внутри доказанного TTM содержит два интервала «Тестирование эпика» длительностью 2 и 3 суток.
- **КОГДА** пользователь смотрит колонку «Тестирование эпика».
- **ТОГДА** она показывает 5 суток; интервалы не превращаются в один вымышленный непрерывный переход.

#### AC-098: Неполная история

- **ДАНО** история не доказывает полную длительность добавленного статуса.
- **КОГДА** пользователь смотрит его числовую ячейку.
- **ТОГДА** система обозначает неизвестность и её причину, а не точный ноль или предполагаемую длительность.

### FR-045: Порядок колонок для сопоставления истории

Система ДОЛЖНА использовать относительный порядок: ↩О → Подготовка → Проверка идей → Валидация → Решили делать → Отложено → Скоринг → Запланировано → Проработка решения → Готово к реализации → Реализация → Тестирование эпика → Релиз → Эксперимент → Оценка результата. Добавление колонок не ДОЛЖНО переставлять реальные переходы в календарной истории.

Открыто представлено только возвратами ↩О; первоначальное ожидание отдельным числом не показывается. Отображение порядка колонок не означает правильный маршрут процесса или обязательное прохождение всех состояний. При отсутствии статуса в наборе колонка пропускается, а относительный порядок остальных сохраняется.

#### AC-099: Колонки Отелей

- **ДАНО** эпик Отелей имеет доказанные интервалы разработки, тестирования, релиза и эксперимента.
- **КОГДА** показаны соответствующие колонки.
- **ТОГДА** их относительный порядок — Реализация → Тестирование эпика → Релиз → Эксперимент.

#### AC-100: Возврат в Discovery

- **ДАНО** история содержит переход из разработки обратно в один из согласованных статусов Discovery.
- **КОГДА** пользователь смотрит колонки и календарь.
- **ТОГДА** колонка Discovery остаётся до проработки решения, а календарный возврат расположен в фактической точке времени.

### FR-046: Колонки по фактически представленным статусам

Система ДОЛЖНА показывать только статусные колонки, встречающиеся в загруженном наборе. Правило применяется к прежним и добавленным статусам, сохраняя возможность показать каждый из них при появлении. Оно не скрывает служебные колонки или TTM. Отсутствие статуса во всём наборе отличается от отсутствия этого статуса у отдельного эпика смешанного набора.

Предложенные критерии присутствия: фактический интервал, включая нулевой, или прочитанное состояние в доступной истории; для агрегатов без истории — хотя бы одно положительное значение. Сам заголовок экспортного шаблона и автоматически заполненные нули не доказывают присутствие. Неполнота истории не скрывает обнаруженное имя, но не разрешает точное число. Состав определяется по всему набору, включая допустимые дочерние объекты; фильтрация, сортировка и сворачивание его не меняют. Отклонённые, недостижимые и аналитические подзадачи не добавляют колонок. ↩О появляется только при обнаруженном возврате, а не первоначальном Открыто. Произвольные статусы дочерних задач и дополнительные агрегаты идут после каталога устойчиво, не переименовываясь в HF-этапы. Эти уточнения являются частью предложенного дизайна.

#### AC-101: В наборе нет отельных этапов

- **ДАНО** набор содержит только доказанные истории прежней модели без «Тестирование эпика» и «Релиз».
- **КОГДА** пользователь открывает таблицу.
- **ТОГДА** колонок этих двух статусов нет.

#### AC-102: Смешанный набор проектов

- **ДАНО** один эпик проходил «Тестирование эпика», другой имеет полную историю без этого статуса.
- **КОГДА** показан общий набор.
- **ТОГДА** колонка присутствует; у первого показана доказанная длительность, у второго — доказанное отсутствие времени в статусе, не скрытие всей колонки. Неполная история второго не даёт ложного нуля.

#### AC-114: Устойчивый состав и нулевые переходы

- **ДАНО** статус есть только у допустимой свёрнутой дочерней строки, другой встречается в переходе нулевой длительности; экспорт также содержит пустые шаблонные колонки.
- **КОГДА** пользователь фильтрует, сортирует, раскрывает или сворачивает строки.
- **ТОГДА** первые две колонки остаются в общем составе, шаблонные колонки без фактов отсутствуют; неизвестная длительность отличается от доказанного нуля.

### FR-048: Два показателя TTM и возвраты

Таблица и детали исходных эпиков ДОЛЖНЫ показывать основной TTM и отдельный «TTM без флага» рядом, с объяснением правил и качества. Новый показатель вычисляется только из доказанной истории статусов и флага. В режиме исходных агрегатов Excel этот показатель недоступен: файл не содержит необходимых точных входов внутри агрегатного источника. Нельзя вычитать общий impediment из исходного TTM файла или подмешивать исторический расчёт в источник «Excel»; доказанный исторический показатель доступен при выборе «История».

Новая метрика ДОЛЖНА поддерживать сортировку с неизвестными значениями в конце. Сводные медиана и максимум, начальная сортировка продолжают относиться к основному TTM корней. Числовое Открыто ДОЛЖНО показывать только возвраты ↩О, без отдельного общего/первоначального ожидания. Названия и подсказки ДОЛЖНЫ отличать исключённое время, время под флагом и календарную длительность; «без флага» не означает трудозатраты.

#### AC-115: Сравнение показателей

- **ДАНО** первый эпик имеет доказанные TTM 15 и TTM без флага 5, у второго известен TTM, но не история флага.
- **КОГДА** пользователь смотрит таблицу, сортирует по новому показателю и открывает детали.
- **ТОГДА** у первого видна пара 15/5; у второго новый показатель — прочерк с причиной и он идёт последним при обоих направлениях; сводка использует основной TTM. Исходный TTM файла не подгоняется под новые числа.

## Изменённые требования

### FR-015: Таблица и фильтры

Система ДОЛЖНА показывать ключ, название, качество и метрики эпика; предоставлять поиск по ключу или названию, фильтр исполнителя и сортировку. Отсутствующее значение ДОЛЖНО оставаться неизвестным, а не нулём.

Поиск выполняется без учёта регистра, исполнитель выбирается по точному отображаемому значению. По умолчанию применяется сортировка по убыванию TTM; неизвестные числа идут последними в обоих направлениях, равные значения упорядочиваются по ключу. Медиана и максимум TTM считаются по известным значениям отфильтрованных строк в выбранном источнике метрик. Состав статусных колонок определяется FR-045/046. Два показателя TTM отображаются по FR-048. Календарный диапазон и шкала состава рассчитываются по всему набору и не сдвигаются при фильтрации.

#### AC-010: Пропущенная метрика

- **ДАНО** у эпика нет подтверждённой длительности.
- **КОГДА** пользователь открывает таблицу.
- **ТОГДА** ячейка показывает прочерк, а подробности содержат предупреждение.

### FR-016: Календарь истории

Система ДОЛЖНА показывать последовательные интервалы по общей временной оси в масштабах день, неделя и месяц. Начальное Открыто и предрабочие состояния ДОЛЖНЫ быть визуально отделены от TTM; узкие интервалы ДОЛЖНЫ получать выносную подпись без изменения их ширины.

Отложено внутри начавшегося TTM ДОЛЖНО иметь обозначение «Не входит в TTM», сохраняя реальные даты и собственный цвет статуса. Оно не называется предрабочим, если началось после старта. Числовой TTM может быть меньше календарного расстояния; ширина истории не подгоняется под число.

Начальный масштаб — неделя; день/неделя/месяц соответствуют 26/8/3 пикселям на сутки, а не округлению длительностей. Для Jira-набора начальный источник метрик всегда «История», даже при неизвестном TTM. Автономный набор без числового TTM, начального Открыто и пригодной истории связанных элементов по умолчанию открывает «Состав из Excel» ([выбор источника](../../../../../../../shared/contracts.ts)).

### FR-017: Состав агрегатов

При доступных агрегатах Excel система МОЖЕТ показывать отдельный состав длительностей этапов на общей абсолютной шкале с отметкой исходного TTM. Порядок известных блоков соответствует FR-045; дополнительные нераспознанные колонки сохраняют относительный порядок файла после известных и не ДОЛЖЕН выдаваться за хронологию. «Открыто» ДОЛЖНО быть исключено из состава, поскольку агрегат не разделяет ожидание и возвраты; TTM остаётся без пересчёта; TTM без флага не выводится из суммы агрегатов и не включается в состав как этап.

Название «Состав из Excel» используется также для контрольных агрегатов CSV. Неизвестные дополнительные агрегатные этапы показываются нейтрально; отсутствующие значения не равны нулю. Файловые агрегаты не пересчитываются при refresh Jira. Разница TTM и суммы известных этапов не доказывает ни порядок переходов, ни причину расхождения.

#### AC-011: Сравнение агрегатов

- **ДАНО** сумма известных этапов отличается от TTM.
- **КОГДА** пользователь открывает детали.
- **ТОГДА** показаны оба исходных числа и разница без подгонки.

### FR-018: Цветовая оценка длительностей

Цветовая оценка ДОЛЖНА использовать сохранённые пороги этапов и TTM. Новые статусы и TTM без флага не получают нормативных порогов. Для возврата в Открыто порог не применяется; неизвестный этап показывается нейтрально.

Точная таблица порогов — [HEAT_BANDS](../../../../../../../shared/heatmap.ts), она также показана в «Правилах расчёта». Нижняя граница включается. TTM: жёлтый до 60 дней, оранжевый от 60, красный от 100, бордовый от 200. Скоринг не окрашивается до 30 дней включительно, выше — оранжевый. Реализация меньше одного дня бордовая: это фактическое правило, а не ошибка описания. Цвет статуса на календаре и heatmap длительности — разные обозначения.

### FR-019: Детали и правила

Система ДОЛЖНА показывать исходные переходы, интервалы, impediment, момент среза, качество и предупреждения, а также доступные пользователю правила расчёта и аудит отбора.

Правила ДОЛЖНЫ объяснять вычитание Отложено, самостоятельный TTM без фактического флага, сохранение общего impediment и отсутствие двойного вычитания. Детали показывают исходные даты, исключённое Отложено, пересечение флага с учитываемым временем и причины неизвестности.

Модальные окна закрываются Escape и кликом по фону, удерживают клавиатурный фокус и возвращают его после закрытия. При успешном новом наборе сбрасываются поиск, исполнитель, выбор источника метрик, выбранный эпик и сортировка; масштаб календаря сохраняется.

#### AC-012: Частичная история

- **ДАНО** история эпика помечена частичной.
- **КОГДА** пользователь открывает его детали.
- **ТОГДА** интерфейс явно показывает качество и причину, не создавая впечатления точного TTM.

### FR-030: Раскрытие связанных элементов


В календарном режиме система ДОЛЖНА показывать у исходных и вложенных эпиков отдельную стрелку раскрытия. Изначально ветки свёрнуты; нажатие показывает непосредственных видимых детей, повторное нажатие скрывает всё поддерево. Название исходного эпика продолжает открывать его детали. Задачи не раскрываются в подзадачи.

Дочерняя строка ДОЛЖНА показывать ключ, название и собственную историю по FR-032 на общей временной оси, с отступом уровня. Дочерняя строка ДОЛЖНА показывать собственные числовые длительности статусов при доказанной истории; её время не суммируется с родителем. Числовые ячейки TTM, TTM без флага и impediment для дочерней строки остаются вне изменения. Названия и даты статусов доступны на полоске и в подсказке. Статистика исходных эпиков не включает дочерние строки; исходные расчёты меняются только по отдельным требованиям этого пакета.

Связанные элементы показываются независимо от HF/DF, но с отклоняющей резолюцией («Отклонено», нормализованные варианты либо «Не будет выполняться») исключаются. Один элемент ДОЛЖЕН быть видим под каждым родителем, а если он сам выбран исходным эпиком — также в исходной строке. Повтор одного элемента в текущей цепочке ДОЛЖЕН останавливать цикл с предупреждением. Подзадачи не показываются отдельными строками и не раскрываются в интерфейсе; их состав и истории читаются для анализа работы по FR-036. Это аналитическое чтение не включает подзадачи в видимый граф, исходную выборку, статистику или границы календаря как самостоятельные элементы.

Если отклонённый промежуточный эпик скрыт, неотклонённые потомки ДОЛЖНЫ оставаться достижимыми через ближайшего видимого предка с пояснением о пропущенном промежуточном элементе. Пользователь подтвердил это правило при разборе повторной проверки пакета.

Подтверждённое отсутствие детей ДОЛЖНО отличаться от неизвестного состава ветки и от старого набора без сведений о связях. Недоступная или недоказанная статусная история оставляет строку и предупреждение, не выдуманную точную полосу статусов. Это ограничение не скрывает независимо подтверждённые сегменты спринтов по FR-035/FR-039: их даты и работа могут быть известны по дочерним задачам даже при неизвестных этапах самого эпика. Календарный диапазон ДОЛЖЕН учитывать исходные строки и доказанные интервалы допустимых дочерних элементов набора, включая скрытые сворачиванием или фильтром корней, и оставаться стабильным при раскрытии, фильтрации и сортировке. Отклонённые элементы, подзадачи, недостижимые элементы и диагностические строки без доказанных интервалов не расширяют ось; допустимые потомки скрытого отклонённого эпика учитываются. Поиск, исполнитель и сортировка применяются к исходным эпикам; дочерние строки следуют за видимым родителем.

При недостаточном бюджете или локальном отказе аналитических подзадач прежние видимые узлы, связи, полосы и полнота основного графа ДОЛЖНЫ сохраняться. Причина ограничения анализа спринтов показывается отдельно. Сегменты спринтов ДОЛЖНЫ отображаться в полосках исходного эпика, раскрытых Delivery-эпиков и задач по FR-035. История статусов каждой строки остаётся читаемой; сегменты эпика отражают только его допустимые нижние задачи и не зависят от раскрытия. Критерий бреши определяется FR-038/039: отметка непосредственно под цветной полосой выбранного этапа, вплотную к её нижнему краю, означает только доказанное отсутствие включённых задач. Недостаточность данных и предварительное отсутствие работы на этой полосе не отображаются; состояния отдельных сегментов спринтов сохраняются.

#### AC-029: Раскрытие по уровням

- **ДАНО** эпик A содержит эпик B, B содержит задачу C, у C есть подзадача D.
- **КОГДА** пользователь открывает набор, затем раскрывает A, затем B.
- **ТОГДА** сначала виден A; после первого нажатия — A и B; после второго — также C; D отсутствует, у B и C видны собственные доказанные длительности статусов; числовые TTM и impediment не добавляются.

#### AC-030: Сворачивание

- **ДАНО** раскрыты A и B.
- **КОГДА** пользователь сворачивает A.
- **ТОГДА** B и C скрыты; исходные полосы, метрики и календарная ось сохранены.

#### AC-031: Недоступная история

- **ДАНО** история C недоступна, а история соседней задачи доступна.
- **КОГДА** пользователь раскрывает их родителя.
- **ТОГДА** C видна с предупреждением без точной полосы; соседняя полоса остаётся видна.

#### AC-032: Общая календарная ось

- **ДАНО** история C начинается раньше родителя и заканчивается позже него.
- **КОГДА** пользователь раскрывает ветку, меняет масштаб и сворачивает её.
- **ТОГДА** вся история помещается на общей оси; даты и длительности не меняются, сворачивание не сдвигает диапазон.

Дополнительный вариант AC-032: у отклонённого эпика, подзадачи и недостижимого элемента даты далеко за пределами допустимых строк; эти даты не расширяют ось. Допустимый потомок отклонённого эпика с более ранним началом расширяет её независимо от сворачивания.

#### AC-035: Общий элемент

- **ДАНО** A и B содержат C, а B также выбран исходным эпиком.
- **КОГДА** обе ветки раскрыты.
- **ТОГДА** C видна под A и B, B сохраняет исходную строку; раскрытие одной ветки не меняет другую, статистика считает только исходные эпики.

#### AC-036: DF и отклонённые

- **ДАНО** у A есть связанный DF-эпик, обычная задача и отклонённый эпик с неотклонённым потомком.
- **КОГДА** A раскрыт.
- **ТОГДА** DF и обычная задача видны, отклонённой строки нет; потомок виден с пояснением о промежуточном исключении.

#### AC-037: Пустая ветка и цикл

- **ДАНО** A не имеет детей, состав B неизвестен, а C содержит D и D содержит C.
- **КОГДА** пользователь исследует эти ветки.
- **ТОГДА** у A показано подтверждённое отсутствие детей, у B предупреждение о неизвестном составе; ветка C конечна и отмечает цикл.

#### AC-105: Собственная длительность вложенного объекта

- **ДАНО** у родительского эпика 10 суток в реализации, у вложенного эпика 4 суток, у его задачи 2 суток в собственном фактическом статусе.
- **КОГДА** пользователь раскрывает обе ветки.
- **ТОГДА** каждая строка показывает свою доказанную длительность; родительское число не заменяется суммой детей, число исходных эпиков и их сводная статистика не увеличиваются. Статус обычной задачи не переименовывается в HF-этап.

#### AC-106: Неизвестная дочерняя длительность

- **ДАНО** история одного дочернего элемента недоступна, история соседнего полна.
- **КОГДА** пользователь раскрывает родителя.
- **ТОГДА** у первого нет вымышленных точных длительностей, у второго показаны собственные доказанные значения; раскрытие не загружает новые данные само по себе.


#### AC-120: Возврат дочерней задачи

- **ДАНО** доказанная собственная история задачи содержит 20 суток первоначального Открыто → 2 суток другого статуса → 3 суток Открыто → 1 сутки другого статуса.
- **КОГДА** пользователь раскрывает её строку.
- **ТОГДА** ↩О показывает 3 суток, первоначальные 20 не добавляются; метрика TTM задачи не создаётся. Для задачи возврат определяется уходом из первоначального Открыто и последующим повторным входом, а не началом родительского TTM.
