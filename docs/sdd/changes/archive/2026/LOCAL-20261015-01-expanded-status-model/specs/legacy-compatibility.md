# Расширенная модель в автономном XLSX

## Добавленные требования

Нет.

## Изменённые требования

### FR-025: Предоставленная история

Для календаря книга ДОЛЖНА содержать непрерывные интервалы листа «История» и явный `asOf` листа «Параметры». Пробелы, пересечения, неоднозначное начало либо отсутствие среза не ДОЛЖНЫ компенсироваться агрегатами. Даты без пояса интерпретируются в Москве; текстовая дата без времени не доказывает точный переход.

Лист «Impediment» ДОЛЖЕН задавать полноту флагов: его отсутствие означает неизвестность, наличие с одними заголовками — отсутствие флагов у всей выборки. К доказанной точной истории применяются FR-010/011/013/044/047 независимо от источника, включая контекст проекта HOTELS по ключу. Файловый отбор по FR-024 не расширяется отельным исключением Jira. Исходные агрегаты остаются отдельным источником по FR-017; они не исправляются под новую формулу и не доказывают флаг. Расчёт ДОЛЖЕН сохранять срез при повторном открытии; история старого набора не подмешивается в новую книгу.

#### AC-017: Отсутствующий и пустой лист флагов

- **ДАНО** пригодная начавшаяся история TTM и явный срез.
- **КОГДА** лист флагов отсутствует либо присутствует только с заголовками.
- **ТОГДА** в первом случае impediment и TTM без флага неизвестны; во втором impediment равен нулю, TTM без флага равен основному TTM, если структура листа корректна.

#### AC-116: Одинаковые доказанные входы

- **ДАНО** эквивалентные полные истории Jira и XLSX, один срез и одинаковая история флага.
- **КОГДА** каждая обрабатывается своим разрешённым источником.
- **ТОГДА** TTM, TTM без флага, возвраты и длительности статусов совпадают, включая примеры 15 и 15/5; XLSX не обращается к Jira или Keychain.

#### AC-117: Только агрегаты

- **ДАНО** файл содержит исходный TTM 75 и Отложено 60, но не точную историю и не доказанные флаги.
- **КОГДА** пользователь открывает «Состав из Excel».
- **ТОГДА** исходный TTM остаётся 75, Отложено видно отдельным блоком/числом; TTM 15 и TTM без флага не выводятся по предположению, календарь не создаётся.

### FR-033: Автономное раскрытие по данным книги

Пользователь ДОЛЖЕН иметь возможность загрузить автономную XLSX-книгу через форму файла. В этом режиме система ДОЛЖНА брать связи, метаданные и точную историю связанных элементов из самой книги и показывать их собственные полосы и длительности по FR-030 и FR-032 без запросов Jira и Keychain.

История ДОЛЖНА иметь явный общий срез. Данные дочерних элементов не требуют включения их в исходный HF-лист; тип, признак подзадачи и резолюция должны быть определимы по книге. Агрегатные длительности и одни ключи не доказывают связи или календарные интервалы. Обычный режим загрузки ключей CSV/XLSX с чтением Jira сохраняется как отдельный явно выбранный режим.

Старая книга без дополнения ДОЛЖНА открываться по прежним правилам с сообщением «Данные о связях не загружены»; отсутствие листа связей не тождественно пустому списку детей. Ошибка отдельной дочерней истории оставляет другие доказанные данные; неоднозначный общий срез или противоречивые идентификаторы структуры не должны молча объединяться.

#### AC-044: Полный автономный путь

- **ДАНО** книга с исходным HF-эпиком, связями, DF-эпиком, задачой, подзадачей и точными историями.
- **КОГДА** пользователь выбирает автономный режим и загружает книгу при отключённой сети.
- **ТОГДА** исходная строка и раскрытие работают; DF и задача видны, подзадача исключена, обращения к Jira и Keychain отсутствуют.

#### AC-045: Старая книга и дефект истории

- **ДАНО** старая книга без связей и новая книга с разрывом истории одной дочерней задачи.
- **КОГДА** каждая загружается отдельно.
- **ТОГДА** первая сохраняет исходные агрегаты и применяет новую модель только к доказанной истории с сообщением об отсутствии загруженных связей; во второй пригодные дочерние полоски видны, проблемная строка содержит предупреждение.

## Удалённые требования

Нет.
