# Смешанная история и сохранение анализа брешей

## Добавленные требования

Нет.

## Изменённые требования

### FR-041: Смешанная история без подмены TTM

Система ДОЛЖНА сохранять собственные названия «Проверка идей», «Валидация», «Отложено», «Запланировано» и других фактически прочитанных статусов. Их присутствие у одного эпика не ДОЛЖНО требовать выбора единственной версии процесса и не разрешает переименовывать новый статус в старый.

ЕСЛИ полная история доказывает даты выбранного для анализа этапа, но расчёт не может определить TTM из-за статуса вне расширенной модели, система ДОЛЖНА обеспечивать показ подтверждённого календарного интервала и оценки спринтов на полосе эпика, сохраняя неизвестность числового TTM и её объяснение. Полная история статусов и вычислимость метрики оцениваются отдельно. При недоказанной истории точный интервал не выдумывается.

Известные этапы на этой полосе ДОЛЖНЫ сохранять цвет и контраст текста из общей легенды независимо от вычислимости TTM. Статусы вне принятой палитры и промежуточное закрытие сохраняют нейтральную заливку со штриховкой; их названия не переименовываются. Подтверждённые бреши отмечаются под цветной полосой по FR-038; её заливка сохраняется.

#### AC-067: Новая и старая модель у одного эпика

- **ДАНО** полная история содержит «Проверка идей», затем «Отложено», «Валидация», «Запланировано», «Реализация» и «Оценка результата».
- **КОГДА** подтверждённые пустые спринты сопоставляются с историей.
- **ТОГДА** бреши показаны только на четырёх разрешённых названиях, без переименования; «Отложено» и «Запланировано» сохранены без отметок.

#### AC-068: Проверка идей распознаётся расширенной моделью

- **ДАНО** история от создания полна, «Проверка идей» стоит до остальных HF-этапов и позволяет доказать старт по FR-010.
- **КОГДА** строится новый анализ спринтов.
- **ТОГДА** даты «Проверки идей» и обоснованные отметки на ней видны, TTM рассчитывается по новой модели с исключением Отложено; неполная версия истории не получает точную полосу или вымышленный TTM.

#### AC-090: Цвета этапов при неизвестном TTM

- **ДАНО** доказанная история эпика начинается со статуса вне принятой модели, а затем содержит этапы расширенного каталога; TTM неизвестен.
- **КОГДА** пользователь открывает календарную полосу эпика.
- **ТОГДА** известные этапы имеют цвета общей легенды, остальные статусы и промежуточное закрытие — нейтральную штриховку; названия, даты, подтверждённые бреши и объяснение неизвестного TTM сохраняются.

Для Jira-набора с полной доказанной цепочкой система ДОЛЖНА показывать длительности распознанных этапов расширенного каталога даже при неизвестном начале TTM. Длительность этапа равна сумме его интервалов до среза, включая повторные входы; неизвестные названия не переименовываются в известные этапы. Для отсутствующего известного этапа в такой истории показывается ноль, если его колонка присутствует по другим объектам набора; пустые для всего набора колонки скрыты по FR-046. TTM, TTM без флага, возврат в Открыто и impediment остаются неизвестными, если их границы не доказаны. Неполная, разорванная либо противоречивая история не даёт точных чисел этапов. Доказанная автономная история согласуется с FR-025; одни агрегаты не являются такой историей. Набор четырёх названий для брешей не расширяется: Проверка идей, Валидация, Реализация, Оценка результата.

#### AC-092: Длительности этапов при неизвестном начале TTM

- **ДАНО** полная Jira-история начинается с статуса вне расширенной модели, а затем содержит этапы расширенного каталога.
- **КОГДА** показана левая часть строки или набор восстановлен из кэша.
- **ТОГДА** известные этапы показывают сумму дней с учётом повторных входов и среза; отсутствующие этапы — ноль, TTM остаётся неизвестным с объяснением. Значения участвуют в сортировке; прежние пороги сохранены, новые статусы нейтральны по FR-018.
- **КОГДА** полнота начала не доказана, переходы разорваны, в том числе после среза, либо конечный статус противоречит цепочке.
- **ТОГДА** длительности остаются неизвестными.

## Удалённые требования

Нет.
