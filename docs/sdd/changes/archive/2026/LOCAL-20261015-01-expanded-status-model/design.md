# Дизайн расширенной статусной модели

## Статус и основание

Дизайн для репозитория `.` согласован к реализации поручением пользователя 02.11.2026. Пользовательские правила зафиксированы в [предложении](proposal.md), проверенные наблюдения — в [исследовании](research.md). Новых библиотек, сервисов, полномочий или записей в Jira не требуется. Проверка текущего кода подтверждает реализуемость в существующих адаптерах и расчётном ядре; она не является проверкой будущей реализации.

## Исходное устройство до реализации

`shared/statuses.ts` одновременно задаёт восемь колонок и через `isActive` определяет старт TTM. Простое добавление Отложено в этот список ошибочно начнёт отсчёт. `server/timeline.ts` приравнивает TTM разности конца и начала, но отдельно проверяет непрерывность интервалов. `server/jira/normalize.ts` разрешает Решили делать до TTM для всех проектов. `shared/metrics.ts` всегда выводит полный каталог в истории и порядок исходных колонок для Excel. Дочерние полосы уже содержат свои точные интервалы, но не числовые ячейки. Кэш сохраняет входы и позволяет пересчитать результат без сети.

## Каталог, контекст и длительности

Расширить каталог до четырнадцати именованных статусов. Сохранить идентификаторы, имена и календарные цвета прежних восьми; для новых применены идентификаторы `idea-check`, `decided`, `deferred`, `planned`, `epic-testing`, `release`. Названия отображения берутся из подтверждённого каталога. Новые календарные цвета подобрать с читаемым текстом; они обозначают статус, а не нормативную длительность.

Отделить три операции: распознать статус, суммировать собственную длительность, определить начало/исключение TTM. Политика TTM получает проект из ключа исходного эпика; это возможно и для сохранённых Jira-входов, и для автономной книги. Для HOTELS `decided` начинает TTM; для остальных сохраняется прежнее разрешённое предрабочее состояние. `deferred` не начинает TTM и исключается всегда. Начальные Open и разрешённые предрабочие периоды не считаются доказательством старта. Положительный неизвестный период перед первым известным стартом по-прежнему оставляет TTM неизвестным.

Для полных историй суммировать длительности распознанных статусов по их собственным интервалам до последнего окончательного закрытия или среза, включая предрабочее Отложено. Неполная цепочка не даёт точных чисел. Полная цепочка с неизвестным началом TTM может независимо доказывать длительности статусов. Все известные нули — результат доказанного отсутствия времени, а не замена отсутствующих данных.

Собственные длительности дочерних задач вычисляются чистой проекцией `shared/metrics.ts` из доказанных интервалов `related-timeline`; отдельный словарь в сохраняемом результате не дублируется. Это использует существующего владельца истории и сохраняет весь согласованный результат. Произвольные имена сохраняются. Нормализация пробелов/регистра не снимает `[DF]` и не объединяет DF с HF; совпадение этапов определяется лишь разрешёнными алиасами. Для задачи возврат в Открыто означает повторный вход после выхода из первоначального Open; он не привязан к TTM родителя. Один общий ребёнок может отображаться под несколькими родителями, но его длительность не удваивается внутри строки и не влияет на корневую статистику.

## Формула и неизменность календаря

Все интервалы полуоткрытые `[start,end)`, в миллисекундах. Сначала доказать непрерывность истории и её границы прежними проверками. Затем определить календарное окно W от старта до окончательного закрытия/asOf, объединение D интервалов Отложено и объединение F фактического флага. Для подсчёта использовать пересечения с W, используя уже проверенные непересекающиеся разбиения статусов и флага; пересечения исключений учитываются один раз. Не менять исходные переходы и не округлять до суток перед операциями.

- Учитываемое время E = W без D.
- `ttmMs = длительность(E)`.
- `ttmFlaggedMs = длительность(E ∩ F)`.
- `ttmWithoutFlagMs = длительность(E) − длительность(E ∩ F)`.
- Прежний `impedimentMs = длительность(W ∩ F)` сохраняется отдельно.

Таким образом 75 календарных суток с 60 сутками Отложено дают TTM 15. Если общий флаг 64 суток включает те же 60 Отложено и 4 учитываемых суток, новый показатель равен 11, а не отрицательному числу. Десять суток планирования с флагом и пять проработки без него дают 15/5. Если фактический флаг не поставлен, договорённость о статусе не создаёт F.

Добавлены производные поля `excludedDeferredMs`, `ttmFlaggedMs`, `ttmWithoutFlagMs` и причины недоступности. Они не являются новыми сырыми входами. При неизвестном TTM все зависимые показатели неизвестны. При доказанном TTM и неизвестном флаге только флагозависимые показатели неизвестны; доказанное отсутствие флага даёт ноль и равенство двух TTM. При работе, начавшейся точно на срезе, оба значения равны нулю только при доказанном флаге. Отложено без старта сохраняет состояние «TTM ещё не начат».

Инварианты: `0 ≤ TTM без флага ≤ TTM ≤ длительность(W)`; `TTM + excludedDeferredMs = длительность(W)`; сумма непрерывных календарных интервалов равна W, а не TTM. Статусные длительности могут включать предрабочие периоды и не обязаны суммироваться в TTM. Промежуточное закрытие и возврат в Открыто после старта включаются как прежде; последнее закрытие определяет конец. Открытое Отложено замораживает число TTM, но не делает эпик завершённым.

## Колонки и интерфейс

Служебные поля, TTM и «TTM без флага» идут перед статусами. Далее согласованный порядок из FR-045, с пропуском отсутствующих статусов. Первоначальное Открыто остаётся в календарной истории без отдельного числа; ↩О отражает только возвраты. Явный возврат с неполной длительностью позволяет показать колонку с прочерком; одно первоначальное Open её не создаёт.

Определять набор колонок один раз по полному текущему набору для выбранного источника метрик. Для истории учитывать прочитанные состояния/интервалы корней и допустимых достижимых детей, в том числе нулевые. Для одних агрегатов положительное значение служит свидетельством; шаблонный ноль без истории не создаёт колонку. Дополнительные дочерние имена идут после каталога в устойчивом порядке по нормализованному имени, сохраняя префиксы; неизвестные агрегаты — в относительном порядке файла. Фильтр, сортировка, сворачивание, прокрутка и постраничное раскрытие не меняют набор колонок. Смена набора или источника может менять его; сортировка по исчезнувшей колонке возвращается к основному TTM.

В истории `metricValue` читает новые производные показатели. В режиме исходных агрегатов не смешивать их с историческими: TTM берётся из файла, новый показатель недоступен с объяснением источника. В составе исключить оба TTM и общий Open из блоков этапов; известные блоки переставить в согласованный порядок без обещания хронологии. Суммы агрегатов и отметка исходного TTM остаются прежними. Дочерние строки в календаре имеют выровненные ячейки собственных статусов, а в колонках корневых метрик — прочерки с понятным отсутствием такой метрики.

`displayIntervals` получает отдельную роль исключённого из TTM Отложено внутри W. До старта оно остаётся предрабочим; подпись и подсказка отличают эти случаи. Сохранить полную ширину календаря, фактические даты, масштабы 26/8/3 пикселя на сутки, раскрытие и общую ось. Новые метрики не меняют медиану/максимум основного TTM и число корней. Нормативная заливка новых статусов, нового показателя и дополнительных статусов — нейтральная; прежние `HEAT_BANDS` не меняются. Неполноту показывать независимо по статусам и флагу.

В деталях и «Правилах расчёта» объяснить основной TTM, исключённое Отложено, фактическое пересечение флага и новый показатель. Не добавлять отдельный режим пересчёта, автоматическое изменение флагов, новые фильтры или выгрузку. Сохранить Escape, фокус, закрытие по фону и сбросы при загрузке набора.

## Ограниченный отбор HOTELS

В адаптере метаданных после проверки типа и исключения отклонённых/DF разрешить три статуса только для проекта из текущего ключа `HOTELS-*`. Проверенные пары: Решили делать/21467, Тестирование эпика/22135, Релиз/20871. Если ID доступен, проверять пару ID/имя; для формата без ID использовать точное нормализованное имя и проект. Любое другое имя не становится HF автоматически; неоднозначный префикс не обходится исключением. В аудит добавить основание «Разрешённый статус эпика HOTELS без [HF]».

Правило действует при новом Jira-импорте и обычном refresh во всех существующих входах (ключи, файл кандидатов, разрешённая доска). Проверка профиля доски, ограничения типов и блокировка неразрешённых кандидатов сохраняются. Новых запросов или изменения профиля автоматически не требуется. Исторические статусы поддерживаются и после исчезновения из текущего каталога; фактические имена не заменяются текущим именем статуса.

## Файлы, кэш и сбои

Автономный путь использует тот же расчёт на доказанной истории, явном срезе и контексте проекта. Сохраняется файловый HF-отбор. Отсутствие Impediment означает неизвестный флаг, лист с одними корректными заголовками — доказанное отсутствие флага. Непрерывная история с неизвестным статусом может доказать отдельные длительности без вычислимого TTM. Одни агрегаты не доказывают даты, возвраты, флаг или новый TTM.

Формат сырых входов v3 не требует расширения: проект выводится из сохранённого ключа, интервалы/флаги уже есть. Новые значения строятся при загрузке, а не мигрируют из прежних производных чисел. Проверить схемы выходного результата и клиентские типы. Прежний v2 сохраняет существующую миграцию с backup; неизвестный/повреждённый кэш остаётся на диске. `id`, `savedAt`, `asOf` и сырые входы не меняются при обычном чтении. Отбор старого снимка сохраняется: без истории ранее исключённый кандидат появляется только после явного refresh, который уже разрешает перечитать кандидатов. Публикация и отказ записи сохраняют прежнюю атомарность.

| Ситуация | Результат |
| --- | --- |
| Полная история, только Open/Отложено до старта | История и длительность Отложено видны, числового TTM нет |
| Статусы доказаны, флаг недоказан | Основной TTM/статусы известны, TTM без флага и impediment неизвестны |
| Разрыв/пересечение/противоречие статусов | Нет точных зависимых чисел; другие строки сохранены |
| Полная цепочка, неизвестное начало TTM | Собственные доказанные этапы видны; зависимые от старта показатели неизвестны |
| Устаревший набор/отказ записи/отмена до публикации | Прежние контракт и набор сохранены |
| Нет сети при восстановлении | Сохранённые входы и срез достаточны, никакого обогащения |
| Только агрегаты Excel | Исходные числа и состав, без выдуманной календарной шкалы |

## Спринты, ограничения и отклонённые варианты

Сохранить четыре этапа брешей: Проверка идей, Валидация, Реализация, Оценка результата. Новое распознавание Проверки идей устраняет прежнюю неизвестность TTM при полной цепочке; по-настоящему неизвестное начало оставляет её. Календарные сегменты, членство, пределы чтения и спринтовый фильтр открытой задачи не меняются. Не переносить норму длительности или оценку бреши на Отложено, Запланировано, Тестирование эпика или Релиз.

Отклонены: добавление статусов только в `STAGES` (ошибочный старт от Отложено), удаление исключённых интервалов из календаря (утрата истории), вычитание общего impediment (двойное вычитание), восстановление флага по названию статуса (неподтверждённые данные), глобальное разрешение статусов без [HF] (расширение отбора других проектов), изменение исходных агрегатов (потеря контроля источника).
