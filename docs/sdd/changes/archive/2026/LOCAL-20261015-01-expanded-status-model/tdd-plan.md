# План TDD

## Граница выполненного

Матрица ниже сохраняет запланированные проверки и причины падения на исходной версии. Фактические RED/GREEN и регрессия приведены в [протоколе](verification.md); исходная точка — 403 теста, итог — 450. G6/G7 использовали существующие адаптеры общего ядра и подтверждены контрактной регрессией, без отдельного фиктивного RED.

## Контрольные данные

Использовать синтетические UTC-отметки с целым числом суток (сутки = 86 400 000 мс), дополненные случаями с секундами и одинаковыми отметками. Для сравнений Jira/XLSX задавать один `asOf` и одинаковые известные флаги. Не обращаться к рабочей Jira и не переписывать пользовательский кэш модульными тестами. Использовать временные каталоги для восстановления и атомарных отказов.

Обезличенное [свидетельство HOTELS-12351](evidence/hotels-12351-statuses-20261102.json) пригодно для отдельного минимального replay статусов. Оно не доказывает полный конвейер импорта или отсутствие флага. Проверка начального Решили делать должна учитывать реальные 8 секунд, без округления. Release и новые статусы требуют явно синтетических фикстур: в этом образце их нет.

## Интеграция и регрессия

После групп выполнить `npm run check` (все тесты, TypeScript, сборка). Проверить доступность новых полей в API и сериализации, прямой список/файл/доску, автономный импорт и восстановление на временном кэше. Сохранить число прошедших тестов и команды, а не заранее заданное ожидаемое количество. Исходная контрольная точка: 403 теста в 55 файлах; это не требование к будущему числу.

DOM-проверки должны проверять значения, порядок, сообщения и доступность управления. Реальные размеры, прокрутку, контраст и взаимное положение полос подтверждает только визуальная часть [BDD](bdd-scenarios.md). При изменении общей модели повторить спринтовую регрессию; новые этапы брешей не добавлять.
