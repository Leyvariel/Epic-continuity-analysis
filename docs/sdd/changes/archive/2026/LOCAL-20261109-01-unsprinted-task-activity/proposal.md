# Работа без спринтов и сброс данных анализа

## Стадия и основание

Бизнес-правила согласованы в текущем диалоге; функциональные дельты и дизайн подготовлены перед реализацией. Последней поправкой 09.11.2026 пользователь ограничил учёт по активным статусам проектами, где действительно нет спринтов. Эта поправка заменяет прежнее предложение об универсальном режиме для любой задачи без спринтов. Пользователь подтвердил добавление найденных проектов в список; состав закреплён в FR-054. В этот же пакет пользователь добавил кнопку полного сброса данных для начала нового анализа. Текущая реализация ещё не изменена.

Канонический владелец — текущий репозиторий; требования — [дельта учёта работы](specs/sprint-continuity.md) и [дельта сброса данных](specs/dataset-lifecycle.md). Подготовлены [дизайн](design.md) и [задачи](tasks.md) для дальнейшей реализации; подготовлены полные сопряжённые дельты, сценарии и трассировка проверок. Вопросы о расчёте закрыты решениями Q1, Q2 и Q4. Технический дизайн и план проверок описаны отдельно; согласование правил не является свидетельством уже выполненной реализации.

## Проблема и результат

У HOTELS-13142 полные календари команд, но TEXT-1314 не состояла ни в одном спринте. Отсутствие календаря одной такой задачи сейчас делает неизвестным покрытие всего эпика и скрывает чёрную отметку. Новое правило использует фактические активные интервалы задачи из подтверждённого проекта без спринтов; остальное время такой задачи не даёт покрытия и не создаёт неизвестность только из-за отсутствия календаря.

Дополнительно пользователь должен иметь возможность очистить сохранённый анализ и вернуться к стартовому экрану без ручного удаления файлов. Очищения одной таблицы недостаточно: старый набор не должен восстановиться после перезапуска.

## Границы

Входят: подтверждение проекта без спринтов, проверка полной истории участия задачи до среза, точные активные интервалы без спринта, объединение с покрытием спринтов, отметки под выбранными этапами и числовая метрика времени без работы, объяснение источника покрытия. Пустое поле Sprint у задачи из спринтового или неклассифицированного проекта не включает альтернативный режим. Сохраняется правило подтверждения активности: текущие подзадачи, при доказанно пустом составе — сама задача. У задачи со спринтами подтверждённая работа по-прежнему покрывает целый спринт. Активность без спринта не расширяется на соседний или пересекающийся спринт.

Смешанная гипотеза сохраняет прежнюю область числовой оценки: известные спринты внутри циклов реализации, без Отложено. Точные активные интервалы задач без спринтов покрывают совпадающее время. Промежутки вне календарей по прежнему решению не добавляются к числу. Если все допустимые задачи при полном непустом составе удовлетворяют FR-054, числовая метрика охватывает весь цикл реализации без Отложено; из него вычитается объединение точной активности. Неполная история участия не считается доказанным отсутствием спринтов. Произвольное название статуса «Взято в спринт» не доказывает наличие Jira Sprint.

Сброс по FR-055 удаляет данные текущего анализа в приложении и локальном кэше, очищает поля и настройки отображения. Предлагается кнопка «Сбросить все данные» с подтверждением; при активном импорте или обновлении она недоступна. Подключение к Jira, исходные файлы пользователя и согласованные правила расчёта сохраняются.

Не входят: изменение формул TTM и содержания исходных связей, историй, Excel-чисел, обновление Jira, commit и push. Сохранённый набор не перезаписывается ради проверки. Новые искусственные спринты не создаются. Автономный XLSX без входов спринтов не приобретает доказательство отсутствия спринтов.

## Открытые вопросы

Открытых бизнес-вопросов не осталось. Граница полностью неспринтового расчёта и условие работы в спринте подтверждены пользователем.

## Принятые решения

- Q1 — закрыт 09.11.2026. Для полностью неспринтовой гипотезы оценивается весь цикл «Реализация → Эксперимент» с исключением Отложено; незавершённый — до среза, окончательно закрытый без эксперимента — до закрытия. Покрывают только точные активные интервалы. Правило смешанной гипотезы об исключении дней вне календарей сохраняется.
- Q4 — закрыт 09.11.2026. Пользователь подтвердил: «сохраняем это условие. Верно». Для покрытия целого спринта нужны одновременно включение и подтверждённая активность задачи или её подзадач. Одного включения недостаточно.


- Q2 — закрыт 09.11.2026. Пользователь: «Давай включим эти проекты в список проектов, работающих без спринтов». К исходному TEXT добавлены CONTENT, MLE и UX; канонический список — в [FR-054](specs/sprint-continuity.md#fr-054-подтверждённая-работа-в-проекте-без-спринтов). Источник классификации — явное решение пользователя. Наблюдения из Jira сохранены в [исследовании](research.md) и сами по себе не считаются доказательством для всех задач проекта. Остальные проекты автоматически не добавляются.

- Q3 — включено в объём 09.11.2026 по поручению пользователя: кнопка сброса всех данных анализа для начала с чистого листа. Сценарии и границы подготовлены в FR-055; это добавление в пакет, не выполненный сброс рабочего набора.

## Реализуемость и критерии успеха

Существующие входы содержат историю членства, её полноту, категории статусов и текущий состав подзадач, но не подтверждение режима всего проекта. Для проверки смешанного расчёта с согласованным списком можно использовать сохранённый набор. Потребуется отдельное точное покрытие; нельзя преобразовать его в положительный спринт, иначе один час снова покроет весь спринт. Предлагаемое хранение явного списка описано в дизайне; дополнительная проверка Jira для принятия этого решения не требуется. Подробности в [проверке исходников](research.md).

- **SC-001**: альтернативный режим применяется только к подтверждённым проектам без спринтов; пустое поле отдельной задачи не меняет режим проекта.
- **SC-002**: три активных дня без спринта покрывают ровно три дня; задача не блокирует остальные календари.
- **SC-003**: неизвестная история не превращается в доказанный простой; прежняя спринтовая логика сохраняется.
- **SC-004**: HOTELS-13142 получает ожидаемую отметку при сохранённых данных; проверки воспроизводимы.

- **SC-005**: подтверждённый сброс возвращает стартовый экран; перезапуск страницы и сервера не возвращает старые данные, новый импорт начинается с пустого состояния.
- **SC-006**: отмена, занятость, устаревшее подтверждение и ошибка очистки не удаляют новый или текущий пригодный набор; успех не сообщается до завершения удаления.

- **SC-007**: полностью неспринтовая гипотеза с 20 сутками цикла, 5 сутками Отложено и 6 сутками подтверждённой активности показывает 9 суток без работы; неполный или пустой состав не получает вымышленного числа.
