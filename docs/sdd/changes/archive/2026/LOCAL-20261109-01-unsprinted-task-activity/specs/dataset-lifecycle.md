# Полный сброс данных анализа

## Добавленные требования

### FR-055: Сброс данных и начало нового анализа

В основном приложении система ДОЛЖНА предоставлять кнопку «Сбросить все данные». Перед выполнением система ДОЛЖНА показывать подтверждение с действиями «Отмена» и «Сбросить данные» и объяснять, что сохранённый анализ будет удалён и для его восстановления потребуется новая загрузка. Отмена и закрытие подтверждения ничего не меняют.

После подтверждения система ДОЛЖНА удалить текущий локальный набор: исходные входы анализа, аудит отбора, загруженные истории, иерархию, спринты и производные результаты, а также локальные копии и временные файлы этого набора, принадлежащие механизму кэша. Завершённые и ошибочные задания с данными прежнего набора удаляются из памяти. Сбрасываются поля ввода источника, поиск, фильтры, сортировка, масштаб, выбор источника метрик, раскрытые строки, выбранная карточка, прежние ошибки и сообщения. Пользователь видит стартовый экран выбора источника. Перезагрузка страницы и перезапуск сервера не восстанавливают удалённый анализ; новый импорт начинается без данных прежнего набора.

Сброс относится к данным анализа внутри приложения. Исходные CSV/XLSX пользователя, данные Jira, настройки и учётные данные подключения, согласованные правила расчёта и список проектов без спринтов сохраняются. Сброс не требует обращения к Jira. Режимы просмотра сохранённого снимка и демонстрации не предоставляют действие сброса.

Во время импорта, обновления или другого сброса действие ДОЛЖНО быть недоступно; сервер также отклоняет конфликтующее действие. Сброс из устаревшей вкладки не ДОЛЖЕН удалять новый набор, появившийся после открытия подтверждения: требуется открыть актуальный набор и заново подтвердить действие. Поздний ответ прежнего запроса не ДОЛЖЕН возвращать удалённые данные на экран.

Успех ДОЛЖЕН отображаться только после подтверждённого удаления сохранённых данных. При ошибке серверной очистки система ДОЛЖНА показать причину и сохранить текущий пригодный набор; удаление части вспомогательных копий не объявляется полным успехом. При потере ответа интерфейс ДОЛЖЕН сверить фактическое состояние с сервером, не предполагая ни успех, ни сохранность прежнего набора. Повторный сброс пустого состояния безопасен. Повреждённый кэш также можно удалить по явному подтверждению.

#### AC-145: Подтверждение и отмена

- **ДАНО** загружен набор и пользователь нажал «Сбросить все данные».
- **КОГДА** открывается подтверждение.
- **ТОГДА** видны последствия и два действия; до подтверждения запрос удаления не отправляется.
- **КОГДА** пользователь отменяет или закрывает подтверждение.
- **ТОГДА** набор, поля ввода и настройки отображения сохраняются.

#### AC-146: Сброс сохраняется после перезапуска

- **ДАНО** сохранён набор с историями, иерархией и спринтами, изменены фильтры и раскрыты строки.
- **КОГДА** сброс подтверждён и сервер завершил очистку.
- **ТОГДА** отображается стартовый экран с исходными значениями полей и настроек; API возвращает отсутствие набора, прежние задания недоступны.
- **КОГДА** страница и затем сервер перезапускаются без Jira.
- **ТОГДА** набор остаётся пустым; копии кэша не восстанавливают старый анализ.

#### AC-147: Новый импорт и границы очистки

- **ДАНО** сохранён анализ A, настроено подключение к Jira и имеется исходный файл пользователя.
- **КОГДА** выполнен сброс, затем импортирован набор B.
- **ТОГДА** B не содержит данных A; исходный файл, настройки подключения и согласованные правила расчёта сохранены. Для самого сброса сетевых запросов к Jira нет.

#### AC-148: Занятость и устаревшее подтверждение

- **ДАНО** выполняется импорт или обновление.
- **КОГДА** пользователь пытается сбросить данные, в том числе прямым запросом API.
- **ТОГДА** действие отклонено как занятое; задание и прежний набор сохраняются.
- **ДАНО** подтверждение открыто для A, но другая вкладка уже загрузила B.
- **КОГДА** отправляется подтверждение сброса A.
- **ТОГДА** B сохраняется, интерфейс сообщает об изменении набора и требует нового подтверждения.

#### AC-149: Ошибка очистки и потерянный ответ

- **ДАНО** существует пригодный сохранённый набор.
- **КОГДА** удаление кэша завершается ошибкой.
- **ТОГДА** пригодный набор остаётся текущим и восстанавливаемым; показана ошибка, успех не заявлен.
- **КОГДА** сервер выполнил сброс, но ответ потерян.
- **ТОГДА** повторное чтение подтверждает пустое состояние; интерфейс не возвращает прежний набор из памяти и не запускает импорт автоматически.

#### AC-150: Пустой или повреждённый кэш

- **ДАНО** набора нет либо его кэш повреждён и анализ не открывается.
- **КОГДА** пользователь подтверждает сброс; в пустом состоянии действие затем повторяется.
- **ТОГДА** результат — стартовый экран без ошибки чтения кэша; повтор не создаёт данных и не требует Jira.

#### AC-151: Просмотр и защита локального действия

- **ДАНО** открыт режим демонстрации или просмотра снимка.
- **КОГДА** отображается интерфейс либо отправлен прямой запрос сброса.
- **ТОГДА** кнопки нет, сервер отклоняет запрос; снимок сохраняется.
- **ДАНО** запрос приходит с чужого источника или без заголовка локального действия.
- **КОГДА** сервер принимает запрос.
- **ТОГДА** он отклоняет его с существующей защитой локального API без удаления данных.

#### AC-152: Поздний ответ прежнего запроса

- **ДАНО** ответ чтения или опроса старого задания задержался, а сброс уже завершён.
- **КОГДА** старый ответ приходит в интерфейс.
- **ТОГДА** пустое состояние сохраняется; история, карточки и результаты прежнего анализа не появляются вновь.

## Изменённые требования

### FR-023: Совместимость кэша

Кэш v2 ДОЛЖЕН мигрировать в v3 с профилем `legacy-v2`, сохраняя исходные входы, `id`, `savedAt` и переданный срез. Перед записью создаётся `dataset.v2.backup.json` с запретом перезаписи. Если файл backup уже существует, реализация продолжает миграцию без проверки соответствия его содержимого текущему v2. Производные числа пересчитываются текущим кодом; тесты подтверждают сохранение чисел проверенных фикстур, а не неизменность при любых будущих изменениях расчёта. Повреждённый кэш или неизвестный профиль ДОЛЖЕН сохраняться для разбора при чтении. Исключение — явно подтверждённый пользователем сброс по FR-055, удаляющий данные анализа, включая повреждённый кэш и его локальную копию.

#### AC-015: Повреждённый кэш

- **ДАНО** локальный файл не проходит проверку схемы.
- **КОГДА** сервер читает его при запуске.
- **ТОГДА** исходный файл остаётся на диске, а API сообщает ошибку.

Сброс такого состояния проверяется отдельно по AC-150; обычное чтение ничего не удаляет.

## Удалённые требования

Нет.
