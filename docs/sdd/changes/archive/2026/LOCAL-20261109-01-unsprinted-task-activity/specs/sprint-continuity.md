# Учёт работы в проектах без спринтов

## Добавленные требования

### FR-054: Подтверждённая работа в проекте без спринтов

Согласованный пользователем 09.11.2026 список проектов без спринтов: **TEXT, CONTENT, MLE, UX**. Система ДОЛЖНА применять проектное исключение только к этому явному списку; отсутствие Sprint у загруженных задач другого проекта не расширяет список.

Если проект подтверждён как работающий без спринтов и полная непротиворечивая история участия до среза подтверждает отсутствие спринтов у обычной задачи, система ДОЛЖНА учитывать её фактические интервалы активного статуса. Отсутствие участия у одной задачи или всех загруженных задач не ДОЛЖНО автоматически классифицировать весь проект как неспринтовый. Для спринтовых и неклассифицированных проектов прежний режим сохраняется, даже если поле Sprint отдельной задачи пусто. Источник подтверждения проекта — явное решение пользователя, зафиксированное в Q2 предложения.

Пустое текущее поле при прежнем участии недостаточно. Неизвестное участие, недоступное поле или непрочитанная история не ДОЛЖНЫ включать этот режим. Обнаруженное участие задачи в спринтах сохраняет прежний путь и требует проверки классификации проекта.

Работа определяется по текущим подзадачам, а при их подтверждённом отсутствии — по самой задаче, с прежними правилами категории «В работе», неизвестности и переноса подзадач. Учитываются точные положительные по длительности интервалы до среза, без расширения до целого спринта. Ожидание и завершённое состояние покрытия не дают. Повторные активные интервалы и пересечения разных задач объединяются без удвоения.

Как исключение для задачи подтверждённого проекта без спринтов из правил FR-036, FR-039 и FR-050, её подтверждённая активность ДОЛЖНА покрывать совпадающее время в общей оценке гипотезы и исключать отметку бреши на этом времени. Само отсутствие её календаря не создаёт глобальную неизвестность. Возможная работа при неполных статусах сохраняется как неизвестность точных возможных интервалов; другая доказанная работа сохраняет покрытие.

Для остальных задач прежние критерии работы в спринте и бреши по включению сохраняются. Включение без подтверждённой активности не покрывает числовое время без работы. Полностью неспринтовая гипотеза оценивается на всём цикле реализации по FR-050; смешанная — внутри известных календарей. Отдельная задача без спринтов не превращает весь пересекающийся спринт в рабочий и не создаёт искусственные спринты. Отметка остаётся ограничена ранее выбранными этапами; точные интервалы и их задачи доступны для объяснения результата.

#### AC-139: Частичное покрытие спринта задачей без спринтов

- **ТОГДА** покрыты только 3 суток, без работы остаются 11; отметка отсутствует только на покрытых 3 сутках; задача не создаёт рабочий спринт на все 14 суток.

#### AC-140: Прежнее участие в спринте

- **ТОГДА** отсутствие спринтов не объявляется доказанным, неопределённость и её причина сохраняются.

- **КОГДА** объединяются интервалы.
- **ТОГДА** подтверждённая активность сохраняется, остаток возможной работы отмечен неизвестным; рабочий статус родителя не подменяет подзадачи. При доказанно пустом составе используется собственная история задачи.

- **ТОГДА** точные активные интервалы вместо спринтов используются для каждого проекта согласованного списка; для HOTELS и проекта вне списка отсутствие Sprint у задач не включает альтернативный режим и не подтверждает режим всего проекта.

- **КОГДА** цикл ещё не завершён либо закрыт окончательно без эксперимента.
- **ТОГДА** используются соответственно общий срез или дата окончательного закрытия по FR-049; последующие циклы учитываются отдельно.

#### AC-155: Неизвестная или пустая ветка не включает полный цикл

- **ТОГДА** гипотеза не объявляется полностью неспринтовой; возможная неизвестность сохраняется, точное число не выдумывается.
- **ДАНО** допустимых обычных задач нет.
- **КОГДА** определяется режим.
- **ТОГДА** пустое множество не считается подтверждением полностью неспринтового состава.

## Изменённые требования

### FR-036: Работа задачи через её подзадачи

Для спринтового способа учёта задача ДОЛЖНА быть включена в рассматриваемый спринт. При наличии подзадач система ДОЛЖНА определять работу по наличию хотя бы одной подзадачи в статусе категории Jira «В работе». Собственный статус родительской задачи при этом МОЖЕТ быть нерабочим. При подтверждённо пустом текущем составе подзадач система ДОЛЖНА использовать статус категории Jira «В работе» самой задачи.

Включение задачи в спринт без соответствующего рабочего статуса не ДОЛЖНО считаться работой. Сама работа без включения задачи в спринт также не удовлетворяет этому правилу. Принадлежность отдельной подзадачи спринту не является дополнительным условием: проверяется задача, для которой читаются подзадачи. Неизвестный состав подзадач не ДОЛЖЕН подменяться пустым составом. Рабочее состояние определяется по истории в рассматриваемом периоде, а не только по текущему статусу.

Система ДОЛЖНА анализировать историю текущих доступных Jira Sub-task родительской задачи. Текущая принадлежность проверяется по штатному отношению parent/subtasks; отдельная issue-link не требуется. Состав фиксируется при загрузке и используется для всего оцениваемого периода, без реконструкции удалённых и перенесённых в прошлом подзадач. Дата создания ограничивает рабочие интервалы подзадачи, но не переключает расчёт на статус родителя до её создания. При непустом текущем составе используется работа подзадач; при подтверждённо пустом — работа задачи; неизвестный состав не подменяется пустым.

При доступной непротиворечивой текущей связи и полной статусной истории работа хотя бы одной подзадачи достаточна для покрытия, даже если истории остальных неизвестны. При явно обнаруженном событии переноса родителя в прочитанной истории такой подзадачи либо противоречивой текущей связи её история не ДОЛЖНА давать покрытие; возможная работа считается неизвестной. Область этой неизвестности включает всю возможную работу подзадачи от создания до среза, ограниченную доказанным членством задачи в спринтах; если её нельзя ограничить, действует FR-039. Восстановление истории переноса не требуется. Известная работа другой непротиворечивой подзадачи сохраняет покрытие. Отсутствие событий переноса не является доказательством того, что переносов не было.

Интерфейс ДОЛЖЕН явно показывать «Анализ по текущему составу подзадач» у аналитики спринтов и объяснять, что переносы и удаления могут менять исторический результат. Пометка ДОЛЖНА сохраняться после перезапуска и быть доступна без раскрытия всех задач. Полнота здесь означает полноту доступного текущего состава в границах прав Jira, а не гарантию отсутствия скрытых либо удалённых в прошлом объектов.

Система ДОЛЖНА сначала проверять полную доступную цепочку переходов до наблюдаемого состояния и восстанавливать состояние на срезе. Переходы после среза ДОЛЖНЫ сохраняться для реконструкции и проверки целостности, но не создавать время или работу после среза. Это правило применяется к статусам и принадлежности задач спринтам. Состав подзадач остаётся текущим наблюдением загрузки; он не объявляется восстановленным на прошлый срез. Разрыв доступной цепочки после среза не ДОЛЖЕН скрываться предварительным отсечением событий.

Для задач, прошедших критерии FR-054, обязательное членство в спринте заменяется точными активными интервалами. Правила текущего состава подзадач, категории «В работе», переносов и проверки истории сохраняются. Это исключение не ослабляет требование подтверждённой активности для покрытия целого спринта у остальных задач.

#### AC-070: Текущий состав и обнаруженный перенос

- **ДАНО** текущая Sub-task S связана с T взаимно через parent/subtasks; T включена в спринт 01–15.09, S работала 04–05.09; истории полны, признаков переноса в прочитанных данных нет.

- **КОГДА** вместо этого прочитано явное событие смены parent S 20.09 либо текущий parent S не совпадает с T.
- **ТОГДА** S не даёт покрытие; её возможная работа в спринте неизвестна, отрицательный вывод запрещён. Проверенная работа другой подзадачи T по-прежнему подтверждает покрытие.
- **КОГДА** S больше не входит в полный текущий состав T, который теперь пуст, а её бывшая принадлежность не обнаружена в полученных данных.
- **ТОГДА** T оценивается по собственному статусу; бывшая S не разыскивается, ограничение текущего состава явно показано. Результат не объявляется реконструкцией прошлого состава.

- **КОГДА** текущий состав подтверждённо пуст.
- **ТОГДА** рабочая история T даёт покрытие этого спринта.
- **КОГДА** вместо этого состав недоступен или неполон и известной работы подзадач нет.
- **ТОГДА** результат неизвестен, собственный статус T не используется как замена.

#### AC-074: Переход после среза нужен для восстановления

- **КОГДА** восстанавливается состояние задачи на срезе.
- **ТОГДА** до среза задача находится «В работе»; последующий переход не добавляет длительности после 10:00 и не стирает предшествующую работу.
- **КОГДА** после среза прочитано добавление в спринт или удаление из него.
- **ТОГДА** членство на срезе восстановлено из полной цепочки: позднее добавление не приписывается прошлому, позднее удаление не стирает доказанное прежнее членство.

#### AC-075: Целостность после среза и точная граница

- **ДАНО** доступная цепочка содержит разрыв после среза либо не согласуется с наблюдаемым текущим состоянием.
- **КОГДА** строится анализ спринтов.
- **ТОГДА** цепочка не объявляется доказанной после удаления неудобного перехода; без другого положительного доказательства показана неизвестность.
- **КОГДА** вместо разрыва есть корректный переход точно на срезе.
- **ТОГДА** он задаёт конечное состояние, но положительного рабочего времени после этого перехода ещё нет.

### FR-037: Покрытие целыми спринтами и объединение задач

ЕСЛИ работа задачи по FR-036 подтверждена хотя бы в части спринта, система ДОЛЖНА считать этот спринт спринтом с работой целиком. Внутренние паузы между рабочими интервалами этой задачи или её подзадач не ДОЛЖНЫ становиться отдельными брешами внутри такого спринта.

Для главного эпика система ДОЛЖНА отдельно объединять временное покрытие спринтов с подтверждённым включением хотя бы одной допустимой дочерней задачи. Такое включение устраняет общую брешь в покрытом периоде независимо от рабочего статуса, команды, проекта и ритма. Состояние работы каждого сегмента по FR-036 при этом не меняется. Это покрытие членством используется только прежними брешами FR-038. Для новой метрики FR-050 объединяются спринты с работой; включение без работы её не покрывает. Сворачивание, порядок строк и порционная отрисовка не ДОЛЖНЫ менять расчёт. Общая задача не увеличивает длительность покрытия при повторной встрече в разных ветках.

Точные активные интервалы FR-054 ДОЛЖНЫ объединяться с покрытием работой спринтов для числовой метрики и с покрытием членством для прежних брешей. Активность проекта без спринтов не меняет состояние соседнего спринта и не расширяется до его границ. Пересечения точных интервалов между собой и со спринтами учитываются один раз.

### FR-038: Бреши только на выбранных этапах главного эпика

Система ДОЛЖНА показывать подтверждённые бреши непосредственно под цветной полосой этапа, вплотную к её нижнему краю, главного эпика только в интервалах этапов «Проверка идей» и/или «Валидация», «Реализация» и «Оценка результата». На остальных этапах отсутствие включённых дочерних задач не ДОЛЖНО обозначаться брешью. Повторное вхождение в один из выбранных этапов ДОЛЖНО оцениваться отдельно по его фактическим датам.

Один эпик МОЖЕТ содержать смешанную историю старых и новых статусов. Система ДОЛЖНА оценивать каждый подходящий интервал независимо от варианта процесса остальных интервалов. «Проверка идей» и «Валидация» сохраняют собственные названия; «Отложено», «Запланировано», «Скоринг» и остальные этапы не получают отметку бреши.

Для задач со спринтовым способом учёта брешь ДОЛЖНА означать доказанное отсутствие включения всех допустимых дочерних задач эпика в закрытые спринты рассматриваемого периода. Включение хотя бы одной задачи хотя бы в части наблюдаемого спринта исключает брешь на всём его интервале, даже если ни задача, ни её Jira Sub-task не были «В работе». Неизвестное членство не доказывает отсутствие включения.

Отметка ограничивается пересечением с выбранным этапом и выглядит как отдельная тонкая тёмная полоса, соприкасающаяся с нижним краем полосы статуса без зазора и перекрытия. Цветная заливка статуса остаётся непрерывной. Обозначение бреши ДОЛЖНО быть объяснено в легенде и отличаться от дорожки Impediment. Исходные даты статуса, числовые TTM, CT и impediment сохраняются. Подсказка ДОЛЖНА объяснять отсутствие включённых задач и даты бреши; исходные спринты доступны в отдельном слое. Недостаточность данных и предварительное отсутствие работы активного спринта на цветной полосе эпика не отображаются; их объяснения остаются в сегментах и деталях спринтов.

Дополнительно точная активность FR-054 ДОЛЖНА исключать брешь только на совпадающем времени; возможная неизвестная активность запрещает отрицательный вывод на возможном интервале. Область прежней отметки остаётся внутри известных закрытых спринтов и выбранных этапов. У полностью неспринтовой гипотезы полный цикл используется числовой метрикой FR-050, но не создаёт искусственных спринтов или новых оснований для прежней отметки. Подсказка объясняет оба источника покрытия; типы текущих статусов и их длительности не меняются.

### FR-039: Неизвестность отличается от бреши

Система ДОЛЖНА различать два вывода: работу в сегменте спринта по FR-036 и отсутствие включённых задач для бреши по FR-038. Недоступная статусная история, неизвестная категория или неполный состав Sub-task делают работу неизвестной, но сами по себе не мешают доказать отсутствие членства родительской задачи. При известном включении брешь отсутствует независимо от полноты рабочих статусов и Sub-task.

Полнота состава дочерних задач ДОЛЖНА оцениваться отдельно для каждого главного эпика, включая вложенные ветки и допустимых потомков скрытого отклонённого эпика. Непрочитанный элемент с неизвестным типом/допустимостью или неполученная часть ветки учитываются как возможные включённые задачи. Если неизвестные состав, членство, даты или календарь не позволяют ограничить возможное включение, отрицательный вывод во всём оцениваемом периоде затронутого эпика запрещён. Неполнота одной ветки не отменяет достоверную оценку независимого главного эпика.

Под цветной полосой эпика ДОЛЖНЫ отображаться только подтверждённые бреши по FR-038. Известное включение задачи исключает брешь на всём спринте; неизвестность возможного включения также запрещает брешь. На перекрытии с активным спринтом окончательная брешь не показывается. Доказанный промежуток без спринта не является брешью. Недостаточность данных на этой полосе не рисуется.

В аналитическом результате сегментов сохраняется приоритет работы: подтверждённая работа, неизвестность, предварительное отсутствие работы активного спринта, отсутствие работы закрытого спринта. Пустой и неизвестный сегменты скрыты по FR-042, но сохраняют собственные границы в аналитике и текстовых пояснениях; отсутствие работы не равнозначно отсутствию включённых задач. Состояния сегментов задач и эпиков не ограничиваются маской FR-038. Отсутствие подходящего HF-этапа у Delivery-эпика не скрывает его сегменты с доказанной работой. Новый числовой показатель имеет собственные границы и правила неизвестности FR-049–051; членство без работы не заменяет рабочее покрытие.

Будущие, ещё не начавшиеся спринты не ДОЛЖНЫ входить в аналитическую выборку, создавать покрытие, неизвестность или расширять ось, в том числе при отсутствии дат. Начавшийся активный спринт ДОЛЖЕН попадать в выборку без completeDate; он ограничивается срезом. Состояние оценивается на срезе; закрытие после него не переносится в прошлое. Отказ чтения спринта или подзадачи сохраняет доступные статусные полосы. Причины неполноты ДОЛЖНЫ оставаться в текстовых пояснениях анализа, доступных и без видимого сегмента; неизвестность отличается от предварительного результата ещё не завершённого периода.

Для задачи, удовлетворяющей FR-054, отсутствие собственного календаря не ДОЛЖНО создавать неизвестность всего эпика. Неизвестность её статусной истории ограничивается возможными точными активными интервалами и не расширяется на целый спринт. На непокрытом остатке учитываются прежние причины неизвестности других задач и веток. Неподтверждённый режим проекта, неполное членство или недоступная ветка не превращаются в доказанное отсутствие работы. Точная активность из другой ветки сохраняет покрытие независимо от этих причин.

#### AC-082: Будущий спринт без дат не скрывает прошлую брешь

- **ДАНО** полный календарь содержит закрытый S с интервалом 01–08.09 и доказанным отсутствием включённых задач и подтверждённый будущий F без дат; задача назначена в F и имеет рабочую историю. Главный эпик находится в реализации 01–08.09, срез — 10.09, иных покрытий и неизвестностей нет.
- **КОГДА** строится анализ, затем набор восстанавливается из кэша без сети.
- **ТОГДА** сегмент S скрыт, его данные сохраняются; прежняя брешь 01–08.09 сохраняется. F отсутствует на полосках, не расширяет ось и не создаёт покрытия или неизвестности.
- **КОГДА** дополнительно имеется активный незакрытый спринт A, начавшийся 09.09, с подтверждённой работой и без completeDate.
- **ТОГДА** A присутствует на полоске задачи и её эпиков с покрытием 09–10.09; отсутствие даты закрытия не исключает его и не меняет результат S.

#### AC-083: Неизвестность Delivery-эпика не зависит от HF-этапов

- **ДАНО** H содержит D1 и D2; у D1 обычные DF-статусы без этапов FR-038, полный календарь S 01–15.09, известная задача без работы и непрочитанная ветка X; у D2 полный состав и работа в том же S. H находится в реализации 01–15.09.

- **ТОГДА** у D1 аналитическое состояние S неизвестно, его сегмент скрыт; причина доступна в текстовых пояснениях; у D2 и H он с работой. Положительный результат другой ветки не меняет состояния D1.
- **КОГДА** X затем полностью прочитана и работа всех задач D1 доказанно отсутствует.
- **ТОГДА** S у D1 аналитически пустой, сегмент по-прежнему скрыт; состояние не требует наличия HF-этапов в истории D1. Сворачивание и восстановление без сети не меняют эти результаты.

#### AC-084: Сегменты работы при неизвестной истории эпика

- **ДАНО** типы и состав H → D → T подтверждены; статусные истории H и D неполны, но членство T в закрытом S 01–15.09 и работа её подзадачи в нём подтверждены; даты S известны.
- **КОГДА** строится календарь и раскрываются строки, затем набор восстанавливается без сети.

У H/D сохранены предупреждения о неизвестной статусной истории; отсутствующие этапы и их границы не выдумываются, числовые метрики не становятся известными. Без доказанной маски H точная брешь не рисуется; это не скрывает известный сегмент S.

- **ТОГДА** известные данные дочерних задач не обходят прежний отказ загрузки: новый набор не публикуется, предыдущий сохраняется.
