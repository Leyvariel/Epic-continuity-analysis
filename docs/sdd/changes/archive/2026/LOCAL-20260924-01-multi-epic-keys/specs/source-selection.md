# Изменение возможности: выбор источника

## Добавленные требования

### FR-026: Прямой ввод списка ключей

Система ДОЛЖНА предоставлять многострочное поле для одновременного ввода ключей разных Jira-проектов. ДОЛЖНЫ приниматься построчный список с пустыми строками и одноколоночная таблица Markdown из [контрольных примеров](../examples.md), а также обычный построчный текст, скопированный из отображаемой колонки таблицы. Первый ключ таблицы считается данными; отдельная подпись `New grid` перед таблицей и строка выравнивания — оформлением. Пробелы по краям ключа ДОЛЖНЫ удаляться, регистр ДОЛЖЕН нормализоваться. Каждый распознанный ключ ДОЛЖЕН проходить существующий отбор по текущей Jira. Одна команда пользователя ДОЛЖНА запускать обработку всей выборки с последующим показом результата; отдельного запуска каждого ключа не требуется.

#### AC-018: Два вида одной выборки

- **ДАНО** 24 ключа из [контрольных примеров](../examples.md) представлены построчно и как одноколоночная таблица.
- **КОГДА** пользователь запускает каждую загрузку.
- **ТОГДА** приложение передаёт в отбор одинаковые 24 ключа в исходном порядке; первый ключ таблицы сохранён.

#### AC-019: Повтор ключа

- **ДАНО** ключ повторён в разных строках или регистрах.
- **КОГДА** список разбирается.
- **ТОГДА** он создаёт одного кандидата и одну строку результата; повтор отражён в аудите.

### FR-027: Ошибочные строки не скрывают результат

Система ДОЛЖНА разбирать корректные ключи даже при наличии ошибочных строк, фиксировать для каждой такой строки исходное значение, номер и понятную причину, если она известна. Строки с ошибками формата не ДОЛЖНЫ направляться в Jira. Пустые строки и поддерживаемое оформление таблицы не считаются ошибками. Если ни одного корректного ключа нет, система ДОЛЖНА показать отчёт об ошибочных строках без выдуманного HF-эпика.

#### AC-020: Корректные и ошибочные вместе

- **ДАНО** между корректными ключами есть неверный текст и пустые строки.
- **КОГДА** пользователь запускает анализ.
- **ТОГДА** корректные ключи проверяются в Jira, а неверная строка остаётся в отчёте с номером и причиной; пустые строки пропущены.

#### AC-021: Нет корректных ключей

- **ДАНО** поле содержит только ошибочные строки либо пустое оформление.
- **КОГДА** пользователь запускает анализ.
- **ТОГДА** ошибочные строки видны в отчёте без чисел и шкал; если нет даже ошибочных строк, пользователь получает сообщение о пустом вводе.

Отчёт о синтаксически ошибочных строках ДОЛЖЕН быть доступен без подключения к Jira, если корректных ключей нет. Наличие лишь ошибок не ДОЛЖНО выдаваться за подтверждённое отсутствие HF-эпиков.

## Изменённые требования

### FR-001: Источники выборки

КОГДА пользователь передаёт CSV/XLSX с ключами, вводит список ключей непосредственно, даёт ссылку на проверенную Jira-доску или ссылку на один эпик, система ДОЛЖНА создать задание выбранного источника. Файл и прямой ввод требуют только ключей; название, тип, резолюция и история берутся из Jira.

#### AC-001: Файл — сохраняемый сценарий

- **ДАНО** CSV или XLSX с одним однозначным списком ключей.
- **КОГДА** пользователь выбирает файл.
- **ТОГДА** приложение собирает кандидатов и читает актуальные данные и историю из Jira.

#### AC-022: Прямой ввод — новый сценарий

- **ДАНО** введено несколько ключей.
- **КОГДА** пользователь запускает анализ.
- **ТОГДА** создаётся одно задание и одна выборка с общим моментом среза.

## Удалённые требования

Нет.
