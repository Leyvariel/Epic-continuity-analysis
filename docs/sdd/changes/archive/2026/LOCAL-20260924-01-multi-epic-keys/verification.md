## Восстановление прежней сборки

Во временных каталогах старая рабочая версия из исходной копии создала совместимый v3 набор. Новая версия записала на его место набор `keys`; старая схема ожидаемо отклонила новый кэш. После восстановления прежнего `dataset.json` старая версия открыла без сети исходный id `2a66335c-d7d4-46a0-9f32-0a3331a3f960` и TTM `1296000000` мс (15 дней). Id промежуточного нового набора: `fbb8edb4-22f7-4a2e-b225-73253d2c62ce`. Реальный пользовательский кэш не изменялся. Это проверяет процедуру восстановления при наличии прежнего совместимого набора; автоматического обратного чтения `kind: keys` старой версией нет.

## Оставшаяся проверка

После реализации выполнена [содержательная сверка SDD](sdd-review.md): устранены остатки трёхисточникового описания, перенесены недостающие сценарии AC и уточнены границы локального отчёта. T015 повторно проверена; это не закрывает визуальную T016.

Снимки смешанной и полностью ошибочной таблиц в реальном браузере отсутствуют. Попытка открыть локальный стенд через Computer Use остановилась: in-app browser недоступен, а автоматическая проверка доступа отклонила управление Google Chrome без пояснения причины. Пользователь затем разрешил разовый доступ только для проверки локального синтетического стенда `http://127.0.0.1:4387`; повторный вызов `cua.getApp("Google Chrome")` всё равно вернул `Computer Use permissions are not granted`. Не заменять эти свидетельства утверждением, что CSS проверен визуально. После восстановления доступа открыть только локальный синтетический стенд, проверить обе таблицы и дополнить этот раздел фактическими снимками/наблюдениями. До этого T016 остаётся открытой; T015 относится к уже проверенной структуре и тексту current specs.
