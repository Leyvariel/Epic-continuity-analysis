# Предложение: раскрытие связанных эпиков и задач на календаре

Пользовательские уточнения завершены. Пакет и переход к реализации согласованы сообщением «Приступай к реализации». Реализация выполнена в рабочем дереве. Пользователь подтвердил проверку по ключу и признал её пока достаточной; SDD актуализирована. Полная приёмка T012/T013 остаётся частичной, пакет не архивирован.

## Проблема

Текущая таблица показывает историю выбранных HF-эпиков, но не даёт сопоставить её с работой по связанным эпикам нижних уровней и задачам. Связи и их истории не входят в текущий набор. Основания: [текущая визуализация](../../specs/visualization.md), [адаптер](../../../../server/jira/adapter.ts), [таблица](../../../../src/App.tsx).

## Ожидаемый результат и подтверждённые решения

| Решение | Подтверждённое поведение |
| --- | --- |
| Глубина | Рекурсивно от исходного эпика через нижние эпики до задач включительно; подзадачи исключены |
| Определение закрытия | Основной источник — `statusCategory`; без неё для эпиков `[HF] Закрыт` / `[DF] Закрыт`, для задач — логика названия статуса; неизвестное название явно обозначается |
| Границы полосок | Все фактические статусы от создания до окончательного закрытия; незавершённые — до среза; возвраты и повторные открытия сохраняются |
| Отбор | Связанные DF показываются; отклонённые элементы исключаются; ограничение исходных эпиков по HF сохраняется |
| Несколько родителей | Один элемент виден под каждым родителем |
| Раскрытие | Изначально всё свёрнуто; стрелка показывает непосредственных детей; вложенный эпик раскрывается своей стрелкой; повторное нажатие сворачивает ветку |
| Ошибка одной истории | Остальные полоски сохраняются, неполнота отмечается предупреждением |
| Числовая часть | В дочерних строках нет числовых длительностей; исходные метрики эпиков сохраняются |
| Источник | Раскрытие требуется для Jira и для автономного XLSX без Jira |

Первые уточнения зафиксированы в этой беседе после [проверки черновика](review.md); раскрытие по уровням и автономный XLSX подтверждены 28.09.2026. Формат книги и технический дизайн затем согласованы вместе с разрешением реализации.

## Область изменения

### Входит в область изменения

- Обход отношений «содержит» только вниз: `A contains B` эквивалентно `B is contained in A`; стандартный состав Epic Link объединяется с этими связями. Посторонние связи не дают дочерних строк.
- Общий календарь исходных эпиков и связанных элементов; отдельное состояние раскрытия для каждого пути к общему элементу.
- Чтение истории связанных задач независимо от HF-этапов.
- Сохранение, восстановление и обновление связей и историй.
- Обычный CSV/XLSX с ключами и историями Jira; автономный XLSX с явными связями и историями внутри книги.
- Доступная пользователю загрузка автономной книги через форму файла.

### Не входит в область изменения

- Показ подзадач; редактирование Jira; включение дочерних строк в исходную выборку и её числовую статистику.
- Изменение расчёта TTM, impediment и heatmap исходных эпиков.
- Автоматическое восстановление связей или точных переходов по агрегатам XLSX.
- Экспорт из Jira в новый XLSX: здесь определяются чтение формата и пример, а не отдельный экспортёр.

## Участники и авторизация

Канонический владелец пакета — этот репозиторий. Пользователь локального приложения выбирает источник и раскрывает строки. Jira читается серверным адаптером с существующим доступом; автономная книга не обращается к Jira и Keychain. Ответственный за согласование результата — пользователь; технический пакет подготовлен агентом и согласован пользователем на этапе 5.

Пользователь дополнительно подтвердил: отклонённый эпик скрывается, но его допустимые потомки показываются у ближайшего видимого предка с пояснением о промежуточной связи. Обход скрытого эпика продолжается.

## Детали согласованного дизайна

- Автономная книга получает дополнительные листы связей, метаданных и истории связанных элементов; точный [формат](xlsx-format.md) реализован и проверен автоматическими тестами.

- Дочерние строки не получают TTM, heatmap и числовой impediment; подсказка календаря содержит название статуса и даты.
- Пределы объёма и постраничное раскрытие описаны в дизайне. Превышение предела не считается полным успешным отображением дерева.

## Критерии успеха

- **SC-001**: все допустимые достижимые элементы появляются в своих ветках, в том числе DF и общие дети; подзадачи и отклонённые строки отсутствуют.
- **SC-002**: обычные статусы задач, повторные открытия и интервалы вне дат родителя показаны без потери времени и без дочерних чисел.
- **SC-003**: частичная ветка отличается от пустой; ошибка одного элемента не скрывает прочие доступные данные.
- **SC-004**: Jira и автономная книга обеспечивают одинаковое раскрытие для одинаковых нормализованных данных; автономный путь выполняет ноль обращений к Jira и Keychain.
- **SC-005**: после перезапуска восстанавливается тот же срез; обновление Jira меняет связи и истории согласованно.
