# Свидетельства реализации

Логи T001–T010 фиксируют содержательные падения и успешные прогоны соответствующих циклов; исходные номера строк относятся к моменту запуска. Первый итоговый `epic-linked-check-final.txt` фиксирует версию до исправления режима просмотра: 292 теста, 40 файлов, TypeScript и Vite, код завершения 0. Отдельные прогоны не прибавляются к числу итоговых тестов.

`epic-rollback-check.txt` — проверка прежних исходников и возврата сырого кэша на вымышленной книге, без Jira. Временная резервная копия реального пользовательского кэша сюда не переносится.

[Демонстрационная книга](linked-issues-demo.xlsx) содержит только вымышленные элементы: HF-корни, нижний DF, общий ребёнок, подзадачу, скрытый отклонённый эпик с допустимой задачей, цикл, отсутствующую историю и создание после среза. Это воспроизводимые данные для ручной проверки, а не её результат.

Запуск из корня репозитория: `npm run build`, затем `npx tsx scripts/verify-hierarchy-demo.ts`. Отдельный сервер работает на `http://127.0.0.1:4329`, использует временный кэш и не обращается к Jira. Остановка — Ctrl+C.

[Реальный образец Jira](jira-live-sample.json) подтверждает ограниченное живое получение BUSDIS-10 → BUSDEL-6 и восстановление без сети; обычной задачи и переоткрытия в нём нет. Полная живая и визуальная приёмка остаётся открытой; результаты и следующие действия — в [протоколе](../verification.md).

`preview-mode-red.txt` фиксирует содержательное падение двух новых сценариев просмотра. `preview-mode-check.txt` — успешные 295 тестов в 41 файле и сборка после исправления; включает сквозной синтетический ввод трёх CARSDIS. Диагностические серверы теперь предназначены только для просмотра; реальные загрузки выполняются в основном приложении на 4317.

`epic-membership-red.txt` — 11 падений новых требований к адаптеру до реализации Epic Link; `epic-membership-check.txt` — 309 успешных тестов в 42 файлах, TypeScript и сборка. Реальные ключи в тестах обозначают синтетический сценарий, а не доказательство живого состава.

`epic-resolution-red.txt` фиксирует падение обработки фактической отклоняющей резолюции до исправления. `epic-membership-live.json` — чтение настоящей Jira с разрешением пользователя на текущую сессию, 30 узлов/29 рёбер и идентичное восстановление. `epic-membership-live-projection.json` — сопоставление 27 ключей пользовательского снимка и 25 допустимых видимых задач, без новых сетевых запросов. Это не визуальная проверка.
