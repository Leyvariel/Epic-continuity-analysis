## Независимые примеры определения закрытия для T002/T004/T006

Все примеры имеют полную историю: создание 01.09, вход в указанный конечный статус 07.09, срез 10.09, время 00:00 МСК. Ожидаемые даты заданы явно. Категория относится к статусу на срезе. Пустая категория означает отсутствие пригодных данных, а не сетевой запрос из XLSX.

| Элемент и конечный статус | Категория | Ожидание |
| --- | --- | --- |
| Задача «Архив команды» | `done` или `completed` | Конец 07.09, основание — категория |
| Задача «В работе» | `new`, `indeterminate` или `in-flight` | Конец на срезе 10.09 |
| Задача «Готово» | Отсутствует либо `undefined` | Конец 07.09, основание — название |
| Задача «В работе» | Отсутствует | Конец на срезе 10.09, основание — название |
| HF-эпик `[HF] Закрыт` | Отсутствует | Конец 07.09 |
| DF-эпик `[DF] Закрыт` | Отсутствует | Конец 07.09 |
| HF/DF-эпик `[HF] Реализация` / `[DF] Реализация` | Отсутствует | Конец на срезе 10.09 |
| Задача «Готово» | `indeterminate` | Конец на срезе 10.09, предупреждение о расхождении |
| Задача «В работе» | `done` | Конец 07.09, предупреждение о расхождении |
| Задача «Готово» | Незнакомый ключ | Конец 07.09 по названию, предупреждение о категории |
| Задача «Архив команды» | Отсутствует либо незнакомый ключ | Предупреждение без точной полосы |
| Задача «Не закрыто» / «Готово к тестированию» | Отсутствует | Не распознавать как закрытие по подстроке; неизвестность без точной полосы |

Проверить все перечисленные в дизайне варианты словаря отдельными табличными случаями. Категория `done` после среза не закрывает задачу, которая на срезе находилась в `indeterminate`. Для версии C с переоткрытием 08.09 без категории название «В работе» продлевает полосу до 10.09 и сохраняет закрытый интервал 07–08.09. Отсутствие справочника при доступной истории допускает резервное правило; глобальные ошибки авторизации/отмены сохраняют общий контракт остановки импорта.

XLSX проверяется с необязательной колонкой категории и без неё; метаданные должны соответствовать последнему статусу истории. Прежнее обязательное поле «Закрыт на срезе» не требуется. После сохранения и открытия кэша без сети дата и основание классификации совпадают. Соответствующие автоматические проверки выполнены; живые категории целевой Jira пока не сверены.

## Граничные наборы для AC-039

- 1000 корней + 9000 детей: лимит узлов не превышен. Ещё один уникальный ребёнок: расширение графа останавливается, новые объекты не ставятся в очередь; доступные результаты сохраняются, затронутые ветки и набор явно неполны. Ровно допустимое число узлов само по себе не означает неполноту, если обход завершён.
- 50 000 и 50 001 уникальное ребро при числе узлов ниже 10 000: аналогичные ожидания для лимита рёбер. Повтор одного ребра не расходует лимит, разные родители общего ребёнка расходуют рёбра, но не добавляют уникальные узлы.
- 200 доступных путей: вся порция видна без предложения продолжения. 201 путь: после «Показать ещё» доступен последний путь без потерь и дублей, предупреждения о неполноте графа из-за порционирования нет.
- AC-036/AC-037/AC-039: между A и допустимым V находятся 20 уровней по два отклонённых эпика; каждый уровень связан с обоими узлами следующего. Проверить одну строку V под A, один восстанавливаемый маршрут пояснения и отсутствие перебора всех комбинаций. В одном обходе скрытый узел раскрывается не более одного раза; глубину вызовов не увеличивает рекурсия. Варианты: V отсутствует; добавлено обратное ребро между скрытыми уровнями. В первом случае обход завершается без допустимых детей, во втором также обозначается цикл.
- Стабильный общий ребёнок: один общий процесс получения снимка для всех родителей; чтение метаданных до и после истории разрешено. Изменившийся ребёнок: один повтор снимка в том же процессе; повторная нестабильность даёт предупреждение, третьего цикла получения снимка нет. HTTP-повторы транспорта учитываются отдельно и остаются ограниченными действующей политикой клиента.
- Эти данные проверяются на Jira-фикстурах и автономном пути по применимости: сетевые счётчики проверяются только у Jira; граф, границы и вывод — у обоих источников. Граница 50 000 рёбер проверяется на Jira-фикстурах и нормализованном графе: один лист «Связи» XLSX раньше достигает собственного предела 20 000 строк. Файловый путь отдельно проверяет этот предел; сквозная проверка XLSX на 50 000 рёбер не заявляется.

Для каждого цикла сохранять команду, исходное падение, внесённый результат и успешный запуск в [протоколе](verification.md). После нового исправления повторять затронутые тесты; полная регрессия и сборка выполняются в T011. Пройденная сборка не заменяет T012/T013.
