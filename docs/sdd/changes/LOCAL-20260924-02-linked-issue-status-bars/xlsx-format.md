# Дополнение автономного XLSX версии 1

Формат FR-033 реализован и проверен автоматическими сценариями. [Автономный контракт](../../../legacy-xlsx.md) описывает действующий импорт, включая старые книги. Фактическая визуальная приёмка остаётся открытой.

## Источник в форме

Вкладка «Файл» предоставляет выбор «История из Jira» / «История из XLSX, без Jira». По умолчанию остаётся первый вариант. Во втором принимается только XLSX и отправляется существующий `POST /api/import` с `X-History-Source: file`. Подпись поясняет, что для раскрытия нужны сведения о связях и истории внутри книги. Автоматического обращения в Jira при неполной книге нет.

## Листы

Один основной лист исходных эпиков сохраняет текущий формат и отбор HF. Остальные таблицы являются источниками дополнения, а не дополнительными списками исходных эпиков.

| Лист | Колонки и смысл |
| --- | --- |
| Параметры | Существующий `asOf`; дополнительно `hierarchyVersion = 1` включает проверенный формат дополнения |
| Элементы | `Ключ`, `Название`, `Вид элемента`, `Резолюция`, `Создан`, `Статус на срезе`; необязательная `Категория статуса на срезе` |
| Связи | `Откуда`, `Связь`, `Куда`; допустимые значения связи — `contains` и `is contained in` |
| История | Существующие `Ключ эпика` либо `Ключ`, `Статус`, `Начало`, `Окончание`; теперь могут относиться к дочерним ключам из «Элементов» |
| Impediment | Прежний необязательный формат для исходных эпиков; дочерней полосе не требуется |

«Вид элемента» имеет значения «Эпик», «Задача», «Подзадача»; это классификация для обхода, не HF/DF. Пустая резолюция допустима и отличается от отсутствующей обязательной колонки. Категория статуса необязательна: если она предоставлена, используются ключи и приоритеты из дизайна; если нет — правила названий HF/DF и задач. Отдельное обязательное поле «Закрыт на срезе» не требуется. Результат по названию сопровождается указанием основания; неизвестное имя без категории не даёт доказанного конца полосы. Метаданные нужны для всех достижимых элементов и исходных родителей. Строки подзадач допустимы во входе, но исключаются из отображения и обхода.

Для одного ключа используется одна история в листе «История», включая случай, когда он одновременно исходный и дочерний эпик. В исходной строке из неё считается прежний HF-TTM, в дочерней — полный жизненный цикл. Эти два представления имеют разные заявленные границы.

## Проверка и совместимость

- Метаданные и связи проверяются до выбора основного листа. «Элементы» исключается из кандидатов основного листа только при валидном маркере дополнения и ожидаемой структуре; произвольный второй основной лист по-прежнему вызывает неоднозначность.
- Файловый Jira-режим тоже распознаёт эти вспомогательные листы по маркеру и структуре, но берёт связи и истории из Jira. Количество исходных эпиков определяется только основным листом.
- Существующие точные даты, Excel 1900/1904 и московское время обрабатываются общим `tableTimestamp`. Сначала сравнивается «Создан» со срезом. Если создание позже среза, элемент становится строкой «Создан после среза»: история не требуется и не рассчитывается, значения статуса/категории на срезе могут быть пустыми; это не превращает ветку в неполную. Для существовавшего на срезе дочернего элемента история должна начинаться ровно в «Создан», идти без разрывов и соответствовать статусу на срезе. При неизвестном создании либо признаке закрытия полоса недоказана, остальные строки сохраняются.
- Для завершённого элемента последняя строка — закрывающий статус с моментом входа. Длительность после него на календаре не показывается. Промежуточное закрытие перед повторным открытием остаётся интервалом.
- Для незавершённого последняя строка оканчивается в `asOf` или имеет пустое окончание; пустота других окончаний недопустима.
- Отсутствующий лист связей означает «данные не загружены», а лист только с заголовками — заявленное отсутствие связей для перечисленных родителей. Полнота здесь основана на содержимом книги, а не проверке Jira.
- Дубли одинаковой связи объединяются; конфликтующие строки метаданных одного ключа либо неизвестная версия дополнения отклоняют новый импорт с сохранением прежнего набора. Неверная отдельная связь отмечает состав затронутой ветки как неполный.
- Непредоставленный ключ назначения даёт предупреждение о неразрешённом элементе, а не вымышленную задачу. Истории недостижимых ключей не добавляют исходные эпики.
- Книга без маркера остаётся старым форматом, без сетевого обогащения. Новые листы без маркера не интерпретируются как доказанные связи; пользователь получает указание на формат.
- Пределы книги сохраняются: 20 МиБ, 20 000 строк и 500 столбцов на листе; граф дополнительно ограничен по NFR-001. Полнота при нарушении пределов не заявляется.

## Минимальный пример

Срез — 10.09.2026 00:00:00 МСК. В основном листе один HF-эпик A-1 с прежними контрольными данными.

| Ключ | Название | Вид элемента | Резолюция | Создан | Статус на срезе | Категория статуса на срезе |
| --- | --- | --- | --- | --- | --- | --- |
| A-1 | Исходный эпик | Эпик | | 01.09.2026 00:00:00 | [HF] Реализация | |
| B-1 | Связанный DF | Эпик | | 01.09.2026 00:00:00 | [DF] Реализация | |
| C-1 | Связанная задача | Задача | Готово | 01.09.2026 00:00:00 | Готово | |

| Откуда | Связь | Куда |
| --- | --- | --- |
| `A-1` | `contains` | `B-1` |
| `C-1` | `is contained in` | `B-1` |

Для C-1 лист «История» содержит «Открыто» 01–03.09, «В работе» 03–07.09 и «Готово» с 07.09 с пустым окончанием. Категория отсутствует; «Готово» распознано по названию. Полоса завершается 07.09 с указанием этого основания. Для A-1 и B-1 также нужны свои непрерывные истории. Готовая [демонстрационная книга](evidence/linked-issues-demo.xlsx) с вымышленными данными сохранена для воспроизведения; дополнительные отрицательные варианты генерируются в тестах.
