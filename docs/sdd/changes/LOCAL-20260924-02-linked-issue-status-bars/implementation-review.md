# Проверка реализуемости по текущему коду

## Результат

На 28.09.2026 изменение реализуемо в существующем локальном приложении. Дополнительная БД и новый внешний сервис не требуются. Нужны изменения адаптера Jira, парсеров книги, сохраняемого дополнения и таблицы. Исходные проверки пройдены; готовность новой функциональности ещё не доказана.

Сверка относится к рабочему дереву, зафиксированному в [списке контрольных сумм](baseline.json), а не только к HEAD: приложение и SDD пока не отслеживаются Git. Состояние ветки и результат `npm run check` записаны в [протоколе](verification.md).

| Проверенный источник | Обнаруженное ограничение | Как учтено |

В текущем Jira-пути глобальная недоступность всех исходных историй блокирует импорт. Этот существующий барьер остаётся: новая иерархия не должна молча обходить отказ корневой загрузки. Недоступность отдельных дочерних историй обрабатывается внутри успешно сформированного исходного набора по новому требованию.

## Зависимости и внешнее подтверждение

Используются уже установленные TypeScript, React, Express, Zod и SheetJS; установка новой библиотеки не заложена. Публичные источники API приведены в дизайне. Они подтверждают основу контракта, но не конфигурацию конкретной Jira 9.12.10. Точные поля связи и закрытия должны быть проверены в T012; при несовпадении адаптер/дизайн корректируются и затронутые проверки повторяются. Старые живые проверки других возможностей не засчитываются.

Пример полного автономного дополнения пока описан как контракт и фиксированные тестовые данные. Существование нового готового XLSX не заявляется. Экспортёр Jira → XLSX в это изменение не входит.

## Ограничения и откат

Граф может иметь общих потомков, поэтому число путей больше числа узлов. Дизайн ограничивает чтение и строит пути лениво. Достижение лимита означает неполный результат, а не закрытый критерий показа всего дерева.

Сохранение версии оболочки кэша не гарантирует сохранность дополнения старой программой после записи. Поэтому обязателен описанный в дизайне откат с резервным сырым кэшем. Проверять на временных данных; рабочий кэш этой проверкой не изменялся.

Блокирующих дополнительных пользовательских уточнений для подготовки пакета нет. Этап 5 требует согласования дизайна, включая формат XLSX, пределы и поведение потомков исключённого промежуточного эпика. Новые тесты, живая интеграция и визуальная проверка остаются работой этапа 6.
