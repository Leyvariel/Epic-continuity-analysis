# Назначение и границы проекта

## Назначение и ответственность

Локальное приложение помогает анализировать длительность и последовательность работы HF-эпиков: выбирать набор из файла, прямого списка ключей, Jira-доски или ссылки на один эпик, читать историю Jira или автономного XLSX, раскрывать связанные нижние эпики и задачи, рассчитывать TTM исходных эпиков и показывать календарь этапов, возвраты в Открыто и impediment. Каноническое место этой SDD — данный Git-репозиторий. [OPEN] Формальный продуктовый владелец и порядок утверждения SDD здесь не указаны. Основания: [README](../../README.md), [запуск](../../server/index.ts), [интерфейс](../../src/App.tsx).

## Область ответственности

- Локальный интерфейс и API, импорт и ручное обновление набора.
- Проверка кандидатов по текущей Jira, аудит отбора и нормализация истории.
- Расчёт длительностей, качества данных, календарное и агрегатное представление.
- Восстановление последнего сохранённого набора без нового обращения к Jira.

Приложение не изменяет Jira, не обновляется в фоне, не предоставляет облачное совместное хранилище и не устанавливает причины задержек автоматически.

## Постоянные ограничения

- Локальный запуск на macOS требует Node.js не ниже 22.12; сервер слушает `127.0.0.1` ([пакет](../../package.json), [запуск](../../server/index.ts)).
- Форма содержит четыре источника. Чтение корректных кандидатов требует проверенного профиля Jira, сети и PAT в macOS Keychain; прямой список только из ошибок формата проверяется локально. Сохранённый набор открывается без Jira. Автономный XLSX-контракт также работает без Jira, и выбирается в форме файла как «История из XLSX, без Jira» ([форма](../../src/SourceForm.tsx), [конвейер](../../server/jira/pipeline.ts), [совместимость](specs/legacy-compatibility.md)).
- Профиль касается Jira Server 9.12.10 и отдельно проверенных настроек досок. Изменившуюся доску или версию нельзя молча считать совместимой.
- Полная приёмка остаётся открытой: не завершены живая загрузка историй всей доски, проверка длинной истории и ручная визуальная проверка ([статус](../../IMPLEMENTATION-HF-STATUS.md)).

## Правила документации

Текущее поведение ДОЛЖНО описываться в `specs/` по проверенным источникам; неисполненные предложения ДОЛЖНЫ оставаться отдельно. Смена формата кэша ДОЛЖНА сохранять входные данные либо сопровождаться проверенной миграцией. Эта SDD ссылается на исходные типы и код, не копируя их определения.

Подтверждённые решения S0–S12 и статусы приёмки сохраняются в исходных проектных документах. Наличие кода или теста само по себе не подтверждает, что техническая деталь стала согласованным бизнес-требованием. [Матрица трассировки](review.md) связывает эти уровни.

Связанные элементы внедрены по согласованному [change-пакету](changes/LOCAL-20260924-02-linked-issue-status-bars/proposal.md). Автоматическая проверка выполнена; живая Jira и фактическая отрисовка пока не приняты.

Для изменения раскрытия связанных элементов пользователь подтвердил проверку по ключу и признал её пока достаточной; SDD актуализирована. Более широкая приёмка остаётся частичной, её границы зафиксированы в [протоколе](changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md).

## Анализ непрерывности по спринтам

В текущем коде реализованы сегменты спринтов задач, Delivery-эпиков и главного эпика и бреши выбранных этапов. Решение согласовано 02.10.2026. Автоматические проверки выполнены; полная живая и ручная визуальная приёмка не завершена. Пакет архивирован 13.10.2026 по прямому поручению пользователя с сохранением этих остатков. [Текущий контракт](specs/sprint-continuity.md), [протокол](changes/archive/2026/LOCAL-20260929-01-sprint-continuity/verification.md). Анализ не устанавливает причину отсутствия работы и не расширяет автономный XLSX.
