# Доменная модель

## Граница ответственности

Jira владеет задачами, статусами, резолюцией и историей. Приложение владеет выбором кандидатов, прочитанным снимком, результатом расчёта и его локальным хранением. Кэш не меняет Jira и не заменяет её ([контракты](../../shared/contracts.ts)).

## Объекты и инварианты

| Объект | Идентичность и жизненный цикл | Инвариант |
| --- | --- | --- |
| Кандидат | Запрошенный ключ, затем стабильный `issueId` Jira | Дубликаты строк или ключей одной задачи отражены в аудите, но не создают два эпика |
| Источник | Файл, прямой список ключей, доска либо один эпик | Файл и список обновляются по сохранённым кандидатам; доска — по актуальному составу; известная задача — по стабильному `issueId` |
| Ошибочный элемент списка | Непустой элемент ввода и его физическая строка для `invalid`; `issueId` либо запрошенный ключ для `unresolved` | Не создаёт эпик или метрики; сохраняется в аудите. Повторные неверные строки видны отдельно, алиасы одной неразрешённой задачи объединяются только в представлении таблицы |
| История | Переходы статусов и флага | Полнота статусов и impediment оценивается отдельно |
| Эпик | Текущие признаки HF и шкала на общем `asOf` | Первоначальное Открыто вне TTM; Отложено не начинает и не увеличивает TTM; Решили делать начинает TTM только для HOTELS |
| Связанный элемент | Jira-ID либо ключ автономной книги; граф и видимые пути | Один объект может иметь несколько родителей; задачи являются листьями, подзадачи исключаются; отклонённый эпик скрыт, но допустимые потомки достижимы |
| Набор | `id`, источник, аудит, входы, результат | Новый набор заменяет старый только после успешной записи; подтверждённый сброс удаляет текущий набор и его задания |
| Задание | `id`, `queued` → `running` → `completed` или `failed` | Job живёт в памяти; после перезапуска остаётся лишь набор |

## Время и качество

Активные HF-этапы заданы [картой статусов](../../shared/statuses.ts). Календарный период начинается с первого учитываемого этапа и продолжается до окончательного закрытия либо общего `asOf`. Числовой TTM исключает все интервалы Отложено внутри этого периода; календарь остаётся непрерывным. Промежуточные закрытия и возвраты в Открыто сохраняются внутри него. До первого активного этапа при доказанной истории показывается «TTM ещё не начат»; при недоказанном начале длительность неизвестна. Общий impediment ограничен календарными границами периода и не меняет основной TTM. Отдельный TTM без флага исключает пересечение фактического флага с учитываемым временем, без повторного вычитания Отложено ([расчёт](../../server/timeline.ts), [проверка истории](../../server/jira/normalize.ts)).

Полная или частичная достоверность отмечается у набора и эпика. Недоказанная история не превращается в точное число; неизвестный статус может отображаться как сегмент без назначения известного HF-этапа. При полной недоступности историй выбранных HF-эпиков новый набор не заменяет старый ([конвейер](../../server/jira/pipeline.ts)).

Длительность считается в миллисекундах; один отображаемый день равен 86 400 000 мс, без исключения выходных и праздников. Интервалы полуоткрытые `[start, end)`, время отображается в `Europe/Moscow`. Округление до двух знаков применяется к показу дней, но не к арифметике ([статусы](../../shared/statuses.ts), [интерфейс](../../src/App.tsx)).

### Значения времени

| Поле | Значение |
| --- | --- |
| `asOf` Jira-набора | Время создания задания; история реконструируется на этот момент |
| `syncStartedAt` / `syncFinishedAt` | Начало задания / окончание сбора входов, до расчёта и записи |
| `savedAt` | Время построения сохраняемого результата, до завершения записи |
| `source.importedAt` файла или прямого списка | Время первоначальной загрузки; refresh его не меняет |
| `asOf` автономной книги | Явный срез листа «Параметры»; при одних агрегатах в v3 — `null` |

Принадлежность к HF, резолюция и метаданные берутся из текущих ответов Jira в окне чтения. Это не восстановленный состав выборки на `asOf`. Задача, созданная после среза, может присутствовать в текущем отборе со состоянием `not-present`. Основания: [конвейер](../../server/jira/pipeline.ts), [миграция](../../server/cache-migrations.ts), [нормализация](../../server/jira/normalize.ts).

Для прямого списка только из `invalid` поля `asOf` и `syncStartedAt`/`syncFinishedAt` являются локальными отметками обработки: Jira не запрашивалась. `historyMode: jira` обозначает режим источника, а не доказательство сетевого запроса. Интерфейс подписывает такой результат как проверку ввода. `inputRows` считает непустые элементы после разделения прямого списка запятыми и переносами строк; служебное оформление пропускается. Несколько элементов и повторов могут иметь один физический номер строки в аудите. Некорректная многостолбцовая Markdown-строка считается одной ошибкой. `sourceCoverage` полного разбора равно `complete`, а `eligibilityCoverage` при `invalid` или `unresolved` — `partial` ([разбор](../../server/key-candidates.ts), [конвейер](../../server/jira/pipeline.ts), [проекция ошибок](../../shared/contracts.ts)).

### Состояния расчёта и полнота

| `ttmState` | Смысл |
| --- | --- |
| `not-started` | Доказано отсутствие активного этапа до среза; TTM неизвестен как число, начальное ожидание видно |
| `running` | Работа началась, окончательного закрытия на срезе нет |
| `finished` | Есть окончательное закрытие |
| `indeterminate` | Начало либо длительность нельзя доказать |
| `not-present` | Задача создана после среза |

Нулевой TTM допустим, например при первом активном переходе точно на срезе; это отличается от `null`. `statusCoverage` и `flagCoverage` имеют независимые значения `complete`, `partial`, `unavailable`. Даже полная статусная история может дать неизвестное начало TTM из-за неизвестного предрабочего состояния. При этом в Jira и автономном XLSX доказанные длительности распознанных этапов суммируются независимо от TTM по [FR-041/AC-092](specs/sprint-continuity.md); неполная или разорванная история точных чисел не даёт. Неполный флаг не отменяет доказанный TTM. Неизвестные статусы **внутри** доказанного TTM сохраняют длительность и предупреждение, не обязательно понижая качество до `partial` ([шкала](../../server/timeline.ts), [нормализация](../../server/jira/normalize.ts)).

Аудит отдельно хранит `sourceCoverage` (полноту источника) и `eligibilityCoverage` (полноту решения об отборе). Для `quality: complete` Jira-набора нужны полное покрытие обоих уровней, отсутствие `invalid` в аудите и `complete` у всех эпиков, а при наличии иерархии — полное покрытие её состава и доказанных дочерних историй. Пустая однозначно разрешённая выборка может быть полной; `completed` у задания сам по себе этого не означает ([построение набора](../../server/jira/dataset.ts)).

### Статусы

Каталог содержит 14 статусов: восемь прежних и шесть добавленных; порядок сравнения и правила присутствия колонок заданы в [FR-043–046](specs/visualization.md). Отображение собственного времени отделено от участия в TTM. Маппинг нормализует пробелы, регистр и `ё`, снимает начальный `[HF]`. Открыто и Закрыто имеют русские и английские алиасы; DF и смешанные состояния не назначаются HF-этапам. Принадлежность **задачи** к HF определяется отдельным, более строгим правилом текущего префикса и ограниченными исключениями HOTELS по [FR-005](specs/source-selection.md); распознавание **интервала** как этапа не доказывает HF задачи ([карта](../../shared/statuses.ts), [адаптер](../../server/jira/adapter.ts)).

История связанного элемента начинается от создания, а не первого активного HF-этапа, и заканчивается окончательным закрытием либо `asOf`. Приоритет категории статуса и резерв по названию описаны в [FR-032](specs/timeline.md). Неизвестное закрытие не превращается в точную полосу; создание после среза — диагностическое состояние, не неполнота истории. Дочерние интервалы сохраняют собственную длительность и последовательность, включая первоначальное и повторное Открыто. Они показаны полосами без числовых ячеек и не добавляют статусных колонок исходным гипотезам; время не прибавляется к родителям; дочерние TTM и impediment не рассчитываются. Полнота ветки независима от полноты истории; отсутствие иерархии в старом кэше отличается от подтверждённо пустого списка детей.

## Работа в спринте

[FR-035–041](specs/sprint-continuity.md) задают независимую аналитическую проекцию. ID спринта определяет идентичность; название и источник календаря не заменяют ID. Наблюдаемый закрытый спринт ограничен `startDate/completeDate`, активный — `startDate/asOf`; плановый `endDate` только поясняет план. Полная цепочка проверяется до отсечения срезом.

Текущая непустая группа native Sub-task задаёт рабочие истории за весь период. Подтверждённо пустая группа разрешает историю родителя. Рабочая категория — `indeterminate` по ID статуса. Для спринтового покрытия историческое членство родительской задачи обязательно, собственный Sprint подзадачи не требуется. Ограничение текущего состава закреплено в [ADR-0001](adr/ADR-0001-current-subtask-sprint-analysis.md). Задачи подтверждённых проектов без спринтов используют тот же выбор рабочих историй, но покрывают только точные интервалы активности; список и требования к доказанному отсутствию членства заданы в [FR-054](specs/sprint-continuity.md#fr-054-подтверждённая-работа-в-проекте-без-спринтов).

Работа по FR-036 покрывает целый наблюдаемый спринт; состояние каждого ID сохраняется отдельно. Брешь по FR-038 основана на членстве спринтовых задач и точном покрытии задач FR-054: `G=(M∩C)\(I∪U_I∪A∪E∪U_E)`, где M — выбранные этапы, C — закрытые спринты, I — целые спринты с включением хотя бы одной дочерней задачи, U_I — возможное включение при неполных данных, A — активные спринты, E — точная активность без спринтов, U_E — её ограниченная неизвестность. Неограниченная неизвестность состава/календаря даёт U_I=M. Тонкая тёмная отметка G рисуется непосредственно под цветной полосой статуса, соприкасаясь с её нижним краем; заливка статуса остаётся непрерывной. Рабочая неизвестность и предварительные результаты сохраняются в аналитике и текстовых пояснениях. Эти состояния не меняют `quality` основного графа или прежние TTM/CT.

Фильтр FR-042 показывает только спринты с подтверждённой работой на всех трёх уровнях. Полный набор сегментов, его идентичности и прежний диапазон календаря сохраняются; фильтр восстанавливается из сохранённых входов и не требует миграции кэша.

## Время без работы

[FR-049–052](specs/sprint-focus.md) определяют самостоятельную производную метрику исходной гипотезы. Она использует циклы реализации, полные наблюдаемые спринты и рабочее покрытие, а не интервалы прежних брешей. Результат различает отсутствие реализации, отсутствие оцениваемого времени, точное число, предварительное число и неизвестность. Незакрытый спринт может позже покрыться работой целиком и уменьшить предварительный результат. Флаг отдельно не исключается. Неизвестность начала TTM не мешает независимо доказанному циклу реализации; неопределённое конечное закрытие не выдаётся за известную границу.

В смешанном составе область оценки остаётся внутри известных спринтов; точная активность FR-054 покрывает только совпадающее время. Полный непустой состав исключительно из допустимых задач без спринтов включает весь цикл реализации без Отложено. Пустой либо неполный состав этого не доказывает. Точное покрытие объединяется без двойного счёта; будущая активность без спринтов не уменьшает прошлое время без работы задним числом. Отображаемое название метрики — «Без работы».
