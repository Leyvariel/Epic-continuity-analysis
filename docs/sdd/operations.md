# Эксплуатация и безопасность

## Запуск и хранение

`npm run dev` запускает разработку, `npm run build` и `npm start` — собранный интерфейс. Нужен Node.js не ниже 22.12. Сервер слушает только `127.0.0.1`, по умолчанию порт 4317; `PORT` допускает значения от 1024 до 65535 ([README](../../README.md), [запуск](../../server/index.ts)).

`.local-data/dataset.json` записывается через временный файл и переименование: каталог имеет права `0700`, файл `0600`. При старте производные шкалы пересчитываются из сохранённых входов. Миграция v2 пытается создать `dataset.v2.backup.json`; существующая копия не перезаписывается и не проверяется на совпадение. Повреждённый кэш не удаляется. Запись не использует `fsync` и межпроцессную блокировку; поддерживаемая модель — один процесс, один набор ([кэш](../../server/cache.ts), [сервис](../../server/service.ts)).

## Сбои и восстановление

| Сбой | Реакция | Действие пользователя |
| --- | --- | --- |
| Нет профиля/PAT, глобальный отказ авторизации | Новая Jira-загрузка завершается ошибкой, старый набор остаётся | Проверить доступ и повторить |
| Сбой отдельного чтения Jira | Повтор либо частичный результат/отказ по правилам источника | Посмотреть аудит и предупреждения |
| Состав доски остаётся нестабильным после повторов | Новый набор не публикуется | Повторить загрузку |
| Настройки доски не совпали с профилем | Чтение блокируется | Заново проверить профиль |
| Частичная история эпика | Неизвестные величины не рассчитываются; показывается предупреждение | Проверить исходную историю |
| Перезапуск сервера | Job исчезает, последний набор восстанавливается | При необходимости повторить импорт |
| Повреждённый кэш | Файл сохраняется, API сообщает ошибку | Разобрать файл и восстановить собственную копию |

Основания: [сервис](../../server/service.ts), [API](../../server/app.ts), [кэш](../../server/cache.ts).

## Безопасность

Сервер проверяет `Host`, `Origin`, `Sec-Fetch-Site` и заголовок `X-Local-Request` для POST; API отвечает с `no-store`, интерфейс использует CSP. PAT читается из Keychain при загрузке или обновлении, требующем Jira; локальный отчёт только об ошибках формата и восстановление кэша обходятся без него. PAT не передаётся браузеру. Jira-клиент допускает только GET к фиксированному origin и разрешённым путям, не следует перенаправлениям с токеном, ограничивает время и размер ответа ([API](../../server/app.ts), [Keychain](../../server/jira/keychain.ts), [клиент Jira](../../server/jira/client.ts)).

Диагностические серверы на 4329 (синтетическая демонстрация) и 4330 (сохранённый снимок) передают режим `demo`/`snapshot` через `GET /api/dataset`. Интерфейс обозначает просмотр, скрывает загрузку и обновление, предлагает открыть основное приложение на 4317. Сервер отклоняет все POST `/api/*` с `409 READ_ONLY_PREVIEW` до обращения к Jira. Для снимка: `npx tsx scripts/serve-snapshot.ts <каталог>`. Основной сервер после изменений серверного кода нужно перезапустить; `npm run dev` не перезапускает backend автоматически.

Открывать приложение нужно по `http://127.0.0.1:4317` (либо выбранному `PORT`): `localhost` не проходит строгую проверку Host. Отсутствующий Origin допускается для локального API-клиента, несовпадающий — нет. Локальность и CSRF-защита не являются аутентификацией разных пользователей ОС. Кэш содержит данные задач и не является обезличенным, хотя PAT в него не записывается.

## Наблюдаемость и пределы

Интерфейс показывает фазу, прогресс, аудит и предупреждения. Отдельная система метрик и оповещений в репозитории не обнаружена. Файл ограничен 20 МиБ, 20 000 строками листа и 500 колонками; прямой список — 1000 уникальными корректными ключами и 16 КиБ JSON-тела; доска — 10 000 кандидатами. Предел 1000 HF-эпиков действует для всех Jira-источников. Два импорта в одном экземпляре сервиса одновременно не запускаются. Граф ограничен 10 000 уникальными узлами вместе с корнями и 50 000 рёбрами; первое превышение останавливает расширение с явным предупреждением и частичным покрытием. Дочерние строки выводятся порциями по 200 путей. Фонового опроса Jira нет ([импорт файла](../../server/file-candidates.ts), [список](../../server/key-candidates.ts), [конвейер](../../server/jira/pipeline.ts)).

`npm run check` запускает Vitest, проверку TypeScript и сборку Vite; отдельно доступны `npm test` и `npm run build`. Диагностические инструменты `verify:workbook`, `verify:jira`, `verify:jira-sample` и скрипты проверки доски/импорта описаны в [README](../../README.md) и [статусе приёмки](../../IMPLEMENTATION-HF-STATUS.md). Инструменты Jira не являются автоматическим стартовым шагом: реальный доступ и объём чтения должны соответствовать разрешению пользователя. Профиль и отчёты диагностики в `.local-data` не входят в Git.

## Статус проверки

Локальные тесты и сборка проверяют кодовые сценарии, но не весь производственный путь. По [отчёту](../../IMPLEMENTATION-HF-STATUS.md) остаются живые проверки полной доски и длинной истории и ручная визуальная приёмка.

## Восстановление изменения связанных элементов

Старый кэш без дополнения открывается без обращения к Jira и показывает «Данные о связях не загружены». Неизвестная версия дополнения, отсутствующие узлы или срез, отличающийся от набора, отвергаются без удаления исходного файла. Обновление Jira собирает новую иерархию целиком; автономная книга обновляется повторным импортом. Ошибка записи оставляет прежний набор и граф.

Для отката возвращаются согласованная версия исходников и её сырой кэш вместе; приватный кэш не помещается в репозиторий. Проверка этого порядка выполнена на временных вымышленных данных: [свидетельство](changes/LOCAL-20260924-02-linked-issue-status-bars/evidence/epic-rollback-check.txt). Подготовленная локальная резервная копия и фактические границы приёмки перечислены в [протоколе](changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md).

Для изменения раскрытия связанных элементов пользователь подтвердил проверку по ключу и признал её пока достаточной; SDD актуализирована. Более широкая приёмка остаётся частичной, её границы зафиксированы в [протоколе](changes/LOCAL-20260924-02-linked-issue-status-bars/verification.md).

## Ошибка Keychain при запуске из ограниченной среды

При запуске сервера из sandbox macOS Keychain может возвращать код 44 для существующих записей PAT. Сообщение «Согласованная запись PAT не найдена в Keychain» в таком процессе не доказывает удаления токена; VPN на это чтение не влияет. Подтверждённый случай 06.10.2026: обе согласованные записи недоступны в sandbox и успешно читаются с ранее предоставленным доступом. Исправление — точечный перезапуск основного сервера с уже разрешённым доступом к Keychain. Не копировать PAT в файлы, не менять записи или права ради этой ошибки. Проверить шлюз приложения через чтение serverInfo, HTTP 200 локального API и неизменность рабочего кэша. При последующих перезапусках сохранять этот контекст доступа. [Свидетельство](changes/archive/2026/LOCAL-20260929-01-sprint-continuity/evidence/keychain-runtime-check.json).

## Спринты: запуск, восстановление и проверка

Новые импорты Jira и ручное обновление читают спринты после основного графа. Старый кэш открывается с сообщением «Спринты не загружены» и не вызывает фоновую сеть. Неизвестная версия либо повреждённое дополнение вызывает `CACHE_INVALID`, исходный файл сохраняется.

Основной граф получает прежние 10 000 узлов и 50 000 рёбер. Аналитические подзадачи используют остаток узлов, не добавляют основные рёбра и допускают до 50 000 отношений. Пределы календарей: 100 источников, 10 000 уникальных спринтов, 200 страниц на источник. UI показывает размер основного графа, добавленные/непрочитанные подзадачи и причины ограничения. Локальные 403/404/исчерпанные HTTP 5xx дают частичную аналитику; глобальные ошибки сохраняют прежний набор. Полностью недоступные истории исходных HF по-прежнему блокируют публикацию.

Синтетический контрольный пример: `npx tsx scripts/verify-sprint-demo.ts`, адрес `http://127.0.0.1:4331`. Он работает в режиме `demo`, не читает Jira и рабочий кэш, запрещает POST, ожидает четыре бреши общей длительностью 26 суток. HTTP-проверка этого пути не является визуальной приёмкой. Откат исходников и чтение прежнего/нового кэша старой версией проверены на изолированной копии; [свидетельства и текущие ограничения](changes/archive/2026/LOCAL-20260929-01-sprint-continuity/verification.md).

## Совместимость прямого списка через запятую

После разделения списка несколько элементов могут иметь один физический номер строки; `inputRows` считает непустые элементы. Новый валидатор читает прежние наборы и проверяет согласованность количества вхождений и решений. Прежний код, запрещавший повторные номера строк, не читает такой новый набор: для отката возвращать прежние исходники вместе с соответствующим прежним кэшем. Формат JSON и версия кэша не менялись. [Контракт](specs/source-selection.md), [схема](../../server/jira/cache-schema.ts).
