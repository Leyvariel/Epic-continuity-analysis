## Реализованный результат

Три формы источников, актуальный отбор по Jira, аудит включения/исключения/недоступности, единая нормализация истории, точный календарь и исходные пороги heatmap, отдельное начальное Открыто и «Решили делать» до TTM. Повторы, возвраты, нулевые интервалы и порядок одновременных переходов сохраняются. Полнота статусов и флагов независима.

Есть ручное обновление всех исходных кандидатов файла, нового состава доски или стабильного id одиночного эпика. Кэш v3 записывается атомарно; старый v2 мигрирует с резервной копией. При ошибке прежний результат сохраняется. Запросы ограничены четырьмя одновременно; после фатального сбоя очередь прекращает запуск новых задач и дожидается остановки активных.

PAT доступен только серверу. Фиксированный origin Jira, GET, запрет переноса PAT при redirect, локальный Host/Origin, ограничения размера/таймаутов и безопасные сообщения об ошибках покрыты тестами. Начальный запуск и восстановление кэша не обращаются к Jira.

## Текущие ограничения и следующий шаг

1. Получить ответ о HF для «Тестирование эпика» и «Релиз». Если подтверждены, добавить явные проверенные соответствия по стабильным id статусов с тестами; это не означает автоматически включать их в уже согласованные этапы или менять начало TTM.
2. Перед чтением историй новых задач получить отдельное разрешение на конкретную контрольную выборку / полную доску. Нынешнее разрешение полного состава доски покрывает метаданные страниц, не истории всех задач. Прежние широкие разрешения не восстановлены.
3. Проверить длинную реальную историю. Server-адаптер использует `expand=changelog` с доказательством полноты; обрезанный ответ остаётся partial, а не считается полной историей. Недоказанная поддержка Cloud-пагинации не предполагается.
4. Завершить ручную визуальную приёмку и живую проверку доски. Только после этого закрывать AC-01/03/07/08/13 и объявлять всю реализацию принятой.

Рабочая конфигурация доски привязана к подтверждённым настройкам и их отпечаткам. Другие доски и изменённые постоянные настройки требуют проверки; произвольный board id сам по себе не означает совместимость. Предел 1000 HF не мешает текущему объёму (636 подтверждённых + 7 неопределённых), но не отменяет проверки полноты.

Документация API: [Jira Server REST 9.12.4](https://docs.atlassian.com/software/jira/docs/api/REST/9.12.4/), [Jira Software REST 9.12.4](https://docs.atlassian.com/jira-software/REST/9.12.4/), [Atlassian о чтении changelog](https://support.atlassian.com/jira/kb/how-to-analyze-the-history-or-changelog-of-an-issue-in-jira/), [влияние сопоставления статусов колонкам](https://support.atlassian.com/jira/kb/jira-software-data-center-kanban-board-does-not-show-all-issues/).
